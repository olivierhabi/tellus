# Runbook — Quiver B2 (Card DAG Validator)

**Owner**: Tellus Quiver team
**Spec**: `tasks/quiver/quiver-tasks.md` §B2

## Surfaces

- `POST /quiver/api/v1/analyses/:rid/_validate` — public validator endpoint.
- `validate(doc)` — in-process function called by B3 on every instruction-apply.

## Metrics (Grafana folder `tellus-quiver`)

| Metric | Type | Labels | Use |
|---|---|---|---|
| `tellus_quiver_dag_validate_seconds` | Histogram | `result` (ok\|fail) | SLO: P50 ≤ 25ms, P95 ≤ 80ms, P99 ≤ 250ms |
| `tellus_quiver_dag_validate_failure_total` | Counter | `error_name` | Alert if rate > 10/min sustained for 5min |
| `tellus_quiver_dag_validate_card_count` | Histogram | none | Capacity planning |
| `tellus_quiver_cards_per_dag` | Gauge | none | Per-tenant capacity (last observed) |

## Alerts

- **QuiverValidatorP99Breach** — `histogram_quantile(0.99, rate(tellus_quiver_dag_validate_seconds_bucket[5m])) > 0.250` for 10min → page on-call.
- **QuiverValidatorRejectionSpike** — `rate(tellus_quiver_dag_validate_failure_total[5m]) > 0.5` for 15min → check recent client deploys; likely spec drift.
- **QuiverRegistryDrift** — service refuses to boot if registry size ≠ 26 (`assertRegistryIntegrity` throws). Symptom: `buildQuiverRouter()` exception in startup log; fix the in-code registry to match `tasks/quiver/registry-fixture.md`.

## Common diagnoses

- **400 CardTypeInputMismatch** — frontend bound an incompatible upstream;
  client should re-fetch registry + show inline error.
- **400 CyclicDag** — `parameters.cyclePath` lists the cycle; client must
  reject the offending instruction.
- **400 CardLimitExceeded / CanvasLimitExceeded** — hard cap (500/50);
  archive/split the analysis.
- **`X-Tellus-Quiver-Warn` header** — soft warn at >200 cards; client
  surfaces a banner.

## SOPs

1. **Registry drift** — pull latest `registry-fixture.md`; rebuild service.
2. **Validator latency regression** — run `npx vitest run --config vitest.quiver.config.ts tests/quiver/unit/dag-slo-unit.test.ts`; profile with `node --prof` if breaches reproduce.
3. **Spike in rejections post-deploy** — check `error_name` distribution; usually one card type whose registry entry changed.
