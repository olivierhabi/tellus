# Runbook — B7 Materialization Backend (Polars / Spark / Iceberg)

## Surface
- `MaterializationBackend` registered via `setMatPortForTests()` against B5's router for 5 card types: `MATERIALIZATION`, `JOIN_MATERIALIZATION`, `EXPRESSION`, `PIVOT_TABLE`, `CATEGORICAL_CHART`.
- Backed by `MatPort` (production: Polars sidecar over UDS + MMDP Spark over Arrow Flight SQL; tests: `InProcessMatAdapter`).
- Cache row carries `iceberg_snapshots JSONB`, `result_blob_uri TEXT`, `mat_tier TEXT`, `mat_plan_json JSONB` (added by migration 068; reversible via `068_b7_quiver_iceberg_snapshots.down.sql`).

## SLOs (per spec §B7 C-09; load measurement deferred to phase boundary per D-17)
- Polars-tier materialization (≤ 1 M rows): p99 ≤ 5 s.
- Spark-tier materialization (≤ 100 M rows): p99 ≤ 60 s.
- Polars-tier hash join (two ≤ 1 M-row inputs): p99 ≤ 10 s.

## Operational Notes
- **Tier selection** is pure — `selectTier({rows, cols, estMemoryBytes}, {cellThreshold, memoryBudgetBytes, force})`. Defaults: `cellThreshold = 10_000_000`, `memoryBudgetBytes = 2 GiB`.
- **Force tier per card** by setting `card.config.forceTier = "polars"` or `"spark"`. Use sparingly; tier selection metric records `reason=forced-{tier}` for audit.
- **Row limit** is 50_000 enforced by the in-process evaluator and the production Polars sidecar. Surfaces as `MatLimitExceededError` (B7 C-08); the route currently propagates this as 500 with envelope (D-51 — richer mapping in B10).
- **Iceberg snapshot pinning** writes the per-dataset snapshot id into `payload.meta.icebergSnapshots` and (via the cache repo) into `quiver_card_output_cache.iceberg_snapshots`. The GIN index `quiver_card_output_cache_iceberg_gin` supports the future "snapshot bumped" invalidator.
- **Per-card-type result types**: `MATERIALIZATION`/`JOIN_MATERIALIZATION` → `TRANSFORM_TABLE`; `EXPRESSION` → `ANY`; `PIVOT_TABLE` → `PIVOT_TABLE`; `CATEGORICAL_CHART` → `CATEGORICAL_CHART`. Documented in `resultTypeFor()` in matBackend.ts.

## Rollback
- Disable B7 by replacing `MatPort` injection in `compute/context.ts` with the stub backends (`buildAllStubBackends()` covers all 5 card types).
- Or roll back migration 068: `psql -f src/migrations/068_b7_quiver_iceberg_snapshots.down.sql`.
