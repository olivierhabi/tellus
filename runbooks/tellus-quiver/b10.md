# Runbook — B10 Publishing (Dashboards / Visual Functions / Templates)

## Surfaces

- `POST /quiver/api/v1/publishing/dashboards`              — publish dashboard from analysis (requires `Idempotency-Key`)
- `GET  /quiver/api/v1/publishing/dashboards/:rid`         — read published record
- `POST /quiver/api/v1/publishing/dashboards/:rid/embed`   — register embed (Workshop / Object View)
- `POST /quiver/api/v1/publishing/visual-functions`        — publish Visual Function (sub-DAG)
- `GET  /quiver/api/v1/publishing/visual-functions/:rid`   — read published record
- `POST /quiver/api/v1/publishing/visual-functions/:rid/inline` — consumer-side inline (returns expanded sub-DAG)
- `POST /quiver/api/v1/publishing/templates`               — publish reusable template
- `GET  /quiver/api/v1/publishing/templates/:rid`          — read published template

All gated behind `TELLUS_QUIVER_PHASE >= 5`.

## Metrics

| Metric                                                | Labels                              | Use                                   |
|-------------------------------------------------------|-------------------------------------|---------------------------------------|
| `tellus_quiver_dashboard_publish_total`               | `result` (ok/conflict/compass_failed) | Publish success/failure ratios        |
| `tellus_quiver_visual_function_publish_total`         | `result`                            | VF publish success/failure ratios     |
| `tellus_quiver_dashboard_embed_total`                 | `surface` (OBJECT_VIEW/WORKSHOP)    | Embed surface mix                     |
| `tellus_quiver_visual_function_inline_total`          | —                                   | Consumer inline rate                  |
| `tellus_quiver_publishing_seconds`                    | `surface` (dashboard/visual_function) | Publish latency P95/P99               |

## Alerts

1. `tellus_quiver_dashboard_publish_total{result="compass_failed"}[5m] > 0`
   → Compass-write call failed during publish; row marked tombstone, idempotency replay returns the same error envelope. Investigate Compass health; users should retry with a fresh `Idempotency-Key`.
2. `histogram_quantile(0.95, tellus_quiver_publishing_seconds_bucket) > 4`
   → Publish P95 above 4 s. Check Compass latency; check for large analyses (> 200 cards).
3. `rate(tellus_quiver_visual_function_inline_total[1m]) == 0` for 24 h
   → Visual Function feature unused or inline endpoint broken; cross-check with consumer logs.

## SOPs

### Compass write failed mid-publish (compass_failed)

1. Confirm `Compass /actions/write` health.
2. The publish row exists in `quiver_published_dashboard` / `quiver_published_visual_function` with `compass_status = 'FAILED'`. The row is tombstoned and unusable.
3. User retries with a **new** `Idempotency-Key` once Compass is healthy.
4. Old key remains cached and replays the failed envelope (per G-04); not a bug.

### Visual Function consumer inline returns stale sub-DAG

1. Visual Functions are immutable per `(rid, version)`. New publishes allocate `version + 1`.
2. Consumer-side inline reads the **pinned** version recorded in the consumer's `bindInput` instruction; bumping the consumer to the new VF version requires an explicit OT instruction.
3. Confirm with `GET /publishing/visual-functions/:rid` — `version` field is the source of truth.

### Embed registration failed

1. Compass requires the embed parent (Workshop module / Object View tab) to be writable by the caller; check `canApplyAction` on the parent.
2. If `403 Tellus:Quiver:EmbedTargetForbidden`, parent permission is the issue, not Quiver.
3. Embed rows in `quiver_dashboard_embed` are unique per `(dashboard_rid, surface, parent_rid)`; duplicates return `409 IdempotencyKeyReplay`.

## Rollback

1. Disable phase: `TELLUS_QUIVER_PHASE=4` — publishing routes return 404.
2. Migration 070 has a reversible `.down.sql` that drops the three `quiver_published_*` tables and their idempotency rows.

## Decisions referenced
- D-63: Compass write is the source of truth; rows tombstoned on failure.
- D-64: VFs are immutable per (rid, version); consumer pins version on bindInput.
- D-65: Templates are content-addressable (hash of canonicalised sub-DAG).
- D-66: Embed registration is idempotent on `(dashboard_rid, surface, parent_rid)`.
