# Runbook — Quiver B5 (Compute Coordinator)

## Endpoints

- `POST /quiver/api/v1/compute/cards` — synchronous card compute. Body:
  `{ analysisRid, cardId, parameterOverrides, branch?, deadlineMs?, cacheBehavior }`.
  Headers: `X-Deadline: <isoInstant>` (preferred) or body `deadlineMs`.
- `GET  /quiver/api/v1/compute/cache/stats` — diagnostic; returns cache
  hit ratio over the last 10-minute window.

Both endpoints are gated by `TELLUS_QUIVER_PHASE >= 2`.

## Metrics & alerts

| Metric | Type | Alert (suggested) |
|---|---|---|
| `tellus_quiver_compute_seconds{cardType,backend,cache}` | Histogram | p99 > 5 s sustained 5 m for `cache=miss` and `backend=OSS` |
| `tellus_quiver_compute_errors_total{cardType,errorCode}` | Counter | rate > 1 / s sustained 5 m on any `errorCode` |
| `tellus_quiver_compute_cache_hit_ratio` | Gauge | < 0.5 sustained 30 m on warm analyses |
| `tellus_quiver_compute_inflight{backend}` | Gauge | > 50 sustained 5 m per backend |
| `tellus_quiver_compute_deadline_exceeded_total{cardType}` | Counter | rate > 0.5 / s sustained 5 m |
| `tellus_quiver_compute_circuit_state{backend}` | Gauge (0/1/2) | == 2 (open) sustained 1 m |

## SOPs

### Cache hit ratio dropped < 50 %
1. Check `tellus_quiver_compute_seconds{cache="hit"}` rate vs `cache="miss"`.
2. Run `psql … -c "SELECT count(*) FROM quiver_card_output_cache WHERE expires_at > NOW();"` to confirm cache rows present.
3. If the cache is empty, an ontology bump may have invalidated it — confirm via the audit row for ontology metadata.
4. If the cache is populated but hit ratio remains low, check that ontology_version is stable (a drifting per-call value would invalidate every read).

### Circuit breaker open
1. `tellus_quiver_compute_circuit_state{backend="OSS"} == 2` indicates the named backend has tripped.
2. Check the backend's own dashboard (OSS, Codex, MMDP, etc.) — it has likely been unavailable.
3. After the backend recovers, the breaker auto-transitions to half-open (30 s after last failure). First half-open success → closed.
4. If repeated trips, escalate to the backend's owner and consider a temporary `cacheBehavior=READ_ONLY` mode at the API gateway to avoid hammering.

### Frequent DEADLINE_EXCEEDED
1. Compare `tellus_quiver_compute_deadline_exceeded_total` against the per-card-type histogram. Are clients sending too-tight budgets, or is a specific backend pathologically slow?
2. If a single `cardType` dominates, check the corresponding backend's latency p99.
3. Frontend may be supplying optimistic deadlines without the user noticing — verify the F-side `X-Deadline` derivation.

### NoBackendForCardType
This is a deployment misconfiguration: a card type exists in the registry but has no backend registered. Compare `BackendRouter.list()` (via `/compute/cache/stats` adjacent endpoint) against `tasks/quiver/registry-fixture.md` to identify the missing entry. The boot-time `assertRegistryIntegrity()` will throw if the registry has drifted from 26 entries.
