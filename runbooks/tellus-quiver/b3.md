## Tables

- `quiver_instruction_log` — append-only OT log (rid, seq) PK +
  UNIQUE (rid, applied_by, client_op_id) for idempotency.

## Alerts

| Alert | Condition | SOP |
|---|---|---|
| OT_SUBMIT_LATENCY_HIGH | `histogram_quantile(0.99, rate(tellus_quiver_ot_submit_seconds_bucket[5m])) > 0.1` | Check Postgres CPU + connection saturation; SELECT FOR UPDATE on hot RIDs is the typical cause |
| OT_DUPLICATE_OP_ID_BURST | `rate(tellus_quiver_ot_duplicate_op_id_total[1m]) > 50` | Likely a client retry loop; check `applied_by` distribution |
| OT_BASE_VERSION_TOO_OLD_RATE | `rate(tellus_quiver_ot_..._failure_total{errorName="OtBaseVersionTooOld"}[5m]) > 1` | Client offline > 200 ops; should auto re-fetch per F2 protocol |
| OT_CONFLICTS_TOMBSTONE | `rate(tellus_quiver_ot_conflicts_total{resolution="tombstone"}[5m]) > 5` | Concurrent delete+update churn; usually benign but worth noting |
| OT_LOG_SEQ_LAG | `tellus_quiver_ot_instruction_log_seq_lag > 1000` | Replay falling behind; check Postgres replication lag |

## SOPs

### Hot row (single analysis dominating SELECT FOR UPDATE)

1. `SELECT rid, count(*) FROM quiver_instruction_log GROUP BY 1 ORDER BY 2 DESC LIMIT 5`.
2. If a single RID has > 100K instructions and many concurrent submitters,
   freeze the analysis (set is_deleted = true, then revert) and
   investigate at app layer.

### Duplicate-op-id burst from one client

1. `SELECT applied_by, count(*) FROM quiver_instruction_log
    WHERE applied_at > now() - interval '5 minutes' GROUP BY 1 ORDER BY 2 DESC`.
2. If one user dominates, ask them to refresh; their client is in a
   retry loop ignoring the cached ack.

### Base-version-too-old loop

1. Client should auto re-fetch + rebase per F2 protocol.
2. If 412 OtBaseVersionTooOld is repeated > 5x, the client is broken;
   force-disconnect that user's WS sessions and ask them to reload.

### Replay validation

```bash
# Verify a single analysis replays to the canonical document.
curl -s -H "x-test-user: $USER" \
  "http://localhost:7311/quiver/api/v1/analyses/$RID/instructions?fromSeq=0" \
  | jq '.count'
# Compare against quiver_analysis.current_version.
```

## Disaster recovery

The instruction log is the source of truth. If a `quiver_analysis`
row is corrupted, replaying its log from `seq=0` reproduces the
canonical document (B3 C-10). The replay engine is in
`src/services/quiver/ot/replay.ts`.

A future runbook entry will cover restoring an analysis from
`replay()` — for now this is a manual operation; do it in a transaction:
