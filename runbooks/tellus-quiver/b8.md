# Runbook — B8 Time-Series Backend (Codex)

## Owned routes & operations

- `POST /quiver/api/v1/compute/cards` (when `cardType` ∈
  `TIME_SERIES_PLOT|TIME_SERIES_CHART|ROLLING_AGGREGATE|EVENT_SET|TIME_SERIES_FORMULA`).
- `GET /quiver/api/v1/compute/timeseries/:token` — cold-hydration polling.
- Backing service: Codex (in-process port stub `inProcessCodex` in dev).

## Alerts (Prometheus)

| Alert | Expression | Severity | Action |
|---|---|---|---|
| `QuiverTsWarmHydrationP99High` | `histogram_quantile(0.99, rate(tellus_quiver_ts_hydration_seconds_bucket{state="warm"}[5m])) > 0.5` | warn | Inspect `CodexPort.hydrateRange` latency; check Codex `/health`. |
| `QuiverTsColdHydrationP95High` | `histogram_quantile(0.95, rate(tellus_quiver_ts_hydration_seconds_bucket{state="cold"}[5m])) > 10` | warn | Codex saturating; check Codex queue depth. |
| `QuiverTsHydrationTimeoutSpike` | `rate(tellus_quiver_ts_hydration_timeouts_total[5m]) > 0.1` | page | Token TTL exceeded; check Codex availability + 60 s budget. |
| `QuiverTsBucketsCapHit` | `histogram_quantile(0.99, rate(tellus_quiver_ts_buckets_returned_bucket[5m])) >= 1000` | info | Defensive downsample triggering; verify dashboard chart density. |

## SOPs

### Cold-hydration timeouts spiking

1. `kubectl logs deploy/codex --tail=200 | rg hydrate` — confirm Codex is the choke point.
2. Confirm token TTL = 60 s in code (`HYDRATION_TOKEN_TTL_MS` in `tsBackend.ts`).
3. If Codex is healthy, increase `X-Deadline` budget upstream — coordinator may be passing < 60 s remaining.

### Per-axis hydration failure on a single axis

1. Inspect `quiver_card_output_cache` rows for the failing card; cache rows are keyed per-axis (B8 C-03).
2. Failing axis row will have `error_name` populated; healthy axes will not.
3. Fix axis-1 dependency without disturbing axis 2 (test `B8 C-03` enforces this isolation).

### Bucket-cap saturation

1. Inspect `tellus_quiver_ts_buckets_returned` histogram — sustained 1000 cap means downsample is silently active.
2. Check chart card config — too-wide time range or too-narrow viewport bucket count?
3. No data is lost (LTTB preserves shape) but high-frequency events may be merged; widen `bucketCount` if visual density permits.
