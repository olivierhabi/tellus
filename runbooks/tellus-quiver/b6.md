# Runbook — Quiver B6 (OSS Object-Set Backend)

## Surface

- **Path:** `POST /quiver/api/v1/compute/cards`
- **Card types served:** `OBJECT_SET`, `FILTER_OBJECT_SET`,
  `SEARCH_AROUND`, `AGGREGATION`, `PROPERTY_VALUE_SELECT`, `ACTION_BUTTON`.
- **Phase flag:** `TELLUS_QUIVER_PHASE >= 2` (shared with B5).

## Metrics

| Metric | Type | Labels | Threshold |
|---|---|---|---|
| `tellus_quiver_oss_query_seconds` | Histogram | `operation` | P99 ≤ 500 ms (load), 2 s (agg), 3 s (search-around d1) |
| `tellus_quiver_oss_query_errors_total` | Counter | `errorCode` | Burn-rate alert: >5/min OSS_UNAVAILABLE for 5m |
| `tellus_quiver_oss_temporary_set_creation_total` | Counter | (none) | Informational |
| `tellus_quiver_oss_action_apply_total` | Counter | `outcome` | Alert on `outcome=failure` rate >10/min for 5m |

## Alerts

1. **`tellus_quiver_oss_query_errors_total{errorCode="OSS_UNAVAILABLE"}` rate**
   - **Threshold:** >5/min for 5 minutes.
   - **Severity:** P2.
   - **SOP:**
     1. Check OSS service health: `curl https://oss/heartbeat`.
     2. If OSS down, page OSS on-call; circuit breaker should already be open
        (verify with `tellus_quiver_compute_circuit_state{backend="OSS"} == 2`).
     3. If circuit is closed but errors are flowing, suspect transient
        network/timeout — check Prometheus for spike in
        `oss_query_seconds{operation="loadObjectSetPage"}`.
     4. Escalate if duration > 30 minutes; recovery requires OSS-side fix.

2. **OSS limit-exceeded rate (`OBJECT_SET_LIMIT_EXCEEDED`)**
   - **Threshold:** >20/min for 10 minutes.
   - **Severity:** P3 (user-visible but not service-impacting).
   - **SOP:** Identify the analysis triggering large input sets via
     `tellus_quiver_compute_errors_total{errorCode="..."}` correlated with
     `tellus_quiver_compute_seconds{cardType="..."}`. Reach out to
     analysis owner; advise filter pre-narrowing or upgrade ontology to
     OSv2 storage.

3. **`tellus_quiver_oss_action_apply_total{outcome="failure"}` rate**
   - **Threshold:** >10/min for 5 minutes.
   - **Severity:** P2.
   - **SOP:**
     1. Identify the failing action via OMS audit log.
     2. Check OMS health (`canApplyAction` returning false uniformly →
        Multipass / OMS issue, not Quiver).
     3. If isolated to a specific user, check Multipass JWT validity.

## Common operations

### Toggle on/off

The B6 path inherits B5's phase flag. To disable Quiver compute entirely:

```
TELLUS_QUIVER_PHASE=1
```

This routes all `/compute/cards` requests to a 503 phase-disabled response.

### Swap in production OSS client

`src/services/quiver/compute/context.ts` calls
`new InProcessOssAdapter()` by default. Production should override at boot:

```ts
import { ProductionOssClient } from "...";
import { setOssPortForTests } from ".../context";
setOssPortForTests(new ProductionOssClient(...));
```

(Renaming `setOssPortForTests` → `setOssPort` is a follow-up; kept as
test-named for now to make audits explicit.)
