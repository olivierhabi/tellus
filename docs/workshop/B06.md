# B06 — OMS Metadata Facade + TTL Cache

## Surface
`GET /workshop/api/v1/object-types[/{id}]`,
`GET /workshop/api/v1/action-types[/{id}]`. Read-only — no audit row.
Reads from existing `object_type` + `action_type` tables (D-02 — same
process as the rest of the monolith).

Cache: `TtlCache<K,V>` per ontology, 30s TTL.
`omsFacade.invalidateOntology(ontologyRid)` is called by B09 (action
type wizard) and any object-type write path so the picker reflects new
types immediately.

## Alerts
| Alert | Trigger |
|---|---|
| `WorkshopOmsCacheStarved` | hit ratio < 0.7 for 1h |
| `WorkshopOmsLookupP95High` | P95 cache-miss > 400ms |

## Diagnose
- **Picker shows stale list**: invalidation didn't fire. The B09 path
  calls `invalidateOntology` after `createActionType`; verify by
  checking the `WORKSHOP_ACTION_TYPE_CREATED` audit row — if present
  but the cache still hits stale, there's an in-process invalidation
  bug.

## Remediate
- Force invalidation in a Node REPL:
  `import { invalidateOntology } from "src/services/workshop/omsFacade";
  invalidateOntology("ri.ontology.main.ontology.…")`.

## Metrics
- `workshop_oms_cache_hit_total`, `workshop_oms_lookup_seconds`.
