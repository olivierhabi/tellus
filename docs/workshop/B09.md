# B09 — Action Type Wizard API

## Surface
`POST /workshop/api/v1/action-types` — Idempotency-Key required.
Writes to existing `action_type` table (D-02 — same process). Emits
`WORKSHOP_ACTION_TYPE_CREATED` audit + invalidates the B06 OMS cache
for the ontology so the picker (F09) sees the new type within 0s.

`src/services/workshop/actionTypeWizard.ts`. Spec §C Phase 6 Step 1
canonical example: "Modify object(s)" with `assignee` (user-bound) +
`status` (static, value="assigned") + Submission Criteria User → self.

## Alerts
- `WorkshopActionTypeApiNameConflict spike`: > 1/min for 10m. Editor
  is letting users submit duplicate apiNames.

## Diagnose
- **`Tellus:Workshop:DuplicateParameterApiName`**: the request body
  has two parameters with the same `apiName`. F09 binding UI bug.
- **Cache stale after creation**: confirm `invalidateOntology` ran;
  see B06 runbook for the canonical procedure.
- **`updated_at` formatted as a string in audit details**: pg can
  return timestamps as `Date` or ISO `string` depending on parser
  config. Service handles both since the bug fix at
  `actionTypeWizard.ts:170-176`.

## Remediate
- A leaked partial action type (created but invalidation missed): run
  `omsFacade.invalidateOntology` for the ontology RID.

## Metrics
- `workshop_action_type_create_seconds`,
  `workshop_action_type_create_total{status}`.
