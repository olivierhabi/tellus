# B04 — Module Bootstrap

## Surface
`POST /workshop/api/v1/modules:bootstrap` — Idempotency-Key required.
Composes B01 createModule + B06 getObjectType to produce a fresh,
seeded Workshop module document (Phase 5 Step 1: "Create new" from
Ontology Manager).

`src/services/workshop/bootstrapService.ts`. Built last per §D Sprint 5
because it depends on B01 + B06.

## Alerts
- Inherits B01's PUT P95 + idempotency alerts; bootstrap is just a
  composed POST internally.

## Diagnose
- **Seeded variable missing**: the Object Set variable named `{Display
  Name} Object Set` must be present when `seedObjectTypeApiName` is
  set. If absent, B06's getObjectType returned a typed-but-empty record;
  `SELECT * FROM object_type WHERE api_name = $1`.
- **Validation 400 from bootstrap**: the seeded definition is
  validate-on-write through B02. Inspect `parameters.issues`. The most
  common cause is a downstream OMS schema change (new required column
  on object_type) — re-derive the seed.

## Remediate
- Failed bootstrap leaving a half-created module: B01's idempotency
  table records the response. If the row says `response_status = 500`,
  delete the record and let the user retry.

## Metrics
- Inherits `workshop_module_request_seconds{op="bootstrap"}`.
