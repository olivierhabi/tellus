# B03 — Versioning, Publish, Resolve

## Surface
- `POST /workshop/api/v1/modules/{rid}:publish` (Idempotency-Key required)
- `POST /workshop/api/v1/modules/{rid}/actions/rollback`
- `GET /workshop/api/v1/modules/{rid}/versions/{semver}`
- `GET /workshop/api/v1/modules/{rid}/resolve/{latest,dev}`

`src/services/workshop/versionService.ts`; migration
`src/migrations/060_b3_workshop_module_version.sql` (reversible).

Cache: in-process `ResolveCache`, 30s TTL; invalidation via Postgres
`LISTEN/NOTIFY` on channel `workshop_resolve` (D-04 — Redis substitute).

## Alerts
| Alert | Trigger |
|---|---|
| `WorkshopResolveP95High` | `histogram_quantile(0.95, …workshop_resolve_seconds{cache_hit="false"}) > 0.400` |
| `WorkshopResolveCacheStarved` | `rate(workshop_resolve_cache_hit_total[5m]) / rate(workshop_resolve_total[5m]) < 0.7` for 1h |
| `WorkshopPublishStuck` | publish operation > 30s wallclock |

## Diagnose
- **Stale resolve after publish**: NOTIFY listener died. `SELECT * FROM
  pg_stat_activity WHERE query LIKE 'LISTEN workshop_resolve%'`. If no
  rows, the listener is gone — bounce the service.
- **Republish (rollback) ignored**: rollback emits
  `WORKSHOP_MODULE_ROLLED_BACK`. Confirm via audit; if missing, the
  emitter shim is broken (likely test code in prod).

## Remediate
- Cache stuck stale: invalidate manually via `NOTIFY workshop_resolve,
  '<rid>'`.
- Audit gap on publish: backfill from `workshop_module_version` row
  (created_at + created_by are authoritative).

## Metrics
- `workshop_publish_seconds`, `workshop_resolve_seconds{cache_hit}`,
  `workshop_resolve_cache_hit_total`, `workshop_resolve_total`.
