# B10 — Action Validate + Apply

## Surface
- `POST /workshop/api/v1/actions/_validate` — no Idempotency-Key
- `POST /workshop/api/v1/actions/_apply` — Idempotency-Key required

Both forward branch + JWT verbatim into the in-process
`ActionsAdapter` (`src/services/workshop/actionsAdapter.ts`). Apply
emits `WORKSHOP_ACTION_APPLIED` audit and writes/replays the
idempotency record.

Property: `validate(p) === apply(p).validation` for any (action,
parameters) pair — verified by `actionApply-unit.test.ts`.

## Alerts
- `WorkshopApplyP95High`: P95 > 900ms.
- `WorkshopValidateP95High`: P95 > 250ms.
- `WorkshopActionStaleObjectSpike`: rate > 5/m for 10m — usually a
  hot-loop edit on the same object set; not necessarily an outage.

## Diagnose
- **`Tellus:Workshop:ActionStaleObject` 409**: the user opened a modal
  with a row at version N, the row moved to N+1 before submit. Per
  §B10 + Forbidden Behaviors the client MUST NOT auto-retry — the
  user reloads. Verify the editor surfaces the stale callout (see
  `SubmissionModal.tsx`).
- **`Tellus:Workshop:IdempotencyKeyReused` 409 surfacing as user
  error**: the FE classifier (`classifyApplyError`) MUST upgrade this
  to "applied" — server already applied. If the user sees a red error
  for this, the FE classifier broke. Test:
  `tests/unit/workshopWidgets.test.ts:F10 C-02`.

## Remediate
- Apply succeeded but no audit row: extremely unlikely (audit is
  inside the same transaction as the idempotency record write); if
  observed, that's a P1.
- Action timeout: server default 60s. `Tellus:Workshop:ActionTimeout`
  504 is reachable; the editor surfaces it without retry.

## Metrics
- `workshop_apply_seconds{phase="validate"|"apply"}`,
- `workshop_apply_total{status}`,
- `workshop_apply_stale_object_total` (counter for the stale
  back-pressure).

## WebSocket reconnect contract (§B10 chaos)
On force-disconnect, every client reconnects with backoff
`(1s, 2s, 4s, …, 30s cap)` and immediately re-subscribes. After
reconnect, the client performs a full B05 reload of every subscribed
variable — the server replays no missed messages.
