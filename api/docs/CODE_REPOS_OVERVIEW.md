## RID format (G-C-01..06)

Every owned resource has a Resource Identifier of the form:

```
ri.<service>.<realm>.<type>.<uuidv4>
```

| `service` | Owner |
|---|---|
| `stemma` | Stemma — repositories, refs, quarantine entries, events |
| `code-repository` | Code Repository service — saga ledger entries (internal) |
| `jemma` | Jemma — runs |
| `functions` | Functions Registry — function rows (composite RID by repo) |
| `templates` | Templates index entries |

`<realm>` is `main` in single-tenant deployments; multi-tenant deployments
use the tenant slug. `<uuidv4>` is generated by `crypto.randomUUID()`.

External (Compass-owned) RIDs like `parentFolderRid` use a different
service namespace (`compass`) and are validated by a permissive
structural check (`isStructurallyRid`) instead of the strict per-namespace
type check, since Code Repositories does not own them.

## Error envelope (G-C-12..16)

Every 4xx/5xx response has **exactly four keys**, no more, no less:

```json
{
  "errorCode":       "INVALID_ARGUMENT",
  "errorName":       "CodeRepos:NameConflict",
  "errorInstanceId": "01HX5N7JQEJF82MZRX1F8K9TKQ",
  "parameters":      { "displayName": "demo" }
}
```

- `errorCode` — one of 11 enum values (10 from gRPC canonical + `UNAUTHENTICATED` per D-2026-05-01-002).
- `errorName` regex: `^[A-Z][a-zA-Z0-9]{0,63}:[A-Z][a-zA-Z0-9]{0,63}$`.
- `errorInstanceId` — ULID; one log line on the server matches it 1:1.
- `parameters` — always present, possibly `{}`. Sanitised: never includes auth tokens, never includes raw bodies > 4 KiB.

Error names are namespaced per service: `CodeRepos:`, `Stemma:`,
`StemmaEvents:`, `BranchProtection:`, `Jemma:`, `Templates:`, `JobSpec:`,
`Functions:`.

## ETag & If-Match (G-C-17..19)

Every mutable resource carries `resource_version BIGINT NOT NULL DEFAULT 1`.
The server returns `ETag: W/"<resource_version>"` on every read and on
every successful mutation (with the bumped value).

PATCH and DELETE on those resources require an `If-Match: W/"<n>"` header.
Mismatch → `400 <Service>:InvalidSettings` (or analogous) with
`parameters.reason="etag-mismatch"` (semantically 412; envelope follows
§1.3 status mapping).

## Idempotency (G-C-20..23, G-C-25)

**Every mutating POST requires** `Idempotency-Key: <uuid v4>`.

- Same key + same body → captured response replayed verbatim with
  `X-Idempotent-Replay: true` header. Audit row count delta = 0 on replay.
- Same key + different body → `409 <Service>:IdempotencyConflict`.
- Same key from a different principal → independent (per-principal scope).
- TTL: 24h after `created_at`. Storage: `code_repos_idempotency` (migration 051).
- Non-UUID-v4 key → `400 <Service>:InvalidIdempotencyKey`.
- Missing key on a mutating POST → `400 <Service>:MissingIdempotencyKey`.

Read-only GETs and the `POST /pre-receive` policy decision (Stemma Events)
are explicitly exempt via the middleware's `skipPaths` option.

## Authentication & IDOR (G-C-07..11)

Bearer JWT via `Authorization` header OR `TELLUS_TOKEN` cookie. The
backend JWT middleware accepts both Tellus-issued and Keycloak access
tokens.

Test mode (`CODE_REPOS_TEST_AUTH=1`):
- `X-Tellus-Test-Principal: <userId>` — synthesises a principal.
- `X-Tellus-Test-Role: <role>` or `X-Tellus-Test-Roles: r1,r2` — assigns roles.
- Test mode is impossible to enable in production builds (gated on env flag).

**IDOR-as-404 (G-C-09)** — Unknown or unauthorized RID returns
`404 <Service>:<Resource>NotFound`, never 403. Tombstoned resources also
return 404 to all principals (no leak via existence-discovery).

## Cursor pagination (§1.5)

Every list endpoint uses opaque base64url cursors, ≥30-day stable shape.
Garbled token → `400 <Service>:InvalidPageToken`. Default `pageSize=20`,
max `pageSize=100`. Response shape:

```json
{
  "items":         [ /* … */ ],
  "nextPageToken": "eyJjcmVhdGVkQXQi…" | null
}
```

`null` `nextPageToken` indicates the final page.

## Audit (G-C-51..54, §1.10)

Every mutating endpoint emits exactly one row in `code_repos_audit_events`
(migration 051) within the same SERIALIZABLE transaction as the data
write. The transaction commits as a unit; if audit fails, the data
rolls back (G-C-52 durable-before-ack).

Audit row schema:
- `audit_id UUID` (PK)
- `seq BIGSERIAL` — global ordering
- `category TEXT` — `'code_repository'`, `'stemma'`, `'stemma_events'`, …
- `action TEXT` — e.g. `'createRepository'`, `'patchRepository'`, …
- `principal_user_id`, `principal_source` (`'jwt'` | `'test-mode'`)
- `parameters_canon JSONB` — sanitised request body
- `before_hash`, `after_hash` — sha256 of canonicalised resource state
- `chain_prev_hash`, `chain_row_hash` — append-only hash chain via
  `code_repos_audit_hash_head` (advisory-lock-protected singleton).

`recordAuditChainHeadMissing()` increments the
`audit_hash_head_missing_total` counter **before** throwing — so audit
chain corruption is observable in metrics even when the failing tx
rolls back. P1 alert.

## Health & readiness (G-C-41)

Every Express app factory mounts:
- `GET /health` — 200 with `{ "status": "ok" }`. Unauthenticated.
- `GET /readiness` — 200 when the DB pool answers a `SELECT 1`; 503 otherwise.
