## Contract interpretations made

1. **Conjure error body uses `parameters._message`** rather than top-level `message` field. The Foundry/OSDK Python contract's top-level body has only `errorCode`, `errorName`, `errorInstanceId`, `parameters`; human messages live inside `parameters._message`. Logged here so future tasks (B7 proposals errors, B9 Funnel errors) follow the same shape.

2. **Idempotency-Key store TTL = 24h via `expires_at` column** rather than periodic sweep. The contract requires "24h replay window"; expiring rows are filtered at lookup time (`WHERE expires_at > now()`). A sweep job is left to B5's trash retention worker (which already needs a periodic cron).

3. **`patScopeMap.ts` rules for /api/v2/filesystem**: GET → `api:read`, all other methods → `api:write`. Spec is silent on PAT scope mapping for v2; matching the v1 default keeps PAT-mediated tests green without inventing new scopes.

4. **Resource `parent_folder_rid`**: top-level folders inside a project use the project's RID as the parent (per B1's existing model in `compassService`'s `_resolveParentForResource`). The `POST /folders` handler delegates to that semantic — passing `null` as `parent_folder_id` to FolderService when the parent is a PROJECT.
