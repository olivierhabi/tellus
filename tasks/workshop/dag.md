## Hard ordering rules (do not violate)

1. **F-anything before B01+B02+B03 is forbidden** — there is no module to render.
2. **F05/F06/F07/F08 before F04 is forbidden** — widgets that bind to variables cannot be tested without the runtime.
3. **B09 before F09 is law** — action-type API must exist before the binding UI.
4. **B10 before F10 is law** — apply + refresh-bus contract must exist before the view-mode renderer that calls it.
5. **B04 sequenced last** — composes B01 + B06 and is best built once those have stabilized; do NOT move it earlier.
6. If a downstream task surfaces a defect in an upstream Done task, **stop**, reopen the upstream task, fix it (with new tests covering the defect), and only then resume.

## Highest-risk tasks (per §E)

1. **F04** Variable Runtime — property-based tests on the topo sort and recompute scheduler are mandatory.
2. **B07 + F06** UI-kind ↔ predicate matrix is large; missing one combination breaks a widget silently. Generate the matrix from a single source of truth.
3. **B10** Stale-object semantics + idempotency + WS reconnect — three independently tricky concerns intersecting.
4. **F10** Reactive refresh after apply must invalidate exactly the right variables — over-invalidate = jank, under-invalidate = stale data. Trace deps via the compiled var graph from B02.
5. **B03** ETag + branch interaction under concurrent edit is the hardest concurrency surface. Lock the row and recompute ETag inside the same transaction.
