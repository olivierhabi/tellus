# TASK 6 OF 30: Database Migration — Funnel State Table

**Objective:** Add the funnel_state table to src/migrate.js. This table tracks the indexing state of each object type, modeling a simplified version of Palantir's Object Indexing pipeline. Reference: https://www.palantir.com/docs/foundry/object-indexing/overview/.

**Step-by-step instructions:**

Add `CREATE TABLE IF NOT EXISTS funnel_state` to src/migrate.js AFTER the backing_datasource table (order matters for consistent migration flow, though funnel_state has no dependency on backing_datasource). The table has 14 columns:

- `funnel_state_id`: UUID PRIMARY KEY DEFAULT gen_random_uuid()
- `object_type_id`: UUID NOT NULL UNIQUE, FOREIGN KEY to object_type(object_type_id) ON DELETE CASCADE. The UNIQUE constraint ensures one funnel_state row per object type.
- `status`: TEXT NOT NULL DEFAULT 'not_indexed', CHECK (status IN ('not_indexed', 'indexing', 'indexed', 'failed', 'stale')). These five statuses form a state machine (see below).
- `objects_indexed`: INTEGER DEFAULT 0
- `objects_failed`: INTEGER DEFAULT 0
- `edits_pending`: INTEGER DEFAULT 0
- `last_indexed_at`: TIMESTAMPTZ, nullable
- `last_index_duration_ms`: INTEGER, nullable
- `last_datasource_modified_at`: TIMESTAMPTZ, nullable
- `error_message`: TEXT, nullable
- `error_count`: INTEGER DEFAULT 0
- `index_name`: TEXT, nullable. Stores the OpenSearch index name (e.g., "ontology-employee"). Generated by `toIndexName()` from Task 8.
- `created_at`: TIMESTAMPTZ DEFAULT now()
- `updated_at`: TIMESTAMPTZ DEFAULT now()

Create an index: `CREATE INDEX IF NOT EXISTS idx_funnel_state_object_type ON funnel_state(object_type_id)`.

**State machine transitions:**
```
not_indexed → indexing     (when indexing starts, future sprint)
indexing    → indexed      (when indexing completes successfully)
indexing    → failed       (when indexing encounters an error)
indexed     → stale        (when datasource is updated/replaced, Task 17)
stale       → indexing     (when re-indexing starts)
failed      → not_indexed  (when datasource is re-registered, Task 17)
```

The initial funnel_state row is created by `objectTypeService.create` (Task 13) with status `'not_indexed'`. The status is updated by `datasourceService` (Task 17) to `'stale'` when a datasource changes. The `indexing` → `indexed`/`failed` transitions are implemented in a future sprint (Week 2: OpenSearch indexing).

After creating the table, log: `"Created table: funnel_state"` (or `"Table already exists: funnel_state"` if it already exists, consistent with the logging pattern from Task 2).

**Files to modify:** src/migrate.js

**Verification:**
- After migration, `\d funnel_state` shows 14 columns
- Status CHECK rejects invalid values: `INSERT INTO funnel_state (object_type_id, status) VALUES (gen_random_uuid(), 'invalid')` → fails
- UNIQUE on object_type_id prevents two funnel_state rows for the same object type
- Migration is idempotent: running `npm run migrate` twice produces no errors
