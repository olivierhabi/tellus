## BE-024: Implement Empty Collection Metadata and Suggestion Hints API

**Palantir Feature:** Data Browsing — Contextual guidance when users encounter empty states in Foundry's file browser and search.

### Objective

Extend list endpoints to return a `hints` object when collections are empty. FE-024 builds empty state components that display contextual messages and action buttons (e.g., "Create your first project" with a create button, or "No results found — try broader keywords" with search suggestions). Rather than hardcoding these messages in the frontend, the backend provides them via the `hints` field so the messages can be updated server-side without a frontend deployment. The `hints` field is only included when the primary data collection is empty; populated responses omit it entirely.

### Implementation

**Hints Response Contract**

The `hints` object is an optional field at the top level of list responses, sibling to `data` and `meta`. It is only present when `data` is an empty array (or all sub-collections are empty for composite endpoints).

```typescript
interface HintsAction {
  action: string;        // Machine-readable action identifier for FE button routing
  label: string;         // Human-readable button text
  description?: string;  // Optional longer explanation
}

interface HintsResponse {
  actions?: HintsAction[];
  suggestions?: string[];
  message?: string;
}
```

**GET /api/projects — Empty Projects Hints**

When the authenticated user has zero projects, return:

```json
{
  "data": [],
  "meta": { "total": 0 },
  "hints": {
    "message": "Create your first project to get started with Foundry.",
    "actions": [
      {
        "action": "create_project",
        "label": "Create Project",
        "description": "Projects organize your folders and datasets."
      }
    ]
  }
}
```

When the user has projects, omit `hints` entirely from the response (do not include `hints: null`).

Update `projectService.listProjects()` to check the result count. If zero, attach the hints object in the controller before sending the response:

```typescript
async list(req: Request, res: Response) {
  const result = await this.projectService.listProjects(req.user.id);
  const response: any = { data: result, meta: { total: result.length } };

  if (result.length === 0) {
    response.hints = {
      message: 'Create your first project to get started with Foundry.',
      actions: [{ action: 'create_project', label: 'Create Project', description: 'Projects organize your folders and datasets.' }]
    };
  }

  res.json(response);
}
```

**GET /api/projects/:projectId/folders/:folderId — Empty Folder Hints**

When a folder contains no subfolders and no datasets, return:

```json
{
  "data": { "folders": [], "datasets": [] },
  "hints": {
    "message": "This folder is empty.",
    "actions": [
      { "action": "upload_files", "label": "Upload Files", "description": "Upload CSV or Excel files to create datasets." },
      { "action": "create_subfolder", "label": "Create Folder", "description": "Organize your data with subfolders." }
    ]
  }
}
```

The `actions` array is ordered by recommended priority. The frontend renders the first action as the primary button and subsequent actions as secondary buttons.

**GET /api/search — Empty Search Results Hints**

When a search query returns zero results, return:

```json
{
  "data": [],
  "meta": { "total": 0 },
  "hints": {
    "message": "No results found for your search.",
    "suggestions": [
      "Check your spelling",
      "Try broader keywords",
      "Remove filters to expand results",
      "Search by file name or dataset content"
    ]
  }
}
```

The `suggestions` array provides plain-text hints rendered as a bulleted list in FE-024's empty search state component.

**Hints Utility**

Create `src/utils/hints.ts` centralizing all hints definitions:

```typescript
export const PROJECT_EMPTY_HINTS: HintsResponse = {
  message: 'Create your first project to get started with Foundry.',
  actions: [{ action: 'create_project', label: 'Create Project', description: 'Projects organize your folders and datasets.' }]
};

export const FOLDER_EMPTY_HINTS: HintsResponse = {
  message: 'This folder is empty.',
  actions: [
    { action: 'upload_files', label: 'Upload Files', description: 'Upload CSV or Excel files to create datasets.' },
    { action: 'create_subfolder', label: 'Create Folder', description: 'Organize your data with subfolders.' }
  ]
};

export const SEARCH_EMPTY_HINTS: HintsResponse = {
  message: 'No results found for your search.',
  suggestions: ['Check your spelling', 'Try broader keywords', 'Remove filters to expand results', 'Search by file name or dataset content']
};
```

Centralizing hints in one file ensures consistent messaging and makes future updates (e.g., localization) straightforward.

### Acceptance Criteria

- `GET /api/projects` returns `hints` with `actions` containing `create_project` when user has no projects
- `GET /api/projects` omits `hints` entirely when user has one or more projects
- `GET /api/projects/:projectId/folders/:folderId` returns `hints` with `upload_files` and `create_subfolder` actions when folder is empty
- `GET /api/projects/:projectId/folders/:folderId` omits `hints` when folder has any content
- `GET /api/search?q=xyz` returns `hints` with `suggestions` array when search yields zero results
- `GET /api/search?q=xyz` omits `hints` when search yields results
- All `hints.actions` entries include `action`, `label`, and optional `description`
- All `hints.suggestions` entries are plain strings
- Hints definitions are centralized in `src/utils/hints.ts`
- The `hints` field is never `null` — it is either a populated object or absent from the response
- FE-024 can render action buttons by mapping `hints.actions[].action` to frontend routes
