# BE-016: Implement WebSocket Heartbeat and Reconnection Protocol Support

**Palantir Feature:** Data Ingestion — Reliable real-time push notifications in Foundry. The server must detect stale clients, support subscription persistence across reconnections, and provide a fallback endpoint for missed events during disconnection periods.

## Objective

Extend the WebSocket server (from BE-012) with server-side heartbeat (ping/pong), stale client detection, subscription persistence per client, subscription replay support after client reconnection, and a bulk status endpoint for missed-event compensation. These features are the backend counterparts to FE-016's WebSocket Connection Manager, ensuring that the server-side connection lifecycle is robust and that clients can reliably recover from network interruptions.

## Server-Side Ping/Pong Heartbeat

Add a heartbeat mechanism to detect and terminate stale connections. The WebSocket protocol (RFC 6455) defines control frames for ping and pong. The server sends periodic pings; the client's WebSocket implementation automatically responds with pongs.

### Implementation

In `src/websocket/wsServer.ts`, add a heartbeat interval per connection:

```typescript
import { WebSocketServer, WebSocket } from 'ws';

wss.on('connection', (ws: WebSocket) => {
  (ws as any).isAlive = true;

  ws.on('pong', () => {
    (ws as any).isAlive = true;
  });

  // Store client metadata
  (ws as any).subscriptions = new Set<string>();
  (ws as any).clientId = generateClientId();
});

// Global heartbeat interval — runs every 30 seconds
const heartbeatInterval = setInterval(() => {
  wss.clients.forEach((ws) => {
    if ((ws as any).isAlive === false) {
      // No pong received since last ping — client is stale
      cleanupClient(ws);
      ws.terminate();
      return;
    }

    (ws as any).isAlive = false;
    ws.ping(); // Client has 30 seconds to respond with pong
  });
}, 30000);

wss.on('close', () => {
  clearInterval(heartbeatInterval);
});
```

### Timing

- **Ping interval:** 30 seconds. The server sends a ping frame to every connected client every 30 seconds.
- **Pong timeout:** If no pong is received before the next ping cycle (i.e., within 30 seconds), the `isAlive` flag remains `false` and the client is terminated on the next sweep. This effectively gives clients up to 30 seconds to respond.
- **Why 30 seconds:** Balances between prompt stale client detection and tolerance for temporary network latency. Shorter intervals (e.g., 5 seconds) generate excessive traffic; longer intervals (e.g., 60 seconds) leave stale connections open too long, consuming server resources.

## Stale Client Cleanup

When a client is terminated (no pong received) or disconnects:

```typescript
function cleanupClient(ws: WebSocket): void {
  const clientId = (ws as any).clientId;
  const subscriptions = (ws as any).subscriptions as Set<string>;

  // Remove client from all subscription channel maps
  for (const channel of subscriptions) {
    const channelClients = subscriptionMap.get(channel);
    if (channelClients) {
      channelClients.delete(ws);
      if (channelClients.size === 0) {
        subscriptionMap.delete(channel);
      }
    }
  }

  // Log for monitoring
  console.log(`Client ${clientId} terminated: ${subscriptions.size} subscriptions cleaned up`);
}
```

## Subscription Persistence

Track active subscriptions per client using a `Set<string>` stored on the WebSocket instance. When a client subscribes to a channel, add it to both the client's set and the global subscription map:

```typescript
// Global subscription map: channel → Set of WebSocket clients
const subscriptionMap = new Map<string, Set<WebSocket>>();

function handleSubscribe(ws: WebSocket, channel: string): void {
  // Add to client's subscription set
  (ws as any).subscriptions.add(channel);

  // Add to global subscription map
  if (!subscriptionMap.has(channel)) {
    subscriptionMap.set(channel, new Set());
  }
  subscriptionMap.get(channel)!.add(ws);

  ws.send(JSON.stringify({ type: 'subscribed', channel }));
}

function handleUnsubscribe(ws: WebSocket, channel: string): void {
  (ws as any).subscriptions.delete(channel);

  const channelClients = subscriptionMap.get(channel);
  if (channelClients) {
    channelClients.delete(ws);
    if (channelClients.size === 0) {
      subscriptionMap.delete(channel);
    }
  }

  ws.send(JSON.stringify({ type: 'unsubscribed', channel }));
}
```

## Subscription Replay Support

After a client reconnects, it sends a `resubscribe` message containing the list of channels it was previously subscribed to:

```typescript
// Client sends: { type: 'resubscribe', channels: ['project:uuid-1', 'dataset:uuid-2'] }

ws.on('message', (raw: string) => {
  const message = JSON.parse(raw);

  switch (message.type) {
    case 'subscribe':
      handleSubscribe(ws, message.channel);
      break;

    case 'unsubscribe':
      handleUnsubscribe(ws, message.channel);
      break;

    case 'resubscribe':
      // Bulk re-subscription after reconnect
      if (Array.isArray(message.channels)) {
        for (const channel of message.channels) {
          if (typeof channel === 'string' && channel.length <= 255) {
            handleSubscribe(ws, channel);
          }
        }
        ws.send(JSON.stringify({
          type: 'resubscribed',
          channels: Array.from((ws as any).subscriptions)
        }));
      }
      break;
  }
});
```

### Validation

- The `channels` array must contain only strings, each at most 255 characters.
- Maximum 100 channels per `resubscribe` message. If more than 100 are provided, only the first 100 are processed and a warning is included in the response.
- Invalid channel names are silently skipped (no error thrown, but not added to subscriptions).

## Missed-Event Compensation Endpoint

`GET /api/v1/datasets/status-batch?ids=uuid1,uuid2,uuid3`

After reconnecting, the client needs to check whether any datasets changed status during the disconnection. Rather than making N individual `GET /datasets/:id/status` calls, the client uses this batch endpoint to fetch statuses for all tracked datasets in a single request.

### Query

```sql
SELECT id, status, updated_at
FROM datasets
WHERE id = ANY($1::uuid[])
```

### Query Parameters

- `ids` (string, required) — comma-separated list of dataset UUIDs. Maximum 50 IDs per request.

### Validation

```typescript
const StatusBatchQuerySchema = z.object({
  ids: z.string().transform(val => val.split(',')).pipe(
    z.array(z.string().uuid()).min(1).max(50)
  )
});
```

Return 400 if `ids` is missing, contains invalid UUIDs, or exceeds 50 entries.

### Response Shape

```json
{
  "success": true,
  "data": [
    { "id": "uuid-1", "status": "ready", "updatedAt": "2024-03-15T10:06:00Z" },
    { "id": "uuid-2", "status": "processing", "updatedAt": "2024-03-15T10:05:30Z" },
    { "id": "uuid-3", "status": "error", "updatedAt": "2024-03-15T10:05:45Z" }
  ]
}
```

Datasets that do not exist are silently omitted from the response (no 404 per missing ID). The client compares the returned list with its request list to detect deleted datasets.

## WebSocket Message Protocol Summary

| Client Message | Server Response | Purpose |
|---------------|----------------|---------|
| `{ type: 'subscribe', channel: 'project:uuid' }` | `{ type: 'subscribed', channel: 'project:uuid' }` | Subscribe to a channel |
| `{ type: 'unsubscribe', channel: 'project:uuid' }` | `{ type: 'unsubscribed', channel: 'project:uuid' }` | Unsubscribe from a channel |
| `{ type: 'resubscribe', channels: ['...'] }` | `{ type: 'resubscribed', channels: ['...'] }` | Bulk re-subscribe after reconnect |
| (automatic pong) | (server-initiated ping) | Heartbeat / stale detection |

## Acceptance Criteria

- Server sends WebSocket ping frames to all connected clients every 30 seconds
- Clients that do not respond with pong within 30 seconds are terminated
- Terminated clients have their subscriptions cleaned up from the global subscription map
- Each client's active subscriptions are tracked in a per-client `Set<string>`
- `subscribe` message adds the channel to the client's subscription set and the global map
- `unsubscribe` message removes the channel from the client's subscription set and the global map
- `resubscribe` message bulk-subscribes the client to all provided channels and returns a confirmation with the active channel list
- `resubscribe` validates channel names (strings, max 255 chars) and limits to 100 channels per message
- GET /api/v1/datasets/status-batch?ids=a,b,c returns statuses for all requested datasets in a single response
- Batch endpoint accepts up to 50 comma-separated UUIDs
- Batch endpoint returns 400 for missing `ids`, invalid UUIDs, or more than 50 IDs
- Non-existent dataset IDs are silently omitted from the batch response (no 404)
- Heartbeat interval is cleared when the WebSocket server closes (no interval leak)
- Empty subscription channels are removed from the global map when the last client unsubscribes
