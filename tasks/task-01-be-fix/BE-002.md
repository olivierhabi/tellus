# BE-002: Implement Folder Contents API with Subfolder and Dataset Aggregation

**Palantir Feature:** Project Setup — Folder browsing in Foundry, where selecting a folder displays its child folders and datasets in a unified view. The Speedrun course folder "Speedrun: Your First E2E Workflow" contains uploaded CSV datasets and optional subfolders, all visible in a single listing.

## Objective

Build the `GET /projects/:projectId/folders/:folderId` endpoint that returns the complete contents of a folder: its own metadata, child subfolders with summary counts, and child datasets with full metadata. This is the primary API endpoint that powers the folder contents page (FE-002), where users browse their project file structure. The response must be shaped so the frontend can render subfolder cards and a dataset table without additional API calls.

## Endpoint Definition

`GET /api/projects/:projectId/folders/:folderId`

### Path Parameters

- `projectId` (UUID, required) — the project that owns this folder. Validated against the folder's actual `project_id` to prevent cross-project access. Return 403 if the folder does not belong to the specified project.
- `folderId` (UUID, required) — the folder whose contents are being requested. Return 404 with `'Folder not found'` if no folder exists with this ID.

### Query Parameters (optional)

- `sortBy` (string) — one of: `name`, `created_at`, `file_size_bytes`, `row_count`, `column_count`. Default: `name`. Only applied to datasets, not subfolders.
- `sortOrder` (string) — one of: `asc`, `desc`. Default: `asc`.

Validate query parameters with Zod:

```typescript
const FolderContentsQuerySchema = z.object({
  sortBy: z.enum(['name', 'created_at', 'file_size_bytes', 'row_count', 'column_count']).default('name'),
  sortOrder: z.enum(['asc', 'desc']).default('asc')
});
```

Server-side sorting is always available but is semantically important when dataset count reaches 200 or more (FE-002 switches from client-side to server-side sorting at that threshold).

## Service Implementation

Create or extend `src/services/folderService.ts` with a `getFolderContents(projectId, folderId, sortBy, sortOrder)` method.

### Step 1 — Fetch Folder Metadata

```sql
SELECT id, name, parent_folder_id, project_id, path, depth, created_at, updated_at
FROM folders
WHERE id = $1 AND project_id = $2
```

Return 404 if no row is found.

### Step 2 — Fetch Child Subfolders

```sql
SELECT f.id, f.name, f.parent_folder_id, f.created_at,
  (SELECT COUNT(*) FROM folders WHERE parent_folder_id = f.id) AS child_folder_count,
  (SELECT COUNT(*) FROM datasets WHERE folder_id = f.id) AS dataset_count
FROM folders f
WHERE f.parent_folder_id = $1 AND f.project_id = $2
ORDER BY f.name ASC
```

Subfolders are always sorted alphabetically by name. The `child_folder_count` and `dataset_count` subqueries allow the frontend to display summary badges on each subfolder card (e.g., "3 folders, 12 datasets") without requiring a separate request per subfolder.

### Step 3 — Fetch Child Datasets

```sql
SELECT id, name, status, file_size_bytes, row_count, column_count,
       original_filename, mime_type, created_at, updated_at
FROM datasets
WHERE folder_id = $1
ORDER BY ${sortBy} ${sortOrder}, id ASC
```

The secondary sort by `id ASC` ensures deterministic ordering when multiple datasets share the same sort value (e.g., identical `created_at` timestamps). All datasets in the folder are returned (no server-side pagination) because the frontend implements client-side search which requires the complete list. If future datasets exceed reasonable limits, cursor-based pagination (BE-019) can be applied.

## Edge Cases

### Empty Folder

When a folder contains no subfolders and no datasets, return `children: { folders: [], datasets: [] }`. This is not an error — the frontend renders an empty state UI.

### Root Folder Access

Root-level folders (where `parent_folder_id IS NULL`) are valid targets for this endpoint. The `parentFolderId` field in the response will be `null`.

### Deleted or Processing Datasets

Datasets in all statuses (`pending`, `processing`, `ready`, `error`) are returned. The frontend uses the status field to render appropriate visual indicators (e.g., spinner for processing, error icon for failed).

### Sort Column Nullability

The `row_count` and `column_count` columns are nullable (populated after parsing). When sorting by these columns, use `NULLS LAST` for ascending order and `NULLS FIRST` for descending order so that unparsed datasets appear at the end regardless of sort direction:

```sql
ORDER BY ${sortBy} ${sortOrder} NULLS LAST, id ASC
```

## Acceptance Criteria

- GET /api/projects/:projectId/folders/:folderId returns 200 with folder metadata, child folders, and child datasets
- Each child subfolder includes `childFolderCount` and `datasetCount` aggregation fields
- Each child dataset includes `name`, `status`, `fileSizeBytes`, `rowCount`, `columnCount`, `createdAt`
- Datasets are sorted by the `sortBy` query parameter (default: `name`) in the `sortOrder` direction (default: `asc`)
- When `sortBy` is `row_count` or `column_count`, datasets with null values appear last regardless of sort direction
- Subfolders are always sorted alphabetically by name
- Requesting a folder that does not exist returns 404
- Requesting a folder that belongs to a different project returns 403
- Empty folders return `children: { folders: [], datasets: [] }` (not 404)
- All response field names use camelCase
- Datasets in all statuses (pending, processing, ready, error) are included in the response
- Invalid `sortBy` or `sortOrder` values return 400 with validation error
