## BE-029: Implement Dataset Metadata Summary Endpoint for UI Badges

**Palantir Feature:** Data Ingestion — Dataset metadata summary powering file size, row count, and column count badges in Foundry's folder browser.

### Objective

Build a lightweight summary endpoint for individual datasets and ensure the folder contents endpoint includes inline summary metadata for each dataset. FE-029 renders metadata badges (file size, row count, column count, parse time) next to each dataset in the folder view. Without inline metadata in the folder contents response, the frontend would need to make N additional API calls (one per dataset) to fetch badge data, causing N+1 query problems and visible loading jitter as badges pop in one by one. This task eliminates that pattern by providing all badge data in two ways: a dedicated summary endpoint for single-dataset views and inline fields in the folder listing.

### Implementation

**Dataset Summary Endpoint**

`GET /api/v1/datasets/:datasetId/summary`

Returns a compact metadata object with only the fields needed for UI badges:

```typescript
interface DatasetSummary {
  datasetId: string;
  fileSize: number;           // bytes, always a number (0 for unknown)
  rowCount: number | null;    // null if not yet parsed
  columnCount: number | null; // null if not yet parsed
  parsedAt: string | null;    // ISO 8601 string, null if not yet parsed
  status: string;             // 'pending' | 'processing' | 'ready' | 'error'
  originalFilename: string;
  mimeType: string;
}
```

SQL query:
```sql
SELECT
  id AS "datasetId",
  file_size_bytes AS "fileSize",
  row_count AS "rowCount",
  column_count AS "columnCount",
  parsed_at AS "parsedAt",
  status,
  original_filename AS "originalFilename",
  mime_type AS "mimeType"
FROM datasets
WHERE id = $1
```

Field type enforcement:
- `fileSize` must be a JavaScript `number`, not a string. PostgreSQL's `bigint` columns return strings in the `pg` driver by default. Use `parseInt()` or configure the pg driver's type parser for bigint columns: `pg.types.setTypeParser(20, parseInt)`.
- `rowCount` and `columnCount` are `number | null`. When the dataset status is `pending` or `processing`, these are `null`. When `ready`, they are integers.
- `parsedAt` is an ISO 8601 string (e.g., `"2026-03-15T14:30:00.000Z"`) or `null`. Use `.toISOString()` on the Date object returned by the pg driver, or configure Knex to return raw ISO strings.

Return 404 if the dataset does not exist. Return 400 if the datasetId is not a valid UUID.

**Inline Summary in Folder Contents Endpoint**

Update the folder contents query in `src/services/folderService.ts` (or equivalent) to include summary fields for each dataset in the response. This is the critical N+1 prevention.

Current folder contents query returns datasets with basic fields. Extend it to include badge metadata:

```sql
SELECT
  d.id,
  d.name,
  d.status,
  d.file_size_bytes AS "fileSize",
  d.row_count AS "rowCount",
  d.column_count AS "columnCount",
  d.parsed_at AS "parsedAt",
  d.original_filename AS "originalFilename",
  d.mime_type AS "mimeType",
  d.created_at,
  d.updated_at
FROM datasets d
WHERE d.folder_id = $1
ORDER BY d.name ASC
```

This is a single query that returns all datasets in a folder with all badge metadata. No additional queries needed. The extra columns add approximately 50-80 bytes per row to the response, which is negligible compared to the cost of N separate HTTP round trips.

**Type Safety**

Add the `DatasetSummary` interface to `src/types/dataset.ts`:

```typescript
export interface DatasetSummary {
  datasetId: string;
  fileSize: number;
  rowCount: number | null;
  columnCount: number | null;
  parsedAt: string | null;
  status: 'pending' | 'processing' | 'ready' | 'error';
  originalFilename: string;
  mimeType: string;
}
```

**Route Definition**

Add to `src/routes/datasets.ts`:
```typescript
router.get('/:datasetId/summary', authenticate, controller.getSummary);
```

**Controller Implementation**

```typescript
async getSummary(req: Request, res: Response) {
  const { datasetId } = req.params;
  const summary = await this.datasetService.getDatasetSummary(datasetId);
  res.json({ data: summary });
}
```

**Numeric Field Guarantee**

FE-029's `formatFileSize(bytes)` and `formatNumber(n)` utilities expect JavaScript numbers. If `fileSize` arrives as `"1234567"` (string), the formatter produces incorrect output. Add a response transformation layer in the service that explicitly coerces numeric fields:

```typescript
function ensureNumericFields(dataset: any): DatasetSummary {
  return {
    ...dataset,
    fileSize: Number(dataset.fileSize) || 0,
    rowCount: dataset.rowCount != null ? Number(dataset.rowCount) : null,
    columnCount: dataset.columnCount != null ? Number(dataset.columnCount) : null,
  };
}
```

### Acceptance Criteria

- `GET /api/v1/datasets/:datasetId/summary` returns `{ data: { datasetId, fileSize, rowCount, columnCount, parsedAt, status, originalFilename, mimeType } }`
- `fileSize` is always a JavaScript number (never a string), even for large files exceeding 2^31 bytes
- `rowCount` and `columnCount` are numbers when status is `ready`, null when `pending` or `processing`
- `parsedAt` is an ISO 8601 string when the dataset has been parsed, null otherwise
- `status` is one of: `pending`, `processing`, `ready`, `error`
- `GET /api/v1/datasets/:datasetId/summary` returns 404 for non-existent dataset
- `GET /api/v1/datasets/:datasetId/summary` returns 400 for malformed UUID
- Folder contents endpoint includes `fileSize`, `rowCount`, `columnCount`, `parsedAt`, `originalFilename`, `mimeType` inline for each dataset
- Folder contents endpoint uses a single SQL query (no N+1 queries for badge data)
- All numeric fields pass `typeof value === 'number'` check in JavaScript (not string representations)
- The summary endpoint returns the same field values as the inline fields in folder contents (data consistency)
