# BE-019: Implement Folder Rename API with Duplicate Detection and Path Update

**Palantir Feature:** Project Setup — Renaming folders in Foundry's Workspace Navigator. When a user renames a folder via inline editing in the sidebar tree, the backend must validate the new name, check for duplicates, and update the ltree path for the folder and all its descendants.

## Objective

Build the `PUT /projects/:projectId/folders/:folderId` endpoint for renaming a folder. The endpoint validates the new name against character constraints and length limits, checks for duplicate names within the same parent folder, and — critically — updates the ltree path for the renamed folder and all of its descendants. Because ltree paths encode folder identity, renaming a folder does not actually change any paths (paths use UUID segments, not names). This simplifies the rename operation to a name-only update with duplicate checking.

## Endpoint Definition

`PUT /api/v1/projects/:projectId/folders/:folderId`

### Path Parameters

- `projectId` (UUID, required) — validated against the folder's actual `project_id`. Return 403 if the folder does not belong to this project.
- `folderId` (UUID, required) — the folder to rename. Return 404 with `'Folder not found'` if no folder exists with this ID.

### Request Body

```typescript
const RenameFolderSchema = z.object({
  name: z.string()
    .min(1, 'Folder name is required')
    .max(255, 'Folder name must be 255 characters or fewer')
    .trim()
    .refine(val => !val.includes('/') && !val.includes('\\'), {
      message: 'Folder name cannot contain / or \\ characters'
    })
});
```

### Validation Details

1. **Non-empty:** After trimming, the name must have at least 1 character. Return 400 with `'Folder name is required'`.
2. **Max length:** 255 characters after trimming. Return 400 with `'Folder name must be 255 characters or fewer'`.
3. **No path separators:** The name must not contain `/` or `\` characters. These characters conflict with filesystem paths and URL routing. Return 400 with `'Folder name cannot contain / or \\ characters'`.
4. **Trimming:** Leading and trailing whitespace is removed before validation and storage.

## Service Implementation

Create or extend `src/services/folderService.ts` with a `renameFolder(projectId, folderId, name)` method:

```typescript
async renameFolder(projectId: string, folderId: string, name: string): Promise<Folder> {
  // 1. Verify folder exists and belongs to this project
  const folder = await this.knex('folders')
    .where({ id: folderId, project_id: projectId })
    .first();

  if (!folder) {
    throw new AppError(404, 'Folder not found');
  }

  // 2. Check for duplicate name within the same parent
  const duplicate = await this.knex('folders')
    .where({
      project_id: projectId,
      parent_folder_id: folder.parent_folder_id,
      name: name
    })
    .whereNot({ id: folderId }) // Exclude the folder being renamed
    .first();

  if (duplicate) {
    throw new AppError(409, 'A folder with this name already exists in this location');
  }

  // 3. Update the name
  const [updated] = await this.knex('folders')
    .where({ id: folderId })
    .update({
      name: name,
      updated_at: new Date()
    })
    .returning('*');

  return updated;
}
```

### Why Ltree Paths Do Not Change on Rename

The ltree path trigger (from BE-002) constructs paths using UUID segments, not folder names: `path = replace(project_id::text, '-', '_') || '.' || replace(folder_id::text, '-', '_')`. Since the folder's UUID does not change when it is renamed, the ltree path remains the same. No descendant path updates are needed.

This is a deliberate design decision from BE-002. If paths used folder names (e.g., `project.Raw_Data.2024`), every rename would require updating the path of every descendant — an expensive recursive operation. UUID-based paths avoid this entirely.

### Duplicate Check Specifics

The duplicate check uses a manual query rather than relying solely on the UNIQUE constraint `(project_id, parent_folder_id, name)` because:

1. The UNIQUE constraint catches duplicates at the database level but returns a generic PostgreSQL error code (`23505`). The manual check provides a more descriptive error message.
2. For root-level folders where `parent_folder_id IS NULL`, PostgreSQL's UNIQUE constraint treats each NULL as distinct (per SQL standard). This means two root-level folders with the same name would NOT violate the UNIQUE constraint. The manual check explicitly handles this with `WHERE parent_folder_id IS NULL`:

```typescript
// Special handling for root folders (parent_folder_id is NULL)
const duplicateQuery = this.knex('folders')
  .where({ project_id: projectId, name: name })
  .whereNot({ id: folderId });

if (folder.parent_folder_id === null) {
  duplicateQuery.whereNull('parent_folder_id');
} else {
  duplicateQuery.where({ parent_folder_id: folder.parent_folder_id });
}

const duplicate = await duplicateQuery.first();
```


The `path` field is unchanged (UUID-based, not name-based). The `updatedAt` field reflects the rename timestamp.

## Edge Cases

### Renaming to the Same Name

If the user submits the same name the folder already has (after trimming), the update still executes (it's a no-op at the database level since the value is identical). The `updated_at` timestamp is updated. The frontend handles the "unchanged name" case by cancelling the rename without making an API call (FE-019), so this scenario should be rare but is handled gracefully.

### Concurrent Renames

Two concurrent rename requests for the same folder both pass the duplicate check but one will succeed and one will receive stale data. This is acceptable for the Foundry Speedrun context. For production systems, an optimistic concurrency control mechanism (e.g., `If-Match` header with row version) would be needed.

## Acceptance Criteria

- PUT /api/v1/projects/:projectId/folders/:folderId with `{ name: "New Name" }` renames the folder and returns 200 with the updated folder object
- Empty name (after trim) returns 400 with 'Folder name is required'
- Name exceeding 255 characters returns 400 with 'Folder name must be 255 characters or fewer'
- Name containing `/` returns 400 with validation error about path separators
- Name containing `\` returns 400 with validation error about path separators
- Duplicate name within the same parent returns 409 with 'A folder with this name already exists in this location'
- Duplicate name check works correctly for root-level folders (parent_folder_id IS NULL)
- Non-existent folderId returns 404
- Folder belonging to a different project returns 403
- Leading and trailing whitespace is trimmed from the name before validation and storage
- The folder's ltree path is unchanged after rename (UUID-based paths are name-independent)
- Descendant folders' paths are unchanged after rename
- The `updatedAt` field in the response reflects the rename timestamp
- Response field names use camelCase
