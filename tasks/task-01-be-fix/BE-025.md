## BE-025: Implement User Preferences API for Keyboard Shortcut Configuration

**Palantir Feature:** User Personalization — Per-user preference storage enabling custom keyboard shortcuts and other UI settings.

### Objective

Create a user preferences system that allows FE-025 to persist custom keyboard shortcut bindings per user. When a user remaps `Mod+K` to open search (instead of the default `Mod+/`), that binding must persist across browser sessions and devices. This task builds the database table, CRUD API endpoints, and default-value fallback logic. The API is generic enough to support future preference keys beyond keyboard shortcuts (e.g., theme, sidebar collapsed state, default sort order).

### Implementation

**Database Migration**

Create a new Knex migration file `src/migrations/XXXXXX_create_user_preferences.ts`:

```typescript
export async function up(knex: Knex): Promise<void> {
  await knex.schema.createTable('user_preferences', (table) => {
    table.uuid('id').primary().defaultTo(knex.raw('gen_random_uuid()'));
    table.uuid('user_id').notNullable().references('id').inTable('users').onDelete('CASCADE');
    table.varchar('preference_key', 100).notNullable();
    table.jsonb('preference_value').notNullable();
    table.timestamps(true, true); // created_at, updated_at

    table.unique(['user_id', 'preference_key']);
    table.index('user_id');
  });
}

export async function down(knex: Knex): Promise<void> {
  await knex.schema.dropTableIfExists('user_preferences');
}
```

The `UNIQUE(user_id, preference_key)` constraint ensures each user can have at most one value per preference key. The `JSONB` column type allows flexible value shapes — keyboard shortcuts are stored as an object, theme preference as a string, sidebar state as a boolean.

**Default Preferences**

Define default values in `src/config/defaultPreferences.ts`:

```typescript
export const DEFAULT_PREFERENCES: Record<string, any> = {
  keyboard_shortcuts: {
    search: 'mod+k',
    upload: 'mod+u',
    new_project: 'mod+shift+p',
    new_folder: 'mod+shift+f',
    delete: 'del',
    rename: 'f2',
    navigate_up: 'alt+ArrowUp',
    select_all: 'mod+a',
    help: 'shift+?'
  },
  theme: 'system',
  sidebar_collapsed: false,
  default_sort: { field: 'updated_at', order: 'desc' }
};
```

When a user requests a preference key that has no stored row, the API returns the default value. Defaults are never written to the database — they exist only in application code. This keeps the database lean and allows defaults to evolve with application updates without requiring data migrations.

**API Endpoints**

`GET /api/users/me/preferences`

Returns all preferences for the authenticated user. Merges stored values with defaults so every known key is present in the response:

```typescript
async getAllPreferences(userId: string): Promise<Record<string, any>> {
  const stored = await this.knex('user_preferences')
    .where({ user_id: userId })
    .select('preference_key', 'preference_value');

  const merged = { ...DEFAULT_PREFERENCES };
  for (const row of stored) {
    merged[row.preference_key] = row.preference_value;
  }
  return merged;
}
```

Response:
```json
{
  "data": {
    "keyboard_shortcuts": { "search": "mod+k", "upload": "mod+u", ... },
    "theme": "system",
    "sidebar_collapsed": false,
    "default_sort": { "field": "updated_at", "order": "desc" }
  }
}
```

`GET /api/users/me/preferences/:key`

Returns a single preference value. If no stored row exists, returns the default. Returns 404 if the key is not a recognized preference key (not in defaults and not stored).

Response:
```json
{
  "data": {
    "key": "keyboard_shortcuts",
    "value": { "search": "mod+k", "upload": "mod+u", ... },
    "isDefault": true
  }
}
```

The `isDefault` boolean tells the frontend whether this is a stored custom value or the application default. FE-025 uses this to show a "Reset to defaults" button when `isDefault` is `false`.

`PUT /api/users/me/preferences/:key`

Creates or updates a preference value using PostgreSQL's `INSERT ... ON CONFLICT ... DO UPDATE` (upsert):

```typescript
async setPreference(userId: string, key: string, value: any): Promise<void> {
  await this.knex('user_preferences')
    .insert({ user_id: userId, preference_key: key, preference_value: JSON.stringify(value) })
    .onConflict(['user_id', 'preference_key'])
    .merge({ preference_value: JSON.stringify(value), updated_at: this.knex.fn.now() });
}
```

Request body:
```json
{
  "value": { "search": "mod+/", "upload": "mod+shift+u" }
}
```

Validate that the request body contains a `value` field. The `value` can be any valid JSON type (object, string, boolean, number). Return 200 with the saved preference.

`DELETE /api/users/me/preferences/:key`

Deletes the stored preference, effectively resetting it to the default value. Returns 204 No Content. Returns 404 if the key has no stored override.

**Validation Schema**

```typescript
const PreferenceValueSchema = z.object({
  value: z.any().refine(val => val !== undefined, { message: 'value is required' })
});

const PreferenceKeySchema = z.object({
  key: z.string().min(1).max(100).regex(/^[a-z][a-z0-9_]*$/, 'Preference key must be lowercase snake_case')
});
```

### Acceptance Criteria

- `user_preferences` table exists with columns: id, user_id, preference_key, preference_value (JSONB), created_at, updated_at
- `UNIQUE(user_id, preference_key)` constraint prevents duplicate keys per user
- `GET /api/users/me/preferences` returns all preferences merged with defaults
- `GET /api/users/me/preferences/keyboard_shortcuts` returns the keyboard shortcuts object with `isDefault: true` when no custom value is stored
- `PUT /api/users/me/preferences/keyboard_shortcuts` with `{ "value": { "search": "mod+/" } }` stores the custom binding
- Subsequent `GET` returns the custom value with `isDefault: false`
- `DELETE /api/users/me/preferences/keyboard_shortcuts` removes the custom value; subsequent `GET` returns the default with `isDefault: true`
- Preference keys must be lowercase snake_case (validated via regex)
- Unknown preference keys (not in defaults and not stored) return 404
- All endpoints require authentication (401 without valid token)
- `ON DELETE CASCADE` on `user_id` removes preferences when the user is deleted
- JSONB column stores any valid JSON value type (object, string, boolean, number)
