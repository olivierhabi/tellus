# T-07 — Unified error envelope + verbose-404 gate

**Status:** DONE 2026-04-30

## Contracts covered

| ID    | Contract |
|-------|----------|
| C-100 | `sanitizeMessage` strips stack frames, absolute paths, IPv4 dotted-quads, and SQL fragments before responses go on the wire |
| C-101 | `formatError` canonicalises legacy codes (`CHART_ERROR`, `VALIDATION_FAILED`, `NOT_FOUND`, `SQL_ERROR`, `LINK_CYCLE_DETECTED`) and preserves the original semantic via `parameters.subtype` |
| C-102 | `sendError` uses the canonicalised body's `statusCode` (so legacy aliases route to 400 instead of the pre-T-07 silent-500) and threads `requestId` from `res.req.correlationId` |
| C-103 | The legacy `error.{code,message,details,timestamp}` compat shim is preserved so existing FE/CLI consumers keep working through the migration |
| C-104 | `ensureObjectTypeExists` does NOT leak the `api_name` catalog in the 404 body. The verbose hint is gated behind the *dual* condition `NODE_ENV !== "production" AND TELLUS_DEBUG_404 === "true"` so staging (which often runs as production) keeps the production-shape behavior |

## Decisions

- **Decision (D-2026-04-30-005):** Vocabulary unification is implemented as a *response-boundary alias* (`CANONICAL_ERROR_ALIAS` in `responseFormatter.ts`) rather than a hard global rename of every `appError("VALIDATION_FAILED", ...)` call site. The strictest plausible interpretation per the Decision Protocol balances three forces: (a) the canonical wire format must be unified (DoD), (b) ~150 throw-sites use `VALIDATION_FAILED` and a synchronous global rename risks subtle behavior changes (audit dashboards, monitoring rules), (c) the legacy `error.code` shim is documented to remain for backward compat. The chosen design unifies on the wire while leaving the throw sites for incremental migration; the legacy semantic is preserved via `parameters.subtype` so monitoring keyed on the legacy code can be migrated without losing information.

## Files changed

- `src/utils/responseFormatter.ts`
  - Added `sanitizeMessage(msg)` — defense-in-depth scrubber for stack frames, paths, IPs, SQL fragments.
  - Added `CANONICAL_ERROR_ALIAS` map: `CHART_ERROR → VALIDATION_ERROR`, `VALIDATION_FAILED → VALIDATION_ERROR`, `NOT_FOUND → OBJECT_NOT_FOUND`, `SQL_ERROR → SQL_EXECUTION_ERROR`, `LINK_CYCLE_DETECTED → VALIDATION_ERROR`.
  - `formatError` now canonicalises the code, sanitises the message, and folds the original code into `parameters.subtype` when an alias was triggered.
  - `sendError` now derives the HTTP status from the canonicalised body (so `CHART_ERROR` returns 400 instead of the pre-T-07 silent 500).
- `src/routes/charts.ts` — every direct `res.status(400).json({success:false, error:{...}})` replaced with `sendError(res, ...)`. Callers still pass the legacy `CHART_ERROR` string; the response-boundary alias canonicalises it on the wire.
- `src/routes/objects.ts`
  - `ensureObjectTypeExists` rewritten: the catalog query is now ONLY issued when both env-gates are open. The default-production path returns a terse `Object type not found.` with `details.objectType` for log correlation.
  - `handleError` now routes through `sendError` (was a hand-rolled non-canonical envelope) and accepts both `err.details` and `err.parameters` so legacy and new throw shapes both populate the structured envelope.
  - Added `__internals = { ensureObjectTypeExists }` testing seam.
- `tests/unit/object-explorer/responseFormatter-T07-unit.test.ts` — 18 tests across C-100..C-103.
- `tests/unit/object-explorer/verbose404-gate-unit.test.ts` — 5 tests across C-104, including the production+debug=true case (still terse, gated by `NODE_ENV`) which is the staging-failure mode.

## Rubric items satisfied

- **Input validation** — page validation already covered in T-09; T-07 adds *defensive output validation* (sanitizeMessage) so a leaky third-party lib message cannot exfiltrate filesystem layout, internal IPs, or SQL fragments via a 4xx response.
- **Structured logs / RED metrics** — `requestId` is now reliably present on every error envelope (was missing on charts.ts non-canonical responses pre-T-07).
- **Auditability** — the legacy semantic is preserved as `parameters.subtype` on aliased codes, so an audit log filtering on the legacy code can be migrated incrementally without losing the dimension.
- **Security boundary preservation** — H-9 catalog leak closed. The dual-gate is testable and tested (C-104a..d).
- **Reversibility** — no schema changes. The alias map is a single edit point that can be removed once all throw-sites are migrated.
