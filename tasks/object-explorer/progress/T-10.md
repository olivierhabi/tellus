# T-10 — Observability uniformity + AST contract guard

## Contracts touched
- C-400: every object-explorer route emits canonical RED metrics (`tellus_route_duration_seconds{route,method,status_class}` + `tellus_route_total{route,method,status_class}`) with bounded label cardinality.
- C-401: every object-explorer read endpoint records the resolved branch slot via `tellus_read_branch_filtered_total{route,branch_class}` (`branch_class ∈ {main, branch}` — only two values, no raw branchId).
- C-402: structured log on every error response carries `requestId`, `route`, `errorCode`, `statusCode`, `branch_class`, `principalSub`, `durationMs`.
- C-403: AST guard rejects any new `router.<verb>(...)` in `src/routes/` that does not (a) accept `(req, res, next)` and (b) wrap the handler body via `instrumentRoute` from `src/utils/routeInstrumentation.ts`. Exemptions are listed by handler name + reason in `tests/contract/routeContractGuard.test.ts`.
- C-404: AST guard rejects any new `res.status(...).json(...)` outside `responseFormatter.ts` so error envelope drift is mechanically prevented.

## Files changed
- new `src/utils/routeInstrumentation.ts`
  - `instrumentRoute(routeKey, branchKey, handler)` wraps `(req,res,next)`-shape handlers. Captures `start = process.hrtime.bigint()`, runs the handler, on `res.on('finish')` emits `incCounter("tellus_route_total", { route, method, status_class })` and `observeHistogram("tellus_route_duration_seconds", { route, method, status_class }, durationSec)`. `status_class` is bucketed to `2xx|3xx|4xx|5xx` so cardinality is bounded.
  - `recordBranchRead(req, route)` reads `readBranchHeader(req)`, classifies `_main → "main"` else `"branch"`, and emits `incCounter("tellus_read_branch_filtered_total", { route, branch_class })`. Returns the resolved branchId so the call site can thread it.
- modified `src/routes/{objects,objectViews,charts,sql,summary,comparisons,explorations,favorites,exports}.ts`
  - Every read handler now wraps in `instrumentRoute("<route-key>", "<branch-key>", async (req,res,next) => { … })`. `<route-key>` matches the OpenAPI operationId where one exists (e.g. `objects.searchByApiName`, `summary.byApiName`, `objectViews.batch`).
  - Every read handler that previously emitted `tellus_read_branch_filtered_total` inline now calls `recordBranchRead(req, route)` so the counter shape is centralized; old inline call sites removed.
- new `tests/contract/routeContractGuard.test.ts`
  - Walks `src/routes/*.ts` via the TypeScript compiler API (no extra dep — see D-2026-04-30-010), enumerates every `router.<verb>(...)` call, and checks: (a) the handler is `instrumentRoute(...)` or listed in `EXEMPT_REASONS` with a justification string, (b) no `res.status(...).json(...)` calls live in route files outside `EXEMPT_RESPOND_DIRECT` (see exemption table below).
- modified `vitest.unit.config.ts` to include `tests/contract/**/*.test.ts` in the unit project.
- new `tests/unit/object-explorer/routeInstrumentation-T10-unit.test.ts`
  - Verifies counter increments per status class, histogram observation, branch_class bucketing, that `recordBranchRead` reads from `readBranchHeader`, and that the wrapper is exception-safe (a thrown handler still records the resulting `5xx`).
- new `decisions/object-explorer/D-2026-04-30-010-ts-compiler-api-vs-ts-morph.md`

## Decisions
- **D-2026-04-30-010** — use the bundled TypeScript compiler API (`ts.createSourceFile` + AST walk) instead of adding `ts-morph`. Zero new dependency, no version-pin risk in FedRAMP audit, and the AST surface we need (CallExpression / PropertyAccessExpression / Identifier) is stable across TypeScript versions ≥4.
