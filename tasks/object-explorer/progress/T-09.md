# T-09 — Search-around / Full-text / Page-cap correctness

**Status:** DONE 2026-04-30

## Contracts covered

| ID    | Contract |
|-------|----------|
| C-150 | `resolveMultiHop` accumulates visited PKs across all hops; cycles cannot revisit |
| C-151 | Accumulated `visitedPKs.size > MULTI_HOP_MAX_INTERMEDIATE` (100_000) → loud `SEARCH_AROUND_LIMIT_EXCEEDED` |
| C-152 | Per-hop frontier fans out via `Promise.all` chunks of `MULTI_HOP_CONCURRENCY` (=50); 1000-PK frontier never exceeds 50 in-flight |
| C-153 | `executeFullTextSearch` detects spec syntax (`AND`, `OR`, `NOT`, `+`, `-`, `"`, `*`, `?`, `~`, `(`, `)`, `:`); only spec-syntax inputs trigger a `query_string` clause |
| C-154 | `query_string` clause hard-sets `allow_leading_wildcard: false` |
| C-155 | `query_string` clause hard-sets `lenient: true` |
| C-156 | `$pageSize > MAX_PAGE_SIZE` → `PAGE_SIZE_OUT_OF_RANGE` (HTTP 400, structured envelope), and `from + size > MAX_FROM_PLUS_SIZE` → `PAGE_DEPTH_EXCEEDED` |

## Decisions

- **D-2026-04-30-004** — `MAX_PAGE_SIZE = 10_000`, `MAX_FROM_PLUS_SIZE = 20_000`. Aligned with default OpenSearch `index.max_result_window=10000`. Loud-fail at the validator boundary preserves the strictest plausible interpretation per the Decision Protocol.

## Rubric items satisfied

- **Input validation** — page-size cap is enforced at the validator, not at the OS boundary. Loud-fail with structured envelope.
- **Bounded fan-out** — chunked `Promise.all` with `MULTI_HOP_CONCURRENCY=50` prevents shard saturation.
- **Bounded memory** — `MULTI_HOP_MAX_INTERMEDIATE=100_000` cap on accumulated visited PKs prevents OOM on dense graphs.
- **RED metrics** — `tellus_full_text_spec_syntax_total`, `tellus_search_around_visited_pks`, `tellus_search_around_hops`, `tellus_search_around_total` with bounded label cardinality.
- **Cycle correctness** — accumulated `visitedPKs` set means A↔B cycles short-circuit on hop 2 instead of looping for 5 hops.
- **No silent truncation** — pre-T-09 over-the-cap searches silently sliced; now they throw `SEARCH_AROUND_LIMIT_EXCEEDED` with the violating count, limit, and hop number in the error envelope.
