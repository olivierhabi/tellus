# BE-009: Implement Dataset Rename, Move, Duplicate, and Metadata Update API

**Palantir Feature:** Data Ingestion — Dataset Resource Management (rename, move, duplicate, update metadata)

## Objective

Build endpoints for updating dataset metadata (name, description, folder) and duplicating datasets. A key architectural insight drives this implementation: logical names are decoupled from physical file paths. The dataset `name` is a user-facing display name stored in the database, while `file_path` uses UUID-prefixed paths (e.g., `a1b2c3d4_orders.csv`). This means rename and move operations are pure database updates with zero file I/O — the physical file never moves on disk.

## Dataset Update Endpoint

`PATCH /api/v1/datasets/:datasetId`

Accepts a partial body with optional fields:

```json
{
  "name": "string (optional, 1-255 chars)",
  "description": "string (optional, max 2000 chars)",
  "folderId": "UUID string (optional, move to different folder)"
}
```

Validate with Zod: at least one field must be provided. Return 400 if body is empty or all fields are undefined.

**Input sanitization rules:**
- Strip leading and trailing whitespace from `name`
- Reject names containing path separators (`/` or `\`) with 400 and message `'Dataset name cannot contain path separators'`
- Reject OS-reserved filenames with 400 and message `'Dataset name uses a reserved word'`. Reserved words list: `CON, PRN, AUX, NUL, COM1, COM2, COM3, COM4, COM5, COM6, COM7, COM8, COM9, LPT1, LPT2, LPT3, LPT4, LPT5, LPT6, LPT7, LPT8, LPT9` (case-insensitive comparison)

**Validation when `folderId` is provided (move operation):**
1. Query the target folder: `SELECT id, project_id FROM folders WHERE id = $1`
2. If not found, return 404 with `'Target folder not found'`
3. Get the dataset's current folder: `SELECT folder_id FROM datasets WHERE id = $1`, then get the project_id from that folder
4. If `targetFolder.project_id !== currentFolder.project_id`, return 400 with `'Cannot move dataset to a folder in a different project'`
5. Check for duplicate name in target folder: `SELECT id FROM datasets WHERE name = $1 AND folder_id = $2 AND id != $3`. Return 409 if duplicate found.

**Dynamic UPDATE building:** Use Knex's `.update()` method with a partial object containing only the provided fields plus `updated_at: knex.fn.now()`. Example: if only `name` is provided, the UPDATE touches only `name` and `updated_at`.

**Audit logging:** After every successful mutation, log a structured entry. If BE-024 (Winston) is already implemented, use `logInfo()`. Otherwise, use `console.log()` with a `// TODO: replace with Winston logger (BE-024)` comment. Log payload: `{ action: 'dataset.updated', actorId: req.user.id, datasetId, changes: { before: { name: oldName, folderId: oldFolderId }, after: { name: newName, folderId: newFolderId } } }`. This is application-level logging, not a separate database table.

Return 200 with the updated dataset object.

## Dataset Duplication Endpoint

`POST /api/v1/datasets/:datasetId/duplicate`

Creates a complete copy of a dataset including its physical file and all column metadata.

1. Get the source dataset: `SELECT * FROM datasets WHERE id = $1`. Return 404 if not found. If source dataset status is `pending` or `processing`, return 409 with `'Cannot duplicate a dataset that is still being processed. Wait until status is ready.'`.
2. Copy the physical file: `fs.promises.copyFile(sourceDataset.file_path, newFilePath)` where `newFilePath = path.join(path.dirname(sourceDataset.file_path), uuidv4() + '_' + sourceDataset.original_filename)`
3. In a Knex transaction:
   a. Insert new dataset record with `name: sourceDataset.name + ' (copy)'`, `file_path: newFilePath`, and all other fields copied from the source
   b. Copy all dataset_columns rows: `INSERT INTO dataset_columns (dataset_id, column_name, column_type, ordinal_position, nullable, sample_values) SELECT $newDatasetId, column_name, column_type, ordinal_position, nullable, sample_values FROM dataset_columns WHERE dataset_id = $sourceDatasetId`
4. If the transaction fails after the file was copied, delete the copied file in a catch block
5. Return 201 with the newly created dataset object

## Acceptance Criteria

- PATCH with only name updates only name and updated_at in DB (no file I/O)
- PATCH with only folderId moves dataset to new folder (no file I/O)
- PATCH with name + folderId updates both in a single query
- PATCH with empty body returns 400
- PATCH with name containing `/` or `\` returns 400
- PATCH with reserved word name (e.g., "CON", "nul") returns 400 (case-insensitive). Reserved words are rejected regardless of OS to ensure portability if files are ever exported to Windows environments.
- PATCH with only description updates only description and updated_at in DB
- POST duplicate returns 409 if source dataset status is 'pending' or 'processing'
- PATCH moving dataset to folder in different project returns 400
- PATCH with duplicate name in target folder returns 409
- PATCH returns 404 for non-existent dataset
- POST duplicate creates new file on disk with UUID-prefixed name
- POST duplicate creates new DB record with " (copy)" suffix appended to name
- POST duplicate copies all dataset_columns rows to the new dataset
- POST duplicate cleans up copied file if DB transaction fails
- POST duplicate returns 201 with the new dataset object
- Audit log entry is written for every successful PATCH mutation
- PATCH returns 400 for malformed UUID
