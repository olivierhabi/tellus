## Project Initialization and Dependencies

Create a new directory named foundry-backend. Initialize it with npm init -y. Set type to commonjs in package.json because TypeScript will compile to CommonJS modules. Install production dependencies: express (v4.18+, the HTTP server framework - we use Express 4 rather than 5 because Express 5 is still in beta and many middleware packages do not yet support it), cors (enables Cross-Origin Resource Sharing so the Next.js frontend running on port 3000 can make API requests to the backend running on port 3001 - without this, all frontend requests would be blocked by the browser same-origin policy), helmet (sets security-related HTTP response headers including Content-Security-Policy, X-Content-Type-Options: nosniff, and disables X-Powered-By which leaks server technology), morgan (HTTP request logger that outputs formatted request logs to stdout), multer (middleware for handling multipart/form-data file uploads), pg (PostgreSQL client for Node.js - the low-level driver that Knex uses internally), knex (SQL query builder and migration toolkit - chosen over full ORMs like Prisma or TypeORM because Palantir ontology layer requires dynamic schema manipulation that ORMs handle poorly), dotenv (loads environment variables from .env file), zod (TypeScript-first schema validation with native type inference - when you define a Zod schema you automatically get the corresponding TypeScript type eliminating duplicate definitions), uuid (generates RFC4122 v4 UUIDs for file naming). Install development dependencies: typescript (v5.3+), ts-node-dev (development server with hot reloading), @types/express, @types/cors, @types/multer, @types/morgan, @types/pg, @types/uuid, @types/node, eslint, @typescript-eslint/parser, @typescript-eslint/eslint-plugin, tsconfig-paths (resolves path aliases at runtime). Add npm scripts: dev (ts-node-dev --respawn --transpile-only -r tsconfig-paths/register src/index.ts - the --respawn flag restarts on crash, --transpile-only skips type checking for fast reloads), build (tsc), start (node -r tsconfig-paths/register dist/index.js — the tsconfig-paths/register flag is required at runtime because compiled JS still contains path alias imports like @/ which Node.js cannot resolve natively), lint (eslint src/ --ext .ts), migrate (knex migrate:latest), migrate:rollback (knex migrate:rollback), seed (knex seed:run).

## TypeScript Configuration

Create tsconfig.json with these compiler options and understand the purpose of each: target ES2020 (supports optional chaining, nullish coalescing, Promise.allSettled; Node 18+ fully supports ES2020), module commonjs (CommonJS loader is more reliable for server-side than ESM, especially with dynamic imports and third-party packages), lib [ES2020], outDir ./dist (compiled JS goes here, must be in .gitignore), rootDir ./src, strict true (enables all strict checks: strictNullChecks prevents null reference errors, noImplicitAny forces explicit types, strictFunctionTypes enforces correct function parameter types, strictPropertyInitialization forces class property initialization), esModuleInterop true (allows import express from 'express' instead of import * as express), skipLibCheck true (faster compilation), forceConsistentCasingInFileNames true (prevents case-insensitive filesystem bugs), resolveJsonModule true, declaration true, declarationMap true, sourceMap true (stack traces show TypeScript line numbers). Configure path aliases: '@/*' maps to 'src/*'. This means import { AppError } from '@/utils/AppError' resolves to src/utils/AppError.ts. Path aliases prevent deep relative import chains and must be used consistently across all tasks.

## Folder Structure

Create the following directory tree under src/: src/config/ contains database.ts (Knex connection pool configured from DATABASE_URL, min 2, max 10 connections), environment.ts (Zod validation of all env vars), knexfile.ts (migration settings for dev/test/prod). src/controllers/ contains request/response handling - controllers parse HTTP input, call services, format output, never contain business logic or direct DB queries. src/services/ contains business logic and database queries - the only layer that imports database config and executes SQL, accepts Knex instances via constructor injection for testability. src/models/ contains TypeScript interfaces for database entities (pure types, not ORM models). src/middleware/ contains errorHandler.ts (global 4-parameter Express error handler), requestLogger.ts (logs method, URL, status, duration), correlationId.ts (generates unique request ID). src/routes/ contains health.ts and router files for each resource. src/types/ contains Zod schemas and TypeScript type definitions per resource. src/utils/ contains AppError.ts (custom error class with statusCode, code, isOperational), response.ts (response formatting helpers), fileCleanup.ts (file deletion utility). src/migrations/ for Knex migration files. src/seeds/ for development data. src/jobs/ for background job definitions. src/websocket/ for WebSocket server and EventBus.

## ESLint Configuration

Create `.eslintrc.js` at the project root with the following configuration: extend `@typescript-eslint/recommended`, set parser to `@typescript-eslint/parser` with `parserOptions.project` pointing to `./tsconfig.json`. Rules: `@typescript-eslint/no-unused-vars` set to `error` (with `argsIgnorePattern: '^_'` to allow unused parameters prefixed with underscore — needed for Express error handler's 4-parameter signature), `@typescript-eslint/no-explicit-any` set to `warn`, `@typescript-eslint/explicit-function-return-type` set to `off` (TypeScript infers return types adequately for this project). Include `src/` in the lint scope and exclude `dist/`, `node_modules/`, and `coverage/`. This configuration ensures the `npm run lint` acceptance criterion is verifiable against a concrete rule set.

## Entry Point Implementation

Create src/index.ts performing operations in strict order: (1) Import and call dotenv.config() FIRST - this must be the very first operation so subsequent imports can access env vars. (2) Import and run environment validation from config/environment.ts - Zod validates all required variables, exit with code 1 if validation fails with specific error details on stderr. This fail-fast behavior prevents cryptic runtime errors from misconfigured variables. (3) Import express and create app instance. (4) Apply middleware in correct order (order matters because Express processes sequentially): helmet() first (security headers before any response), cors({origin: FRONTEND_URL, credentials: true}) second (CORS headers for preflight requests), express.json({limit: '10mb'}) third (JSON body parsing), morgan(NODE_ENV === 'production' ? 'combined' : 'dev') fourth (request logging). (5) Register health route at /health (before auth middleware added in BE-013). (6) Register global error handler LAST (Express identifies error handlers by 4-parameter signature). (7) Create HTTP server explicitly via http.createServer(app) - required because BE-012 will attach WebSocket server to same HTTP server. (8) Listen on PORT with error handling.

## Environment Validation

Create src/config/environment.ts with Zod schema validating: DATABASE_URL (z.string().startsWith('postgresql://') - reject non-PG URLs), PORT (z.coerce.number().int().min(1024).max(65535).default(3001) - coerce converts string from process.env to number), NODE_ENV (z.enum(['development','production','test']).default('development')), UPLOAD_DIR (z.string().default('./uploads')), MAX_FILE_SIZE_MB (z.coerce.number().min(1).max(500).default(50)), FRONTEND_URL (z.string().url().default('http://localhost:3000')), JWT_SECRET (z.string().min(32) - minimum 32 chars for security). Export validated config AND inferred type: export type EnvConfig = z.infer<typeof envSchema>.

## Error Handling

Create src/utils/AppError.ts extending Error with: statusCode (number, the HTTP status), code (string like NOT_FOUND, VALIDATION_ERROR, CONFLICT), isOperational (boolean - true for expected errors safe to expose, false for bugs showing only generic message in production). Create src/middleware/errorHandler.ts: 4-parameter function (err, req, res, next). If AppError and isOperational: send statusCode with {error: {code, message}}. If non-operational in development: send full stack trace. In production: send generic {error: {code: 'INTERNAL_ERROR', message: 'An unexpected error occurred'}}. Always log full error to stderr.

## Acceptance Criteria

- Running npm run dev starts server on port 3001 with startup log message
- GET /health returns 200 with {status: 'ok', timestamp, uptime}
- Server rejects malformed JSON bodies with 400 error and response body `{error: {code: 'VALIDATION_ERROR', message: <descriptive message>}}`
- Missing DATABASE_URL causes process.exit(1) with descriptive Zod error
- npm run build compiles to dist/ with zero errors
- npm run lint passes with zero warnings
- .env.example documents all 7 environment variables with example values: DATABASE_URL=postgresql://user:pass@localhost:5432/foundry, PORT=3001, NODE_ENV=development, UPLOAD_DIR=./uploads, MAX_FILE_SIZE_MB=50, FRONTEND_URL=http://localhost:3000, JWT_SECRET=your-secret-key-at-least-32-characters-long
- .gitignore excludes node_modules, dist, .env, uploads/, *.log, coverage/
- Folder structure matches specification exactly
- Path aliases resolve correctly at compile time and runtime
