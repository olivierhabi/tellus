# BE-017: Implement Advanced Dataset Preview with Filtering and Sampling

**Palantir Feature:** Data Ingestion — Foundry dataset preview capabilities (column selection, sampling, sorting, filtering)

## Objective

Enhance the existing `GET /api/datasets/:datasetId/preview` endpoint (from BE-007) to support column selection, multiple sampling modes (first/random/last), type-aware sorting, and multi-filter support. When no new query parameters are provided, the endpoint behaves identically to the BE-007 implementation (returns first 50 rows).

## Parameter Processing Order

When multiple parameters are combined, they are applied in this strict order:

1. **Filter** rows from the CSV stream
2. **Sort** the filtered rows (loads into memory, capped at 10,000 rows)
3. **Sample** from the sorted/filtered rows
4. **Select** requested columns from the sampled rows

This order ensures filtering reduces the dataset before sorting (performance), and column selection happens last (preserves all columns for filter/sort operations).

## Query Parameters

All validated with Zod:

```typescript
const PreviewQuerySchema = z.object({
  rows: z.coerce.number().int().min(1).max(1000).default(50),
  columns: z.string().optional(), // comma-separated column names
  sample: z.enum(['first', 'random', 'last']).default('first'),
  sortBy: z.string().optional(),
  sortOrder: z.enum(['asc', 'desc']).default('asc'),
  filter: z.union([z.string(), z.array(z.string())]).optional(),
  offset: z.coerce.number().int().min(0).default(0)
});
```

## Column Selection

`?columns=order_id,amount,status`

1. Parse the CSV header row first.
2. Validate that all requested column names exist in the header. Return 400 with `'Unknown column: <name>. Available columns: <list>'` if any are invalid.
3. After all other processing, strip non-requested columns from each row before returning.

## Sampling Modes

### `?sample=first` (default — preserves BE-007 behavior)
Read the CSV file from the beginning, collect the first N rows after applying filters. Use stream destruction (from BE-007) to stop reading after enough rows are collected.

### `?sample=random` (Algorithm R — Reservoir Sampling)
Perform a single-pass reservoir sampling to select N rows uniformly at random from the filtered rows:

```typescript
const reservoir: Record<string, string>[] = [];
let count = 0;

for (const row of filteredRows) {
  count++;
  if (count <= N) {
    reservoir.push(row);
  } else {
    const j = Math.floor(Math.random() * count);
    if (j < N) {
      reservoir[j] = row;
    }
  }
}
```

This guarantees each row has an equal probability of being selected, regardless of file order.

### `?sample=last`
Count total lines in the file first using a byte-counting approach (count newline characters in a read stream), then seek to `totalLines - N` using the csv-parse `from_line` option:

```typescript
const parser = parse({ columns: true, from_line: Math.max(1, totalLines - N), ... });
```

This avoids reading the entire file into memory.

## Type-Aware Sorting

`?sortBy=amount&sortOrder=desc`

1. Validate that `sortBy` column exists in the CSV header. Return 400 if not.
2. Collect all filtered rows into memory (capped at 10,000 rows). If more than 10,000 rows match the filters, sort only the first 10,000 and include a warning in the response metadata: `{ warning: 'Sort applied to first 10,000 matching rows only. Use filters to narrow the dataset.' }`.
3. Look up the column's inferred type from `dataset_columns.column_type` for the sort comparator:
   - `integer`, `numeric` → numeric comparison: `parseFloat(a) - parseFloat(b)`
   - `date`, `timestamp` → chronological comparison: `new Date(a).getTime() - new Date(b).getTime()`
   - `text`, `boolean`, or unknown → lexicographic comparison: `a.localeCompare(b)`
4. Sort in the requested order (`asc` or `desc`).

## Filter Syntax

`?filter=amount:gt:100&filter=status:eq:shipped`

Each filter is a colon-separated triple: `column:operator:value`. Multiple filters are combined with AND logic (all must match for a row to be included).

Supported operators:

| Operator | Meaning | Type Coercion |
|----------|---------|---------------|
| `eq` | Equals | Case-insensitive string comparison |
| `neq` | Not equals | Case-insensitive string comparison |
| `contains` | Substring match | Case-insensitive `value.includes(filterValue)` |
| `gt` | Greater than | Coerced to column's inferred type (see below) |
| `lt` | Less than | Coerced to column's inferred type |
| `gte` | Greater than or equal | Coerced to column's inferred type |
| `lte` | Less than or equal | Coerced to column's inferred type |
| `isNull` | Value is null/empty | No value needed: `?filter=col:isNull` |
| `isNotNull` | Value is not null/empty | No value needed: `?filter=col:isNotNull` |

**Type coercion for comparison operators (gt, lt, gte, lte):**
- Columns with inferred type `integer` or `numeric` → `parseFloat(value)` for both the row value and filter value, then numeric comparison
- Columns with inferred type `date` or `timestamp` → `new Date(value).getTime()` for chronological comparison
- All other types → lexicographic string comparison via `localeCompare()`

**Validation:**
- Return 400 if filter column does not exist: `'Unknown filter column: <name>'`
- Return 400 if filter operator is not in the supported list: `'Unknown filter operator: <op>'`
- Return 400 if filter string is malformed (not enough colon-separated parts)

## Response Shape

```json
{
  "datasetId": "uuid",
  "rows": [{ "order_id": "...", "amount": "..." }],
  "metadata": {
    "totalRows": 50000,
    "returnedRows": 50,

    "appliedSort": { "column": "amount", "order": "desc" },
    "sampleMode": "first",
    "warning": null
  }

```

## Backward Compatibility

When no new query parameters are provided (no `columns`, `sample`, `sortBy`, `filter`), the endpoint behaves identically to BE-007: returns the first 50 rows of the CSV file with stream destruction. The response shape adds the `metadata` wrapper, but the `rows` array content is identical.

## Acceptance Criteria

- `?columns=col1,col2` returns only col1 and col2 in each row
- `?columns=nonexistent` returns 400 with list of available columns
- `?sample=first` returns the first N rows (default behavior, matches BE-007)
- `?sample=random` returns N rows uniformly distributed across the file (verified statistically over multiple calls)
- `?sample=last` returns the last N rows of the file
- `?sortBy=numericCol&sortOrder=asc` sorts numerically (1, 2, 10, not 1, 10, 2)
- `?sortBy=textCol` sorts lexicographically
- `?sortBy=dateCol` sorts chronologically
- `?sortBy=nonexistent` returns 400
- `?filter=col:eq:value` returns only matching rows (case-insensitive)
- `?filter=col:gt:100` compares numerically for numeric columns
- `?filter=col:isNull` returns only rows where col is null/empty
- `?filter=col:isNotNull` returns only rows where col has a value
- Multiple filters combined with AND logic: `?filter=a:gt:10&filter=b:eq:x` returns rows matching both
- `?filter=col:invalid:value` returns 400 with 'Unknown filter operator'
- `?filter=nonexistent:eq:value` returns 400 with 'Unknown filter column'
- Response metadata includes totalRows, returnedRows, columns, appliedFilters, appliedSort, sampleMode
- Sort with more than 10,000 matching rows returns first 10,000 sorted with warning in metadata
- No query parameters returns first 50 rows (BE-007 backward compatibility)
- Preview still returns 409 for datasets with status not 'ready'

## Dependencies

BE-006 (csvParsingService, column type inference in dataset_columns), BE-007 (existing preview endpoint to enhance, stream destruction pattern)
