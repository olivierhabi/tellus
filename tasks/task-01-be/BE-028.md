# BE-028: Implement Duplicate File Detection via Content Hashing

**Palantir Feature:** Data Ingestion — Preventing duplicate uploads (SHA-256 content hashing with duplicate warnings and deduplication)

## Objective

Compute SHA-256 hashes of uploaded files, store the hash in the existing `datasets.content_hash` column (already defined in BE-002 with an index), detect duplicates during upload and include a warning in the response, expose an endpoint to list duplicate groups per project, and provide a deduplication endpoint that removes the newer duplicate while keeping the oldest (original) dataset.

## Hash Computation During Upload

Modify `src/services/uploadService.ts` `processUpload()` to compute the SHA-256 hash after content detection (BE-027) but before the database INSERT:

```typescript
import crypto from 'crypto';

async function computeFileHash(filePath: string): Promise<string> {
  return new Promise((resolve, reject) => {
    const hash = crypto.createHash('sha256');
    const stream = fs.createReadStream(filePath);
    stream.on('data', (chunk) => hash.update(chunk));
    stream.on('end', () => resolve(hash.digest('hex')));
    stream.on('error', reject);
  });
}
```

After computing the hash, check for existing duplicates within the same project:

```sql
SELECT d.id, d.name, d.folder_id, f.name AS folder_name, d.created_at
FROM datasets d
JOIN folders f ON f.id = d.folder_id
WHERE d.content_hash = $1
  AND f.project_id = $2
LIMIT 1
```

If a duplicate is found, include a warning in the upload response but **proceed with the upload** (the frontend decides whether to prompt the user):

```json
{
  "success": true,
  "data": [{
    "id": "new-dataset-uuid",
    "name": "orders.csv",
    "warning": {
      "code": "DUPLICATE_DETECTED",
      "message": "This file is identical to an existing dataset",
      "existingDataset": {
        "id": "existing-uuid",
        "name": "orders.csv",
        "folderId": "folder-uuid",
        "folderName": "data",
        "uploadedAt": "2024-03-15T10:00:00Z"
      }
    }
  }]
}
```

Store the hash in the INSERT: add `content_hash: hash` to the dataset INSERT. The `content_hash` column and its index already exist from BE-002.

## Duplicate Listing Endpoint

`GET /api/v1/projects/:projectId/duplicates`

Query datasets grouped by `content_hash` where the group count exceeds 1:

```sql
SELECT d.content_hash, d.id, d.name, d.folder_id, f.name AS folder_name,
       d.file_size_bytes, d.created_at
FROM datasets d
JOIN folders f ON f.id = d.folder_id
WHERE f.project_id = $1
  AND d.content_hash IS NOT NULL
  AND d.content_hash IN (
    SELECT d2.content_hash
    FROM datasets d2
    JOIN folders f2 ON f2.id = d2.folder_id
    WHERE f2.project_id = $1
    GROUP BY d2.content_hash
    HAVING COUNT(*) > 1
  )
ORDER BY d.content_hash, d.created_at ASC
```

Group the results in the service layer and return:

```json
{
  "success": true,
  "data": [
    {
      "contentHash": "a1b2c3d4...",
      "fileSize": 12345,
      "count": 3,
      "datasets": [
        { "id": "uuid1", "name": "orders.csv", "folderId": "f1", "folderName": "data", "uploadedAt": "2024-01-01" },
        { "id": "uuid2", "name": "orders_copy.csv", "folderId": "f2", "folderName": "archive", "uploadedAt": "2024-02-01" },
        { "id": "uuid3", "name": "orders.csv", "folderId": "f1", "folderName": "data", "uploadedAt": "2024-03-01" }
      ]
    }
  ]
}
```

Sort groups by count descending (most duplicates first). Within each group, sort datasets by `created_at ASC` (oldest first — the oldest is considered the "original").

Return 200 with an empty `data` array if no duplicates exist.

## Deduplication Endpoint

`POST /api/v1/datasets/:datasetId/deduplicate`

Removes the specified dataset (the "duplicate") and keeps the oldest dataset with the same `content_hash` in the same project (the "original").

1. Get the dataset to be removed: `SELECT * FROM datasets WHERE id = $1`. Return 404 if not found.
2. Find the original (oldest with same hash in same project):
   ```sql
   SELECT d.id, d.name FROM datasets d
   JOIN folders f ON f.id = d.folder_id
   WHERE d.content_hash = $1
     AND f.project_id = $2
   ORDER BY d.created_at ASC
   LIMIT 1
   ```
3. If the original is the same as the dataset being deduplicated (it IS the oldest), return 409 with `'This is the original dataset. Deduplicate a newer copy instead.'`.
4. If no other dataset shares the hash, return 409 with `'This dataset has no duplicates to resolve.'`.
5. In a Knex transaction:
   a. Delete the duplicate's database record: `DELETE FROM datasets WHERE id = $1`. CASCADE handles `dataset_columns`.
   b. Delete the duplicate's physical file: `fs.promises.unlink(duplicate.file_path).catch(() => {})`.
6. Return 200 with:
   ```json
   {
     "success": true,
     "data": {
       "removed": { "id": "duplicate-uuid", "name": "orders_copy.csv" },
       "keptOriginal": { "id": "original-uuid", "name": "orders.csv" }
     }
   }
   ```

## Acceptance Criteria

- Uploading a file computes and stores its SHA-256 hash in `datasets.content_hash`
- Uploading the same file twice produces a warning on the second upload with the first dataset's details
- Two different files produce different content hashes
- The upload always succeeds even when a duplicate is detected (warning only)
- GET /api/v1/projects/:projectId/duplicates returns groups of datasets with matching hashes
- GET /api/v1/projects/:projectId/duplicates with no duplicates returns empty array
- Duplicate groups are sorted by count descending; datasets within groups are sorted by created_at ASC
- POST /api/v1/datasets/:datasetId/deduplicate removes the specified dataset and its file
- POST /api/v1/datasets/:datasetId/deduplicate returns the removed dataset and the kept original
- POST /api/v1/datasets/:datasetId/deduplicate on the oldest (original) dataset returns 409
- POST /api/v1/datasets/:datasetId/deduplicate on a dataset with no duplicates returns 409
- After deduplication, the removed dataset no longer appears in listing or duplicate queries
- After deduplication, the physical file of the removed dataset no longer exists on disk
- Content hash is computed via streaming (does not load entire file into memory)
