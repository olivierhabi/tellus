# BE-016: Implement ZIP Archive Upload with Extraction

**Palantir Feature:** Data Ingestion — Foundry batch upload capability (uploading multiple files via a single ZIP archive)

## Objective

Extend the existing upload endpoint (from BE-005) to accept `.zip` files in addition to CSV/TSV/TXT files. When a ZIP file is uploaded, extract its contents to a temporary directory, process each valid file (.csv/.tsv/.txt) using the existing upload service logic, create subfolders for nested directories found within the ZIP, and return a structured response indicating which files were created, skipped, or errored. ZIP processing uses partial-success semantics: each file is processed independently, so one file's failure does not prevent others from succeeding.

## ZIP Detection

In `src/config/multer.ts`, update the `fileFilter` to also accept `.zip` files:

```typescript
const allowed = ['.csv', '.tsv', '.txt', '.zip'];
```

After Multer saves the file, the upload controller checks if the uploaded file has a `.zip` extension. If so, it routes to the ZIP processing flow instead of the standard CSV flow.

## ZIP Processing Flow

Create `src/services/zipUploadService.ts`:

```typescript
async processZipUpload(
  zipFilePath: string,
  projectId: string,
  folderId: string,
  ownerId: string
): Promise<ZipUploadResult>
```

### Step 1 — ZIP Bomb Protection

Before extraction, read the ZIP central directory using `adm-zip` (install via `npm install adm-zip` and `npm install --save-dev @types/adm-zip`):

```typescript
const zip = new AdmZip(zipFilePath);
const entries = zip.getEntries();
const totalUncompressedSize = entries.reduce((sum, e) => sum + e.header.size, 0);
if (totalUncompressedSize > 1_073_741_824) { // 1 GB
  throw new AppError(413, `ZIP archive uncompressed size (${formatFileSize(totalUncompressedSize)}) exceeds the 1GB limit`);
}
```

### Step 2 — Path Traversal Protection

Before extracting any entry, validate that the entry name does not escape the temp directory:

```typescript
for (const entry of entries) {
  const resolvedPath = path.resolve(tempDir, entry.entryName);
  if (!resolvedPath.startsWith(path.resolve(tempDir))) {
    throw new AppError(400, `ZIP contains a path traversal attack: ${entry.entryName}`);
  }
}
```

Reject the entire ZIP if any entry attempts path traversal (e.g., `../../etc/passwd`).

### Step 3 — Extraction

Extract to a temporary directory: `const tempDir = path.join(os.tmpdir(), 'foundry-upload-' + uuidv4())`. Use `zip.extractAllTo(tempDir, true)`.

### Step 4 — Walk Extracted Tree

Recursively walk the extracted directory. For each directory encountered, create a corresponding subfolder in the database by calling `folderService.createFolder()`. If a subfolder name already exists under the target parent, reuse the existing folder (catch the 409 error and query for the existing folder ID).

For each file encountered:
1. Check extension: `.csv`, `.tsv`, `.txt` only. Other files go into the `skipped` array with reason `'Unsupported file type: <ext>'`.
2. Copy the file to the proper upload directory: `<UPLOAD_DIR>/<projectId>/<targetFolderId>/<uuid>_<filename>`.
3. Create a dataset record and schedule a parse job using the same logic as `uploadService.processUpload()` but for a single file.
4. If any step fails for this file, add it to the `errors` array and continue with the next file.

### Step 5 — Cleanup

In a `finally` block, delete the temporary directory: `fs.promises.rm(tempDir, { recursive: true, force: true })`. Also delete the original ZIP file from the upload directory (the ZIP itself is not stored as a dataset).

## Response Format

Return 201 with:
```json
{
  "success": true,
  "data": {
    "created": [
      { "id": "uuid", "name": "orders.csv", "fileSize": 12345, "folderId": "uuid", "folderName": "data" }
    ],
    "skipped": [
      { "fileName": "readme.md", "reason": "Unsupported file type: .md" }
    ],
    "errors": [
      { "fileName": "broken.csv", "error": "Failed to create dataset record: duplicate name" }
    ],
    "foldersCreated": [
      { "id": "uuid", "name": "data", "parentFolderId": "uuid" }
    ]
  }
}
```

## Handling Encrypted ZIPs

If `adm-zip` throws an error when reading entries (encrypted ZIPs cannot be read), catch the error and return 400 with `'ZIP archive appears to be encrypted. Please upload an unencrypted ZIP.'`.

## Handling Empty ZIPs

If the ZIP contains no valid files (all skipped or zero entries), return 200 with an empty `created` array. This is not an error.

## Acceptance Criteria

- ZIP file with 3 CSV files creates 3 dataset records and returns 201 with `created` array
- ZIP file with mix of CSV and XLSX files creates datasets for CSVs and returns XLSX in `skipped` array
- ZIP file with nested directories (e.g., `data/sales/orders.csv`) creates corresponding subfolders
- If a nested directory name matches an existing folder, the existing folder is reused (no 409 error)
- ZIP file exceeding 1GB uncompressed size is rejected with 413 before extraction
- ZIP file with path traversal entry (e.g., `../../etc/passwd`) is rejected with 400
- Encrypted ZIP returns 400 with descriptive error
- Empty ZIP (no valid files) returns 200 with empty `created` array
- Temp directory is cleaned up on success (verified: directory no longer exists after response)
- Temp directory is cleaned up on failure (finally block)
- Original ZIP file is deleted from upload directory after processing
- Each created dataset triggers a parse job (status transitions to 'processing' then 'ready')
- One file's failure does not prevent other files from being processed (partial-success)
- Non-ZIP file uploads (.csv, .tsv, .txt) continue to work exactly as before (BE-005 behavior unchanged)

## Dependencies

BE-004 (folderService.createFolder for nested directories), BE-005 (upload endpoint to extend, uploadService.processUpload for single-file logic), BE-006 (CSV parse job scheduling)
