# BE-014: Implement Role-Based Access Control with Project Membership

**Palantir Feature:** Project Access Control — Project membership and role-based permissions (owner/editor/viewer roles, role enforcement on all protected operations)

## Objective

Build a complete role-based access control (RBAC) system for projects. Create a `project_members` table linking users to projects with roles, auto-add the project creator as owner, expose CRUD endpoints for managing project membership, create an `authorize` middleware factory that enforces role requirements on routes, and update existing routes to require appropriate roles. After this task, project access is determined by membership rather than ownership alone.

## Database Schema

Create a new migration file `src/migrations/004_create_project_members.ts`:

**project_members table:**
- `project_id` UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE
- `user_id` UUID NOT NULL REFERENCES users(id) ON DELETE CASCADE
- `role` VARCHAR(20) NOT NULL CHECK(role IN ('owner', 'editor', 'viewer'))
- `created_at` TIMESTAMPTZ DEFAULT NOW()
- PRIMARY KEY (project_id, user_id) — composite key prevents duplicate membership

Add index: `CREATE INDEX idx_project_members_user ON project_members(user_id)` for efficient lookup of all projects a user belongs to.

Migration `down()` drops the index and then the table.

## Auto-Add Creator as Owner

Modify `src/services/projectService.ts` `create()` method to insert a `project_members` row within the same transaction as the project INSERT:

```typescript
return this.knex.transaction(async (trx) => {
  const [project] = await trx('projects').insert({ name, owner_id: userId }).returning('*');
  await trx('project_members').insert({ project_id: project.id, user_id: userId, role: 'owner' });
  return project;
});
```

This ensures every project always has at least one owner from the moment of creation.

## Member Management Endpoints

### Add Member

`POST /api/v1/projects/:projectId/members`

Request body validated with Zod:
```typescript
const AddMemberSchema = z.object({
  userId: z.string().uuid('Invalid user ID format'),
  role: z.enum(['editor', 'viewer'], { message: 'Role must be editor or viewer. Owners can only be set by transferring ownership.' })
});
```

Implementation:
1. Verify the target user exists: `SELECT id FROM users WHERE id = $1`. Return 404 with `'User not found'` if missing.
2. Check for existing membership: `SELECT role FROM project_members WHERE project_id = $1 AND user_id = $2`. Return 409 with `'User is already a member of this project'` if found.
3. Insert: `INSERT INTO project_members (project_id, user_id, role) VALUES ($1, $2, $3) RETURNING *`.
4. Return 201 with `{ projectId, userId, role, createdAt }`.

Only project owners can add members (enforced via `authorize('owner')` on this route).

### Remove Member

`DELETE /api/v1/projects/:projectId/members/:userId`

Implementation:
1. Check if the target member exists: `SELECT role FROM project_members WHERE project_id = $1 AND user_id = $2`. Return 404 with `'Member not found'` if missing.
2. If the target member's role is `'owner'`, count remaining owners: `SELECT COUNT(*) FROM project_members WHERE project_id = $1 AND role = 'owner'`. If count is 1, return 400 with `'Cannot remove the last owner. Transfer ownership first.'`.
3. Prevent self-removal if user is the last owner (same check).
4. Delete: `DELETE FROM project_members WHERE project_id = $1 AND user_id = $2`.
5. Return 204 No Content.

Only project owners can remove members.

### List Members

`GET /api/v1/projects/:projectId/members`

Query:
```sql
SELECT pm.user_id, u.email, u.display_name, pm.role, pm.created_at
FROM project_members pm
JOIN users u ON u.id = pm.user_id
WHERE pm.project_id = $1
ORDER BY pm.role ASC, u.display_name ASC
```

Return 200 with array of member objects. Any project member (including viewers) can list members.

### Update Member Role

`PATCH /api/v1/projects/:projectId/members/:userId`

Request body: `{ role: z.enum(['editor', 'viewer']) }`. Owners cannot be demoted via this endpoint; transferring ownership is a separate concern out of scope for this task.

1. Verify membership exists. Return 404 if not.
2. Verify the target is not an owner: `SELECT role FROM project_members WHERE project_id = $1 AND user_id = $2`. If role is `'owner'`, return 400 with `'Cannot change the role of a project owner'`.
3. Update: `UPDATE project_members SET role = $1 WHERE project_id = $2 AND user_id = $3 RETURNING *`.
4. Return 200 with updated member object.

Only project owners can update roles.

## Authorize Middleware Factory

Create `src/middleware/authorize.ts`:

```typescript
export function authorize(...allowedRoles: string[]) {
  return async (req: Request, res: Response, next: NextFunction) => {
    const userId = req.user.id;
    const projectId = req.params.projectId || req.params.id;

    if (!projectId) {
      return next(new AppError(400, 'Project ID required for authorization'));
    }

    const membership = await db('project_members')
      .where({ project_id: projectId, user_id: userId })
      .first();

    if (!membership) {
      return next(new AppError(403, 'You are not a member of this project'));
    }

    if (!allowedRoles.includes(membership.role)) {
      return next(new AppError(403, `This action requires one of these roles: ${allowedRoles.join(', ')}. Your role: ${membership.role}`));
    }

    req.userRole = membership.role;
    next();
  };
}
```

## Update GET /api/v1/projects

Modify `projectService.listProjects()` to filter by membership instead of owner_id:

```sql
SELECT p.* FROM projects p
INNER JOIN project_members pm ON pm.project_id = p.id
WHERE pm.user_id = $1
ORDER BY p.updated_at DESC
```

This replaces the previous `WHERE owner_id = $1` query, ensuring users see all projects they are members of (not just projects they own).

## Interaction with projects.default_role

The `projects.default_role` column (from BE-002) is informational metadata only — it does NOT auto-assign roles. When the project owner adds a new member via POST, they must explicitly specify the role. The `default_role` field can be used by the frontend to pre-select the role dropdown, but the backend does not use it for automatic role assignment.

## Acceptance Criteria

- POST /api/v1/projects/:id/members with valid userId and role 'editor' returns 201
- POST /api/v1/projects/:id/members with valid userId and role 'viewer' returns 201
- POST /api/v1/projects/:id/members with role 'owner' returns 400 (owners cannot be added via API)
- POST /api/v1/projects/:id/members with duplicate userId returns 409
- POST /api/v1/projects/:id/members with non-existent userId returns 404
- POST /api/v1/projects/:id/members with invalid role returns 400
- POST /api/v1/projects/:id/members by a non-owner returns 403
- DELETE /api/v1/projects/:id/members/:userId removes the member and returns 204
- DELETE /api/v1/projects/:id/members/:userId for the last owner returns 400
- DELETE /api/v1/projects/:id/members/:userId for non-existent member returns 404
- GET /api/v1/projects/:id/members returns all members with user details sorted by role then name
- PATCH /api/v1/projects/:id/members/:userId updates role and returns 200
- PATCH /api/v1/projects/:id/members/:userId on an owner returns 400
- Creating a project auto-adds the creator as 'owner' in project_members (within same transaction)
- authorize('editor', 'owner') middleware returns 403 for 'viewer' role
- authorize('owner') middleware returns 403 for 'editor' and 'viewer' roles
- Non-member accessing any project route returns 403 with 'not a member' message
- GET /api/v1/projects returns only projects where the user is a member (via JOIN)
- Upload/create folder/create dataset require 'editor' or 'owner' role
- Delete project requires 'owner' role
- GET operations on projects/folders/datasets allow 'viewer' role
- Migration down() drops project_members table and its index
