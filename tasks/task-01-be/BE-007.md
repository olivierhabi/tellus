# BE-007: Implement Dataset Listing, Detail, Preview, and Status Polling API

**Palantir Feature:** Data Ingestion — Viewing uploaded datasets and their schemas in Foundry. In the Speedrun course, after uploading CSV files and before opening Pipeline Builder, users can see their datasets listed in the folder view with status indicators, click into a dataset to see its schema (column names and detected types), and preview actual data rows. The Pipeline Builder's "Add Foundry data" step uses these endpoints to let users browse and select datasets.

## Objective

Build four API endpoints that serve as the read layer for the dataset subsystem: a list endpoint for browsing datasets within a folder, a detail endpoint that returns complete schema metadata, a preview endpoint that streams actual CSV rows without loading the full file into memory, and a lightweight status endpoint optimized for frontend polling during upload processing. These endpoints bridge the upload/parsing phase and the pipeline building phase. The Pipeline Builder needs the dataset listing to populate its "Add Foundry data" dialog, needs the schema to configure transform nodes (Cast needs to know current column types, Rename needs the column list, Join needs column names for the match condition), and needs the preview to show data samples during pipeline authoring.

## Dataset Listing Endpoint

`GET /api/v1/projects/:projectId/folders/:folderId/datasets`

This endpoint supports filtering, sorting, and pagination. Query parameters (validated with Zod):

- `status`: Optional enum filter (`pending`, `processing`, `ready`, `error`). The Pipeline Builder will filter to `ready` datasets only.
- `sort`: Column to sort by, default `name`. Allowed values: `name`, `created_at`, `updated_at`, `file_size_bytes`, `row_count`.
- `order`: Sort direction, default `asc`. Allowed: `asc`, `desc`.
- `page`: 1-indexed page number, default 1.
- `limit`: Items per page, default 20, max 100.

The SQL query uses a window function to compute the total count without a separate query:

```sql
SELECT d.*,
  COUNT(*) OVER() AS total_count
FROM datasets d
WHERE d.folder_id = $1
  AND ($2::varchar IS NULL OR d.status = $2)
ORDER BY d.{sort_column} {order}
LIMIT $3 OFFSET $4
```

The `COUNT(*) OVER()` window function computes the total number of matching rows across all pages. This value is identical for every row in the result set, so extract it from the first row and strip it from the individual objects. This halves the database round trips compared to executing a separate `SELECT COUNT(*)` query.

Parse the results to construct the pagination response:

```typescript
const totalCount = results.length > 0 ? results[0].total_count : 0;
const datasets = results.map(({ total_count, ...d }) => d);
const totalPages = Math.ceil(totalCount / limit);

return {
  data: datasets,
  meta: {
    total: totalCount,
    page,
    limit,
    totalPages,
    hasNext: page < totalPages,
    hasPrev: page > 1
  }
};
```

## Dataset Detail Endpoint

`GET /api/v1/datasets/:datasetId`

Returns the complete dataset record with all column metadata in a single database query using `json_agg`:

```sql
SELECT d.*,
  json_agg(
    json_build_object(
      'id', dc.id,
      'columnName', dc.column_name,
      'columnType', dc.column_type,
      'ordinalPosition', dc.ordinal_position,
      'nullable', dc.nullable,
      'sampleValues', dc.sample_values
    ) ORDER BY dc.ordinal_position
  ) FILTER (WHERE dc.id IS NOT NULL) AS columns
FROM datasets d
LEFT JOIN dataset_columns dc ON dc.dataset_id = d.id
WHERE d.id = $1
GROUP BY d.id
```

The `LEFT JOIN` ensures datasets with no parsed columns (status `pending` or `processing`) still return — `columns` will be `null` instead of the query returning zero rows. The `FILTER (WHERE dc.id IS NOT NULL)` prevents a `[null]` array when there are no columns. The `ORDER BY dc.ordinal_position` inside `json_agg` ensures columns appear in their original CSV order, which is critical for the Pipeline Builder's column displays.

Return 404 if the dataset doesn't exist. Return 400 if the datasetId is not a valid UUID (validated by the Zod `UuidParamSchema`).

## Dataset Preview Endpoint

`GET /api/v1/datasets/:datasetId/preview?rows=50`

This is the most technically interesting endpoint because it must stream-read a CSV file and return only the first N rows without loading the full file into memory.

```typescript
async getDatasetPreview(datasetId: string, rowCount: number): Promise<PreviewResult> {
  const dataset = await this.knex('datasets').where({ id: datasetId }).first();
  if (!dataset) throw new AppError(404, 'Dataset not found');

  if (dataset.status !== 'ready') {
    throw new AppError(409,
      `Dataset is still being processed. Current status: ${dataset.status}. ` +
      `Please wait until status is 'ready' before previewing.`
    );
  }

  return new Promise((resolve, reject) => {
    const rows: Record<string, string>[] = [];
    const stream = createReadStream(dataset.file_path, { encoding: 'utf-8' });
    const parser = parse({ columns: true, skip_empty_lines: true, trim: true, bom: true });

    parser.on('data', (row) => {
      rows.push(row);
      if (rows.length >= rowCount) {
        // Destroy the stream to stop reading the file
        parser.destroy();
        stream.destroy();
        resolve({
          datasetId: dataset.id,
          rows,
          returnedRows: rows.length,
          totalRows: dataset.row_count
        });
      }
    });

    parser.on('end', () => {
      // File had fewer rows than requested
      resolve({
        datasetId: dataset.id,
        rows,
        returnedRows: rows.length,
        totalRows: dataset.row_count
      });
    });

    parser.on('error', reject);
    stream.pipe(parser);
  });
}
```

The key optimization: calling `parser.destroy()` and `stream.destroy()` after collecting enough rows stops the file read immediately. For a 2GB CSV file where we only need 50 rows, this reads approximately 5-10KB instead of the full 2GB. Without explicit stream destruction, the parser would continue reading the entire file and discarding rows, consuming unnecessary I/O and CPU.

Set the response header `Cache-Control: private, max-age=60` because the CSV file content is immutable once uploaded (files are never modified in place — new uploads create new versions per BE-018). This allows the browser to cache preview responses for 60 seconds, eliminating redundant server round trips when the user switches between the file browser and preview tabs.

## Dataset Status Endpoint

`GET /api/v1/datasets/:datasetId/status`

The lightest-weight endpoint, designed for polling:

```sql
SELECT id, status, row_count, column_count FROM datasets WHERE id = $1
```

Returns only 4 fields (~100 bytes) instead of the full dataset object (~2KB+). The frontend polls this endpoint every 2 seconds after uploading a file, so the small payload reduces bandwidth by 95% compared to polling the detail endpoint. Once the status transitions to `ready` or `error`, the frontend stops polling and fetches the full detail.

## Acceptance Criteria

- Listing supports pagination and returns correct total/page/limit/hasNext/hasPrev
- Listing filters by status correctly (status=ready returns only parsed datasets)
- Listing sorts by any of the 5 allowed columns in both directions
- Detail includes nested columns array ordered by ordinal_position
- Detail returns null columns array for datasets with status 'pending'
- Preview returns exactly N rows from the CSV file
- Preview returns 409 Conflict for datasets with status not 'ready'
- Preview for large files reads only the requested rows (verified: parser.destroy() and stream.destroy() are called after collecting N rows, confirmed via unit test)
- Status endpoint returns only 4 fields for efficient polling
- All endpoints return 404 for non-existent dataset IDs
- All endpoints return 400 for malformed UUID parameters
- Listing query uses window function COUNT(*) OVER() to avoid a separate count query
- GET /api/v1/datasets/:datasetId returns dataset with nested columns array (null for pending/processing datasets)
- Cache-Control: private, max-age=60 header is set on preview responses
