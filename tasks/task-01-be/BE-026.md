- HTTP testing via `fetch` against a running server

**What to reuse vs. build new:**
- **REUSE** Saturday's test pattern structure (describe/it blocks, setup/teardown, assertion patterns) — adapt to Jest + Supertest + TypeScript
- **REUSE** the end-to-end test flow from Sunday Task 25 (create → upload → verify lifecycle) — adapt for the foundry-backend's project/folder/dataset lifecycle
- **BUILD NEW** the Jest + ts-jest configuration, the test database lifecycle (create/migrate/teardown with timestamped DB names), the `TRUNCATE ... RESTART IDENTITY CASCADE` helper, and the `createTestUserAndLogin()` auth helper
- **IMPROVE** the daily tasks' testing by using Supertest instead of `fetch` (Supertest doesn't require a running server), adding per-test table truncation (the ontology-engine tests don't clean up between tests, causing potential state leakage), and achieving 80%+ coverage targets. Consider backporting these testing infrastructure improvements.

## Objective

Configure Jest with `ts-jest` for TypeScript support, set up test database lifecycle (create, migrate, teardown), configure Supertest for HTTP testing against the Express app without starting a real server, implement per-test table truncation, create test files for four API resource areas, and create fixture CSV files. Target: all tests complete in under 30 seconds with over 80% line coverage across `src/services/`, `src/controllers/`, and `src/routes/`.

## Test Database Lifecycle

### test/setup.ts — Global Setup

```typescript
export default async function setup(): Promise<void> {
  const dbName = `test_foundry_${Date.now()}`;
  // Connect to default 'postgres' database to create test DB
  const adminKnex = knex({ client: 'pg', connection: { database: 'postgres', ... } });
  await adminKnex.raw(`CREATE DATABASE "${dbName}"`);
  await adminKnex.destroy();

  // Store DB name for teardown
  process.env.TEST_DB_NAME = dbName;

  // Connect to new test DB and run migrations
  const testKnex = knex({ client: 'pg', connection: { database: dbName, ... } });
  await testKnex.migrate.latest();
  await testKnex.destroy();
}
```

The timestamp in the DB name (`test_foundry_1710000000000`) prevents collisions when tests run in parallel CI environments.

### test/teardown.ts — Global Teardown

```typescript
export default async function teardown(): Promise<void> {
  const dbName = process.env.TEST_DB_NAME;
  const adminKnex = knex({ client: 'pg', connection: { database: 'postgres', ... } });
  // Terminate connections then drop
  await adminKnex.raw(`SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname = '${dbName}'`);
  await adminKnex.raw(`DROP DATABASE IF EXISTS "${dbName}"`);
  await adminKnex.destroy();
}
```

### test/helpers.ts — Per-Test Utilities

```typescript
import { app } from '@/index'; // Import Express app without calling .listen()
import knex from 'knex';

export const testKnex = knex({
  client: 'pg',
  connection: { database: process.env.TEST_DB_NAME, ... }
});

export { app };

export async function truncateAllTables(): Promise<void> {
  await testKnex.raw(
    'TRUNCATE users, projects, folders, datasets, dataset_columns, project_members, refresh_tokens RESTART IDENTITY CASCADE'
  );
}

// Helper to create an authenticated test user and get JWT
export async function createTestUserAndLogin(): Promise<{ userId: string; token: string }> {
  const res = await request(app)
    .post('/api/auth/register')
    .send({ email: 'test@example.com', password: 'TestPass123', displayName: 'Test' });
  return { userId: res.body.user.id, token: res.body.accessToken };
}
```

The Express app must export the `app` instance WITHOUT calling `server.listen()`. Supertest creates its own ephemeral server internally.

### Auth Testing Strategy

Tests authenticate by calling `POST /api/auth/register` to create a test user and receiving a JWT. The JWT is included in subsequent requests via `.set('Authorization', `Bearer ${token}`)`. No mocking of the auth middleware — tests exercise the full authentication flow.

For testing 403 (forbidden) scenarios, create two users: one who is the project owner, and one who is not a member.

## npm Scripts

Add to `package.json`:

```json
{
  "scripts": {
    "test": "jest --runInBand --forceExit",
    "test:watch": "jest --watch --runInBand",
    "test:coverage": "jest --runInBand --forceExit --coverage"
  }
}
```

`--runInBand` ensures tests run sequentially (required because they share a database). `--forceExit` prevents Jest from hanging on open handles (Knex pool, timers).
