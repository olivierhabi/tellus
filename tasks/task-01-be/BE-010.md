**Palantir Feature:** Workspace Navigator — Unified Search Across Projects, Folders, and Datasets

- **IMPROVE** the ontology-engine's search by considering the dual-strategy approach (tsvector + ILIKE substring) for cases where OpenSearch is unavailable

## Objective

Build a full-text search system using PostgreSQL's built-in tsvector/tsquery engine, plus a lightweight autocomplete endpoint for typeahead suggestions. This requires a database migration to add tsvector columns and GIN indexes, then two API endpoints.

## Database Migration

Create a new migration file that adds the following to the `projects`, `folders`, and `datasets` tables:

1. Add a `search_vector` column of type `tsvector` to each table
2. Create a GIN index on each `search_vector` column:
   - `CREATE INDEX idx_projects_search ON projects USING GIN(search_vector)`
   - `CREATE INDEX idx_folders_search ON folders USING GIN(search_vector)`
   - `CREATE INDEX idx_datasets_search ON datasets USING GIN(search_vector)`
3. Create trigger functions that automatically update `search_vector` when the `name` column changes:
   ```sql
   CREATE OR REPLACE FUNCTION update_project_search_vector() RETURNS trigger AS $$
   BEGIN
     NEW.search_vector := to_tsvector('english', COALESCE(NEW.name, ''));
     RETURN NEW;
   END;
   $$ LANGUAGE plpgsql;

   CREATE TRIGGER trg_projects_search_vector
     BEFORE INSERT OR UPDATE OF name ON projects
     FOR EACH ROW EXECUTE FUNCTION update_project_search_vector();
   ```
   Repeat for folders and datasets tables.
4. Backfill existing rows: `UPDATE projects SET search_vector = to_tsvector('english', COALESCE(name, ''))` (repeat for folders, datasets)

The migration `down()` drops triggers, functions, indexes, and columns in reverse order.

## Search Endpoint

`GET /api/search`

**Query Parameters** (validated with Zod):
- `q` — Search text, optional, max 500 chars. Validated with Zod: `z.string().max(500).optional().default('')`. Return 400 if exceeds 500 chars. When empty or omitted, triggers "recent items" behavior (see below).
- `type` — Optional filter: `'project' | 'folder' | 'dataset'`. When omitted, search all three types.
- `projectId` — Optional UUID, scopes results to a single project
- `folderId` — Optional UUID, scopes results to folders and datasets that are descendants of this folder (via LTREE `<@` operator from BE-004). When `folderId` is provided, projects are excluded from results because projects are not contained within folders.
- `page` — 1-indexed page number, default 1
- `limit` — Items per page, default 20, max 100

**Search algorithm (dual strategy):**

For each of the three tables (projects, folders, datasets), execute a query that combines tsvector full-text search with ILIKE substring matching, then UNION ALL the results:

```sql
-- Example for one table (repeat for each, then UNION ALL):
SELECT id, name, 'project' AS type, updated_at,
  ts_rank(search_vector, plainto_tsquery('english', $1)) AS fts_rank,
  CASE WHEN LOWER(name) = LOWER($1) THEN 100 ELSE 0 END AS exact_bonus,
  CASE WHEN LOWER(name) LIKE LOWER($1) || '%' THEN 50 ELSE 0 END AS prefix_bonus
FROM projects
WHERE search_vector @@ plainto_tsquery('english', $1)
   OR name ILIKE '%' || $1 || '%'
```

**Result combination:** The three UNION ALL subqueries are wrapped in an outer query that:
1. Deduplicates by `(type, id)` — each resource appears at most once
2. Adds `COUNT(*) OVER() AS total_count` to compute the total matching count for pagination
3. Orders by `exact_bonus DESC, prefix_bonus DESC, fts_rank DESC, updated_at DESC`
4. Applies `LIMIT` and `OFFSET` for pagination

**Empty query behavior:** When `q` is empty or omitted, return the 20 most recently updated items across all three types, ordered by `updated_at DESC`. This serves as a "recent items" view.

## Autocomplete/Suggest Endpoint

`GET /api/search/suggest`

**Query Parameters:**
- `q` — Search text, required, max 500 chars

Returns the top 10 name matches optimized for keystroke-speed response. No joins, no ranking computation — just a simple prefix query:

```sql
SELECT name, 'project' AS type, id FROM projects WHERE LOWER(name) LIKE LOWER($1) || '%'
UNION ALL
SELECT name, 'folder' AS type, id FROM folders WHERE LOWER(name) LIKE LOWER($1) || '%'
UNION ALL
SELECT name, 'dataset' AS type, id FROM datasets WHERE LOWER(name) LIKE LOWER($1) || '%'
ORDER BY name ASC
LIMIT 10
```

Response: `{ suggestions: [{ name: string, type: string, id: string }] }`

When `q` is empty or omitted for the suggest endpoint, return an empty `suggestions` array (no "recent items" fallback for autocomplete).

## Acceptance Criteria

- Migration adds search_vector column and GIN index to all three tables
- Migration creates triggers that auto-update search_vector on name INSERT/UPDATE
- Migration backfills existing rows
- Migration down() cleanly removes all added objects
- GET /api/search?q=flight returns datasets, folders, and projects with "flight" in the name
- GET /api/search?q=flight&type=dataset returns only datasets
- GET /api/search?q=flight&projectId=<uuid> scopes results to that project
- GET /api/search?q=flight&folderId=<uuid> scopes results to that folder's LTREE descendants
- Exact name matches rank highest (exact_bonus = 100)
- Prefix matches rank second (prefix_bonus = 50)
- tsvector word matches rank third (via ts_rank)
- GET /api/search with empty q returns 20 most recently updated items across all types
- GET /api/search?q=<501+ chars> returns 400
- Pagination works correctly (page, limit, total count)
- GET /api/search/suggest?q=ord returns top 10 prefix-matched names
- Suggest endpoint responds in under 50ms (no joins, no ranking)
- Results are deduplicated — each resource appears at most once
