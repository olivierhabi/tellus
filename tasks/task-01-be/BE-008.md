# BE-008: Implement Dataset Deletion and Orphan Cleanup Service

**Palantir Feature:** Data Ingestion — Dataset Deletion and System Maintenance

## Objective

Build endpoints for deleting individual and batch datasets (DB records + physical files), and a background CleanupService that periodically reconciles orphaned files and records. Deletion order is a hard requirement: always delete the database record first, then the physical file. This ensures the worst case is an orphaned file on disk (harmless, cleaned up by CleanupService), never a database record pointing to a missing file (causes application errors).

## Single Dataset Deletion

`DELETE /api/datasets/:datasetId`

1. Delete database record: `DELETE FROM datasets WHERE id = $1 RETURNING file_path`. The CASCADE constraint on `dataset_columns` automatically removes column metadata.
2. Delete physical file using `fs.promises.unlink(filePath)`. If the error code is `ENOENT` (file already gone), proceed without error. Log all other file system errors as warnings but do not fail the request — the DB record is already gone.
3. Return 204 No Content with empty body.
4. Return 404 if dataset does not exist. Return 400 for malformed UUID.

## Batch Dataset Deletion

`DELETE /api/datasets` with body `{ datasetIds: string[] }`

Validate with Zod: `z.object({ datasetIds: z.array(z.string().uuid()).min(1).max(100) })`. Return 400 if array is empty, exceeds 100 items, or contains non-UUID strings.

1. Use a Knex transaction for all database deletes: `DELETE FROM datasets WHERE id IN ($1...$N) RETURNING id, file_path`.
2. After the transaction commits, delete physical files using `Promise.allSettled(filePaths.map(fp => fs.promises.unlink(fp).catch(() => {})))`. `Promise.allSettled` ensures one file deletion failure does not block others.
3. Return 200 with `{ deleted: number, fileCleanupErrors: number }`.

## CleanupService

Create `src/services/cleanupService.ts` with two methods:

**`cleanOrphanedFiles()`** — Walk `UPLOAD_DIR` recursively using `fs.promises.readdir({ recursive: true })`. For each file found, query `SELECT id FROM datasets WHERE file_path = $1`. If no matching record exists, delete the file with `fs.promises.unlink()`. Return the count of deleted files.

**`cleanOrphanedRecords()`** — Query `SELECT id, file_path FROM datasets WHERE status != 'error'`. For each record, check file existence with `fs.promises.access(filePath, fs.constants.F_OK)`. If the file does not exist, update the record: `UPDATE datasets SET status = 'error', schema_info = '{"error": "File missing from disk"}', updated_at = NOW() WHERE id = $1`. Return the count of updated records.

## Scheduled Execution

Create `src/jobs/cleanupScheduler.ts` to schedule the CleanupService to run every 6 hours via `setInterval`:

```typescript
let isRunning = false;
const CLEANUP_INTERVAL_MS = 6 * 60 * 60 * 1000; // 6 hours

setInterval(async () => {
  if (isRunning) return; // Prevent overlapping executions
  isRunning = true;
  try {
    const filesDeleted = await cleanupService.cleanOrphanedFiles();
    const recordsUpdated = await cleanupService.cleanOrphanedRecords();
    logger.info('Cleanup completed', { filesDeleted, recordsUpdated });
  } finally {
    isRunning = false;
  }
}, CLEANUP_INTERVAL_MS);
```

The `isRunning` boolean guard prevents overlapping executions if a cleanup run takes longer than 6 hours.

## Admin Trigger Endpoint

`POST /api/admin/cleanup`

Triggers the CleanupService immediately (bypassing the 6-hour schedule). Returns:

```json
{
  "orphanedFilesDeleted": 3,
  "orphanedRecordsUpdated": 1,
  "durationMs": 1234
}
```

This endpoint should be protected by `authorize('owner')` (admin-only access via BE-014). If BE-014 is not yet implemented, use the placeholder `authorize()` middleware from BE-005 and add a TODO comment: `// TODO: Restrict to owner role (BE-014)`.

## Acceptance Criteria

- DELETE /api/datasets/:datasetId removes the DB record (with CASCADE to dataset_columns) and the physical file
- DELETE /api/datasets/:datasetId returns 204 with empty body on success
- DELETE /api/datasets/:datasetId returns 404 for non-existent dataset
- DELETE /api/datasets/:datasetId returns 400 for malformed UUID
- If physical file is already missing (ENOENT), DELETE still returns 204 (not an error)
- Non-ENOENT file errors are logged as warnings but do not fail the request
- Batch DELETE validates datasetIds is a non-empty array of UUIDs with max 100 items
- Batch DELETE uses a transaction for all DB deletes (all-or-nothing)
- Batch DELETE returns count of deleted records and file cleanup errors
- CleanupService.cleanOrphanedFiles() deletes files on disk that have no matching DB record
- CleanupService.cleanOrphanedRecords() sets status='error' for DB records whose files are missing
- Scheduled cleanup runs every 6 hours and does not overlap with itself
- POST /api/admin/cleanup triggers cleanup immediately and returns counts with duration
- DB deletion always happens BEFORE file deletion (never reversed)
- POST /api/admin/cleanup returns 403 for non-owner users (when BE-014 is implemented)
- Scheduler code lives in src/jobs/cleanupScheduler.ts (not in src/index.ts)
