## Multi-Environment Knex Configuration

Extend `src/config/knexfile.ts` to export environment-specific configurations:

```typescript
const config = {
  development: {
    client: 'pg',
    connection: process.env.DATABASE_URL,
    migrations: { directory: './src/migrations', extension: 'ts' },
    seeds: { directory: './src/seeds', extension: 'ts' },
    pool: { min: 2, max: 10 }
  },
  test: {
    client: 'pg',
    connection: {
      host: process.env.DB_HOST || 'localhost',
      port: Number(process.env.DB_PORT) || 5432,
      user: process.env.DB_USER || 'postgres',
      password: process.env.DB_PASSWORD || 'postgres',
      database: 'test_foundry'
    },
    migrations: { directory: './src/migrations', extension: 'ts' },
    seeds: { directory: './src/seeds', extension: 'ts' },
    pool: { min: 1, max: 5 }
  },
  production: {
    client: 'pg',
    connection: {
      connectionString: process.env.DATABASE_URL,
      ssl: { rejectUnauthorized: false }
    },
    migrations: { directory: './dist/migrations' },
    seeds: { directory: './dist/seeds' },
    pool: { min: 2, max: 20 }
  }
};

export default config;
```

The `test` environment uses a separate database (`test_foundry`) to avoid polluting development data. The `production` environment requires `DATABASE_URL` and enables SSL.

## npm Scripts

Add to `package.json`:

```json
{
  "scripts": {
    "migrate:up": "knex migrate:latest --knexfile src/config/knexfile.ts",
    "migrate:down": "knex migrate:rollback --knexfile src/config/knexfile.ts",
    "migrate:status": "knex migrate:status --knexfile src/config/knexfile.ts",
    "migrate:reset": "knex migrate:rollback --all --knexfile src/config/knexfile.ts && knex migrate:latest --knexfile src/config/knexfile.ts",
    "seed": "knex seed:run --knexfile src/config/knexfile.ts",
    "db:setup": "npm run migrate:up && npm run seed"
  }
}
```

### Programmatic CSV Generation

Generate three CSV files with 100 rows each:

**File 1: `orders_office_goods.csv`**
**File 2: `orders_bureau_transactional_system.csv`**
**File 3: `consolidated_customers.csv`**

Column definitions:
- `order_id` — UUID v4 generated via `crypto.randomUUID()`
- `item_name` — randomly selected from this hardcoded list of 20 office supply products:
  ```
  ['Printer Paper A4', 'Ballpoint Pens (50pk)', 'Stapler Heavy Duty', 'Whiteboard Markers',
   'Filing Folders (25pk)', 'Desk Lamp LED', 'USB Flash Drive 32GB', 'Sticky Notes (12pk)',
   'Paper Clips (200pk)', 'Correction Tape', 'Binder Clips Large', 'Highlighter Set',
   'Desk Organizer', 'Tape Dispenser', 'Scissors Office', 'Notebook A5 Lined',
   'Calculator Desktop', 'Envelope C4 (50pk)', 'Label Maker', 'Pencil Sharpener Electric']
  ```
- `status` — randomly selected from `['pending', 'assigned', 'shipped']`
- `customer_name` — randomly selected from a hardcoded list of 20 names:
  ```
  ['Alice Johnson', 'Bob Smith', 'Carol Williams', 'David Brown', 'Emma Davis',
   'Frank Miller', 'Grace Wilson', 'Henry Moore', 'Ivy Taylor', 'Jack Anderson',
   'Karen Thomas', 'Leo Jackson', 'Mia White', 'Nathan Harris', 'Olivia Martin',
   'Paul Thompson', 'Quinn Garcia', 'Rachel Martinez', 'Sam Robinson', 'Tina Clark']
  ```
- `order_due_date` — random date between `2025-01-01` and `2025-03-31` (fixed epoch, not relative to seed run date, ensuring deterministic output). Format: `YYYY-MM-DD`.
- `days_until_due` — integer computed as the difference in days between `order_due_date` and the fixed epoch `2025-01-01`.

Use a seeded PRNG (e.g., simple LCG or `Math.seedrandom`) initialized with a fixed seed value (`42`) so that running the seed multiple times produces identical CSV content.

## Acceptance Criteria

- `npm run migrate:up` applies all pending migrations successfully
- `npm run migrate:down` rolls back the last migration batch
- `npm run migrate:status` prints a table showing applied and pending migrations
- `npm run migrate:reset` rolls back all migrations then re-applies them
- `npm run seed` inserts the test user, project, project_members, folder, and three datasets
- `npm run seed` running twice produces no errors and no duplicate records (idempotent)
- `npm run db:setup` runs migrate:up then seed in sequence
- Three CSV files exist at `<UPLOAD_DIR>/<projectId>/<folderId>/` with exactly 100 data rows plus a header
- Each CSV has correct columns: order_id, item_name, status, customer_name, order_due_date, days_until_due
- Test user can log in with email `testuser@foundry.local` and password `TestPassword1`
- Running the seed with a fixed PRNG seed produces identical CSV content each time
- The test environment uses database `test_foundry` (separate from development)
- Production config requires DATABASE_URL and enables SSL
