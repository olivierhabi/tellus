# BE-012: Implement WebSocket Server for Real-Time Upload and Processing Status Notifications

**Palantir Feature:** Data Ingestion — Foundry's real-time feedback during file upload and processing. In the Speedrun course, when the user uploads CSV files and when Pipeline Builder deploys a pipeline, the UI shows status indicators that update without page refreshes. The object table in Workshop also updates in real-time after an action is executed. This real-time capability is powered by a push notification system.

## Reuse from Ontology Engine (Daily Tasks)

**Saturday Task 14** implements a data preview endpoint with real-time status updates, and the indexing pipeline (Tuesday Tasks 11–12) uses event-driven status tracking for the 7-stage indexing funnel. While neither implements WebSocket directly, the event emission patterns are reusable.

**What to reuse vs. build new:**
- **REUSE** the status transition pattern from Tuesday's indexing funnel (pending → indexing → ready/error) as the model for dataset processing events
- **BUILD NEW** the entire WebSocket server (the ontology-engine does not have WebSocket support), the EventBus singleton, the project-scoped subscription model, and the heartbeat/ping-pong mechanism
- **IMPROVE** the ontology-engine by eventually adding WebSocket support for real-time indexing status updates and action execution notifications — this BE-012 implementation can serve as the reference

## Objective

Build a WebSocket server that runs alongside the Express HTTP server, providing real-time event delivery to connected frontend clients. Services throughout the backend emit events to a central event bus, and the WebSocket server forwards those events to clients subscribed to the relevant project. This replaces the polling-based alternative (where the frontend would call GET /api/v1/datasets/:id/status every 2 seconds), reducing server load by approximately 90% and providing instant updates (sub-100ms latency vs 2-second polling intervals). This notification system is the backbone for all real-time features: upload progress, parsing completion, pipeline execution status, and eventually action execution confirmation in Workshop.

## Architecture: Event Bus Decoupling

The core design principle is that **no service should directly reference the WebSocket server**. Instead, services emit events to a centralized `EventBus` (a Node.js EventEmitter singleton), and the WebSocket server subscribes to the bus and forwards relevant events to connected clients.

This decoupling provides three critical benefits:

1. **Testability**: Services can be unit-tested by asserting events emitted to the bus, without needing a running WebSocket server. The test just checks `eventBus.emit` was called with the correct arguments.

2. **Extensibility**: New event consumers (email notifications, webhook callbacks, audit logging) can subscribe to the same bus without modifying any service code.

3. **Reliability**: If the WebSocket server crashes or restarts, services continue operating normally. Events emitted during WebSocket downtime are simply lost (acceptable for status updates, which are eventually consistent via polling fallback).

## Event Bus Implementation

Create `src/websocket/eventBus.ts`:

```typescript
import { EventEmitter } from 'events';

export interface WSEvent {
  event: string;
  projectId: string;
  payload: Record<string, unknown>;
  timestamp: string;
}

class AppEventBus extends EventEmitter {
  private static instance: AppEventBus;

  private constructor() {
    super();
    this.setMaxListeners(50); // Allow many subscribers without warnings
  }

  static getInstance(): AppEventBus {
    if (!AppEventBus.instance) {
      AppEventBus.instance = new AppEventBus();
    }
    return AppEventBus.instance;
  }
}

export const eventBus = AppEventBus.getInstance();
```

Create a helper in `src/utils/emitEvent.ts` that all services use:

```typescript
import { eventBus, WSEvent } from '@/websocket/eventBus';

export function emitEvent(eventName: string, projectId: string, payload: Record<string, unknown>): void {
  const event: WSEvent = {
    event: eventName,
    projectId,
    payload,
    timestamp: new Date().toISOString()
  };
  eventBus.emit('ws:event', event);
}
```

All services call `emitEvent('dataset.parsed', projectId, { datasetId, rowCount })` — they never import the WebSocket module directly.

## WebSocket Server Implementation

Create `src/websocket/server.ts` using the `ws` npm package:

```typescript
import { WebSocketServer, WebSocket } from 'ws';
import { Server as HttpServer } from 'http';
import { eventBus, WSEvent } from './eventBus';
import { logger } from '@/config/logger';

interface ClientState {
  ws: WebSocket;
  subscribedProjects: Set<string>;
  isAlive: boolean;
  connectionId: string;
}

export function initWebSocketServer(httpServer: HttpServer): void {
  const wss = new WebSocketServer({ server: httpServer, path: '/ws' });
  const clients = new Map<WebSocket, ClientState>();

  // --- Connection Handling ---
  wss.on('connection', (ws: WebSocket) => {
    const connectionId = crypto.randomUUID();
    const state: ClientState = {
      ws,
      subscribedProjects: new Set(),
      isAlive: true,
      connectionId
    };
    clients.set(ws, state);
    logger.info('WebSocket client connected', { connectionId, totalClients: clients.size });

    // Handle incoming messages from client
    ws.on('message', (data: Buffer) => {
      try {
        const message = JSON.parse(data.toString());

        if (message.action === 'subscribe' && typeof message.projectId === 'string') {
          // Validate UUID format
          const uuidRegex = /^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i;
          if (!uuidRegex.test(message.projectId)) {
            ws.send(JSON.stringify({ event: 'error', payload: { message: 'Invalid projectId format' } }));
            return;
          }
          state.subscribedProjects.add(message.projectId);
          ws.send(JSON.stringify({
            event: 'subscribed',
            payload: { projectId: message.projectId }
          }));
          logger.debug('Client subscribed to project', { connectionId, projectId: message.projectId });
        }

        if (message.action === 'unsubscribe' && typeof message.projectId === 'string') {
          state.subscribedProjects.delete(message.projectId);
          ws.send(JSON.stringify({
            event: 'unsubscribed',
            payload: { projectId: message.projectId }
          }));
        }
      } catch (err) {
        ws.send(JSON.stringify({ event: 'error', payload: { message: 'Invalid JSON message' } }));
      }
    });

    // Handle disconnection
    ws.on('close', () => {
      clients.delete(ws);
      logger.info('WebSocket client disconnected', { connectionId, totalClients: clients.size });
    });

    // Handle pong for heartbeat
    ws.on('pong', () => {
      state.isAlive = true;
    });
  });

  // --- Heartbeat: Detect Stale Connections ---
  const heartbeatInterval = setInterval(() => {
    clients.forEach((state, ws) => {
      if (!state.isAlive) {
        // Client didn't respond to last ping — terminate
        logger.warn('Terminating unresponsive WebSocket client', { connectionId: state.connectionId });
        clients.delete(ws);
        return ws.terminate();
      }
      state.isAlive = false;
      ws.ping(); // Client must respond with pong within 15 seconds
    });
  }, 15000); // Check every 15 seconds

  // Clean up heartbeat interval when server closes
  wss.on('close', () => {
    clearInterval(heartbeatInterval);
  });

  // --- Event Forwarding: Bus → Subscribed Clients ---
  eventBus.on('ws:event', (event: WSEvent) => {
    let deliveredCount = 0;
    clients.forEach((state, ws) => {
      if (state.subscribedProjects.has(event.projectId) && ws.readyState === WebSocket.OPEN) {
        try {
          ws.send(JSON.stringify(event));
          deliveredCount++;
        } catch (err) {
          // Client connection broke between readyState check and send
          logger.warn('Failed to deliver event to client', {
            connectionId: state.connectionId,
            event: event.event
          });
          clients.delete(ws);
          ws.terminate();
        }
      }
    });
    logger.debug('Event delivered', { event: event.event, projectId: event.projectId, recipients: deliveredCount });
  });
}
```

## Integration with HTTP Server

In `src/index.ts`, modify the server creation to attach the WebSocket server:

```typescript
import { initWebSocketServer } from '@/websocket/server';

const server = http.createServer(app);
initWebSocketServer(server); // Attach WebSocket to same HTTP server
server.listen(PORT, () => {
  logger.info(`Server running on port ${PORT} (HTTP + WebSocket at /ws)`);
});
```

Clients connect to `ws://localhost:3001/ws` — the WebSocket server shares the same port as the HTTP server but uses a different protocol (WS vs HTTP) and a different path (/ws).

## Event Catalog

```typescript
export const WS_EVENTS = {
  UPLOAD_STARTED: 'upload.started',       // Payload: { datasetId, fileName, fileSize }

} as const;
```

## Frontend Client Protocol

Document the expected client behavior for the frontend team:

1. Connect to `ws://localhost:3001/ws` on app load
2. Send `{ "action": "subscribe", "projectId": "<uuid>" }` when navigating to a project
3. Listen for events matching the WS_EVENTS catalog
4. On `dataset.statusChanged` with newStatus `ready`: refresh the dataset list or update the status badge
5. On `dataset.parsed`: update column metadata in the local cache
6. On `dataset.parseError`: show error notification
7. Send `{ "action": "unsubscribe", "projectId": "<uuid>" }` when navigating away
8. Handle reconnection: if the connection drops, wait 1s and reconnect with exponential backoff (1s, 2s, 4s, 8s, max 30s)

## Acceptance Criteria

- WebSocket server runs on the same port as HTTP at path /ws
- Clients connect via ws://localhost:3001/ws and receive a connection acknowledgment
- Sending { action: 'subscribe', projectId: '<uuid>' } subscribes to that project's events
- Sending { action: 'unsubscribe', projectId: '<uuid>' } removes the subscription
- Only subscribed clients receive events for their subscribed projects
- Clients subscribed to Project A do NOT receive events from Project B
- Invalid JSON messages return { event: 'error', payload: { message } }
- Invalid projectId format (not UUID) returns error message without crashing
- Heartbeat ping/pong detects unresponsive clients within 30 seconds
- Unresponsive clients are terminated and removed from subscription lists
- When a dataset is uploaded, subscribed clients receive upload.completed event
- When parsing completes, subscribed clients receive dataset.parsed with column schema
- When parsing fails, subscribed clients receive dataset.parseError with error message
- EventBus decoupling verified: upload service does not import websocket module
- Total connected client count logged on every connect/disconnect
- Server handles 100 concurrent WebSocket connections with event delivery latency under 100ms per client
- WebSocket server exposes a close method that sends close frame with code 1001 to all clients (called by BE-030 during graceful shutdown)
