## Objective

Create a `validate()` middleware factory that accepts Zod schemas for body, params, and query, collects all validation errors across all three sources, and returns a structured 400 response using the response envelope format from BE-022. Then refactor all existing controllers to remove inline `safeParse` calls and use `validate()` in route definitions instead. **This task must be implemented AFTER BE-022** so the error response uses the standard envelope format.

## Validate Middleware Factory

Create `src/middleware/validate.ts`:

```typescript
import { ZodSchema, ZodError } from 'zod';
import { Request, Response, NextFunction } from 'express';

interface ValidationSchemas {
  body?: ZodSchema;
  params?: ZodSchema;
  query?: ZodSchema;
}

export function validate(schemas: ValidationSchemas) {
  return (req: Request, res: Response, next: NextFunction) => {
    const errors: ValidationErrorDetail[] = [];

    // Validate body (strip unknown fields for mass assignment prevention)
    if (schemas.body) {
      const result = schemas.body.strip().safeParse(req.body);
      if (!result.success) {
        errors.push(...formatZodErrors(result.error, 'body'));
      } else {
        req.body = result.data; // Replace with stripped/validated data
      }
    }

    // Validate params
    if (schemas.params) {
      const result = schemas.params.safeParse(req.params);
      if (!result.success) {
        errors.push(...formatZodErrors(result.error, 'params'));
      }
    }

    // Validate query
    if (schemas.query) {
      const result = schemas.query.safeParse(req.query);
      if (!result.success) {
        errors.push(...formatZodErrors(result.error, 'query'));
      }
    }

    if (errors.length > 0) {
      return res.status(400).json({
        success: false,
        error: {
          code: 'VALIDATION_ERROR',
          message: 'Validation failed',
          details: errors
        }
      });
    }

    next();
  };
}
```

## Error Detail Format

```typescript
interface ValidationErrorDetail {
  field: string;     // Dot-path notation: "name", "address.city", "filters[0].value"
  message: string;   // Human-readable: "Required", "Must be at least 1 character"
  expected: string;  // Expected type: "string", "number", "uuid"
  received: string;  // Actual type: "undefined", "null", "number"
}
```

### Path Formatting Rules

Transform Zod's `issue.path` array into a string:
- Simple field: `['name']` → `"name"`
- Nested object: `['address', 'city']` → `"address.city"`
- Array index: `['filters', 0, 'value']` → `"filters[0].value"`
- Array root: `[0, 'name']` → `"[0].name"`

```typescript
function formatFieldPath(path: (string | number)[]): string {
  return path.reduce((acc, segment, idx) => {
    if (typeof segment === 'number') return `${acc}[${segment}]`;
    return idx === 0 ? segment : `${acc}.${segment}`;
  }, '');
}

function formatZodErrors(error: ZodError, source: string): ValidationErrorDetail[] {
  return error.issues.map(issue => ({
    field: formatFieldPath(issue.path),
    message: issue.message,
    expected: 'expected' in issue ? String(issue.expected) : 'valid value',
    received: 'received' in issue ? String(issue.received) : 'invalid'
  }));
}
```

## Schema Stripping Behavior

The `.strip()` call on body schemas removes any fields not defined in the Zod schema. This prevents mass assignment attacks where an attacker includes extra fields like `{ "name": "test", "role": "admin" }` and the extra `role` field gets passed through to a database query. Stripping ensures only declared fields survive validation.

`.strip()` is only applied to body schemas. Params and query schemas do not need stripping because Express already constrains their shape.

If a body schema does not support `.strip()` (e.g., it's a `z.union` or `z.intersection`), call `safeParse` without `.strip()` and log a debug warning.

## Acceptance Criteria

- `validate({ body: schema })` returns 400 when body fails validation
- `validate({ params: schema })` returns 400 when params fail validation (e.g., malformed UUID)
- `validate({ query: schema })` returns 400 when query params fail validation
- Multiple simultaneous errors across body and query are all returned in a single response
- Error response uses envelope format: `{ success: false, error: { code: 'VALIDATION_ERROR', message, details: [...] } }`
- Each error detail includes `field`, `message`, `expected`, `received`
- Nested object paths use dot notation: `address.city`
- Array index paths use bracket notation: `filters[0].value`
- Unknown body fields are stripped (not passed through to controller)
- `req.body` is replaced with validated+stripped data after successful validation
- If no schema is provided for a request part (e.g., no `query` schema), that part is not validated
- All four controller files have zero remaining `safeParse` calls
- All existing validation behavior (400 responses, error messages) is preserved after refactoring
- Route definitions use `validate()` middleware for all endpoints that accept input
