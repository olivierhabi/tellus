# BE-011: Implement Breadcrumb Navigation Path Resolution API

**Palantir Feature:** Workspace Navigator — Breadcrumb Navigation Bar

## Objective

Build an API endpoint that resolves the ancestor path for any resource (project, folder, or dataset), returning an ordered breadcrumb array from root to current item. Includes an LRU cache for performance and an optional `includeChildren` parameter.

## Breadcrumb Endpoint

`GET /api/breadcrumb/:type/:id`

**Path Parameters:**
- `type` — One of `'project'`, `'folder'`, or `'dataset'`. Return 400 for any other value.
- `id` — UUID of the resource. Return 400 for malformed UUID. Return 404 if resource not found.

**Query Parameters:**
- `includeChildren` — Optional boolean (`'true'` or `'false'`, default `'false'`). When `'true'`, the response additionally includes the direct children of the final breadcrumb segment.

## Breadcrumb Resolution by Type

**Project breadcrumb:** Returns a single-element array:
```json
[{ "id": "<project-uuid>", "name": "My Project", "type": "project", "url": "/projects/<project-uuid>" }]
```

**Folder breadcrumb:** Query the folder's LTREE path, retrieve all ancestors using the `@>` operator, order by depth ascending, and prepend the project:

```sql
SELECT f.id, f.name, f.depth
FROM folders f
WHERE f.project_id = $1
  AND f.path @> (SELECT path FROM folders WHERE id = $2)
ORDER BY f.depth ASC
```

Note: The `@>` (ancestor-of) operator returns all folders whose path is an ancestor of OR equal to the target folder's path. This means the target folder itself is included in the result.

Construct the breadcrumb: `[{ id: project.id, name: project.name, type: 'project', url }, ...ancestorFolders.map(f => ({ id: f.id, name: f.name, type: 'folder', url }))]`

**Dataset breadcrumb:** Resolve the parent folder's breadcrumb (using the folder logic above), then append the dataset as the final element:
```json
[...folderBreadcrumb, { "id": "<dataset-uuid>", "name": "orders.csv", "type": "dataset", "url": "/datasets/<dataset-uuid>" }]
```

## Each Breadcrumb Segment Shape

```typescript
interface BreadcrumbSegment {
  id: string;       // UUID of the resource
  name: string;     // Display name
  type: 'project' | 'folder' | 'dataset';
  url: string;      // Frontend URL path (e.g., "/projects/<uuid>", "/folders/<uuid>", "/datasets/<uuid>")
}
```

## includeChildren Response

When `?includeChildren=true`, the response shape changes to:

```json
{
  "breadcrumb": [/* array of BreadcrumbSegment */],
  "children": {
    "folders": [{ "id": "...", "name": "...", "createdAt": "..." }],
    "datasets": [{ "id": "...", "name": "...", "status": "...", "createdAt": "..." }]
  }
}
```

`children.folders` contains direct child folders of the final breadcrumb segment (sorted by name ASC). `children.datasets` contains datasets directly in the final breadcrumb segment's folder (sorted by name ASC). For project-type breadcrumbs, children are the root-level folders and datasets. For dataset-type breadcrumbs, children are the siblings (other items in the same folder).

When `?includeChildren=false` (default), the response uses the same object shape but with `children` set to `null`:

```json
{
  "breadcrumb": [/* array of BreadcrumbSegment */],
  "children": null
}
```

This ensures a consistent return type for the frontend (always an object, never a raw array), simplifying TypeScript typing.

## LRU Cache

Use the `lru-cache` npm package with these settings:
- Max entries: 1000
- TTL: 60 seconds (60000 ms)
- Cache key format: `${type}:${id}` (e.g., `folder:a1b2c3d4-...`)

The cache stores resolved breadcrumb objects. On folder rename or move events (emitted by BE-004 via the EventBus from BE-012), invalidate all cache entries that contain the affected folder ID. Implementation: iterate cache keys, delete entries where the key matches `folder:${affectedFolderId}` OR the cached breadcrumb array contains a segment with the affected folder's ID.

**If BE-012 is not yet implemented when this task is built:** Create the LRU cache and implement TTL-based expiration, but add a TODO comment for event-based invalidation: `// TODO: Subscribe to EventBus folder.renamed and folder.moved events (BE-012) to invalidate cache entries`. The cache will still function correctly via TTL expiration alone — event invalidation is an optimization.

## Acceptance Criteria

- Project breadcrumb returns single-element array with type 'project'
- Folder breadcrumb returns ordered ancestor chain from project root to current folder
- A folder 3 levels deep returns breadcrumb with 4 elements (project + 3 folders)
- Dataset breadcrumb appends dataset to its parent folder's breadcrumb
- Each segment includes id, name, type, and url fields
- Returns 400 for invalid type parameter (not project/folder/dataset)
- Returns 400 for malformed UUID
- Returns 404 for non-existent resource
- ?includeChildren=true returns breadcrumb array plus children object with folders and datasets arrays
- ?includeChildren=false (default) returns object with breadcrumb array and children: null
- Cached results bypass the database query on subsequent calls (verified via unit test that DB is not queried)
- Cache entries expire after 60 seconds
- Cache invalidates when a folder is renamed or moved
- 10-level deep paths use GIST index on folders.path (verified via EXPLAIN ANALYZE showing index scan)
