## Objective

Replace the existing `GET /health` endpoint (from BE-001, which returns a simple `{status: 'ok'}`) with four health-check endpoints that provide infrastructure-level health information. These endpoints support Kubernetes liveness/readiness probes and operational diagnostics. None of the four endpoints require authentication.

## Endpoints

### GET /health — Overall Health Status

Returns 200 if the system is healthy, 503 if any critical check fails.

```typescript
async healthCheck(req: Request, res: Response): Promise<void> {
  const dbHealthy = await this.checkDatabase();
  const diskHealthy = await this.checkDisk();

  const status = dbHealthy && diskHealthy ? 'healthy' : 'unhealthy';
  const statusCode = status === 'healthy' ? 200 : 503;

  res.status(statusCode).json({
    status,
    timestamp: new Date().toISOString(),
    uptime: process.uptime(),
    checks: {
      database: dbHealthy ? 'pass' : 'fail',
      disk: diskHealthy ? 'pass' : 'fail'
    }
  });
}
```

**Database check:** Execute `SELECT 1` with a 3-second timeout using `Promise.race`:

```typescript
async checkDatabase(): Promise<boolean> {
  try {
    await Promise.race([
      this.knex.raw('SELECT 1'),
      new Promise((_, reject) => setTimeout(() => reject(new Error('DB timeout')), 3000))
    ]);
    return true;
  } catch {
    return false;
  }
}
```

**Disk check:** Attempt to write and delete a temp file in the upload directory:

```typescript
async checkDisk(): Promise<boolean> {
  const tempFile = path.join(config.UPLOAD_DIR, `.health-check-${crypto.randomUUID()}.tmp`);
  try {
    await fs.promises.writeFile(tempFile, 'health check');
    await fs.promises.unlink(tempFile);
    return true;
  } catch {
    return false; // Both write failure AND delete failure are unhealthy
  }
}
```

If the write succeeds but the delete fails, the check returns `false` (unhealthy) — a filesystem that cannot delete files is problematic.

### GET /health/ready — Readiness Probe

Returns 200 only when the system is ready to accept traffic. Returns 503 with a reason if not ready.

Readiness conditions (ALL must pass):
1. Database pool has available connections: `this.knex.client.pool.numFree() > 0`
2. Upload directory is writable (same disk check as /health)

```json
// Ready
{ "ready": true }

// Not ready
{ "ready": false, "reason": "Database pool exhausted (0 free connections)" }
```

### GET /health/live — Liveness Probe

Always returns 200. No checks performed. This confirms the Node.js process is running and responding to HTTP requests.

```json
{ "alive": true }
```

Kubernetes uses this to detect crashed processes. Any check here risks false negatives that cause unnecessary pod restarts.

### GET /health/detailed — Diagnostic Information

Returns detailed system metrics. **Security note:** This endpoint is NOT behind auth middleware for simplicity in this project. In a production deployment, this should be restricted to internal network access or require an API key. A TODO comment in the code should note this.

```json
{
  "database": {
    "poolSize": 10,
    "available": 7,
    "pending": 0,
    "used": 3
  },
  "memory": {
    "heapUsedMB": 45.2,
    "heapTotalMB": 65.0,
    "rssMB": 82.1,
    "externalMB": 1.3
  },
  "disk": {
    "uploadDirExists": true,
    "uploadDirWritable": true
  },
  "uptime": 3600.5,
  "version": "1.0.0",
  "nodeVersion": "v20.11.0"
}
```

Memory values are in MB (divide bytes by 1048576, round to 1 decimal). Version is read from `package.json` at startup.

## Route Registration

Create `src/routes/health.ts` with all four endpoints. Register in `src/index.ts` BEFORE the authenticate middleware:

```typescript
app.use('/health', healthRouter); // No auth required
// ... then apply authenticate middleware to remaining routes
```

This replaces the simple inline `GET /health` from BE-001.

## Acceptance Criteria

- GET /health returns 200 with `{ status: 'healthy' }` when DB is up and disk is writable
- GET /health returns 503 with `{ status: 'unhealthy', checks: { database: 'fail' } }` when DB is down
- GET /health returns 503 when upload directory is not writable
- GET /health/ready returns 200 with `{ ready: true }` when DB pool has free connections
- GET /health/ready returns 503 with `{ ready: false, reason: '...' }` when DB pool is exhausted
- GET /health/live always returns 200 with `{ alive: true }` regardless of system state
- GET /health/detailed returns DB pool metrics (poolSize, available, used, pending)
- GET /health/detailed returns memory metrics in MB
- GET /health/detailed returns version from package.json
- None of the four endpoints require authentication (accessible without JWT)
- Database check has a 3-second timeout (does not hang if DB is unresponsive)
- Disk health check cleans up its temp file (no leftover `.health-check-*.tmp` files)
- The existing BE-001 inline `/health` route is replaced by this health router
- TODO comment in code notes that /health/detailed should be restricted in production
