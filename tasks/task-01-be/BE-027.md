## Objective

Create a content-based file detection service that validates uploaded files by inspecting the first 8KB of content rather than relying solely on file extensions. The service detects the delimiter, validates UTF-8 encoding, checks for binary content, verifies column consistency, and stores detection results in the dataset's `schema_info` JSONB. Integrate this service into the upload flow between file storage and database record creation.

## File Detection Service

Create `src/services/fileDetectionService.ts`:

```typescript
interface FileDetectionResult {
  isValid: boolean;
  delimiter: string | null;    // ',' | '\t' | ';' | null (if invalid)
  encoding: string;            // 'utf-8', 'latin1', etc.
  rejectionReason: string | null;
}

export async function detectFileType(filePath: string): Promise<FileDetectionResult>
```

### Step 1 — Read First 8KB

```typescript
const buffer = await readFirstBytes(filePath, 8192);
```

Use `fs.createReadStream` with `{ start: 0, end: 8191 }` and collect into a Buffer.

### Step 2 — Encoding Detection

Use the `chardet` npm package (install via `npm install chardet` and `npm install --save-dev @types/chardet`):

```typescript
const detectedEncoding = chardet.detect(buffer);
const confidence = chardet.analyse(buffer)?.[0]?.confidence ?? 0;
const encoding = confidence >= 50 ? (detectedEncoding || 'utf-8') : 'utf-8';
```

If `chardet`'s confidence is below 50%, default to `utf-8`. This avoids false positives from ambiguous byte sequences.

### Step 3 — Binary File Detection

Check for null bytes (0x00) in the buffer:

```typescript
if (buffer.includes(0x00)) {
  return { isValid: false, delimiter: null, encoding, rejectionReason: 'Binary file detected (contains null bytes)' };
}
```

This catches binary files (images, executables, Office documents) that have been renamed to `.csv`.

### Step 4 — Delimiter Auto-Detection

Convert the buffer to a string (using detected encoding) and split into the first 10 lines. For each candidate delimiter in order `[',', '\t', ';']`:

```typescript
function detectDelimiter(lines: string[]): { delimiter: string; consistency: number } | null {
  const candidates = [',', '\t', ';'];
  let bestDelimiter = null;
  let bestConsistency = 0;

  for (const delim of candidates) {
    const columnCounts = lines.map(line => line.split(delim).length);
    const mode = mostFrequent(columnCounts);
    const matchingRows = columnCounts.filter(c => c === mode).length;
    const consistency = matchingRows / columnCounts.length;

    if (consistency > bestConsistency) {
      bestConsistency = consistency;
      bestDelimiter = delim;
    }
    // On tie, prefer the earlier candidate (comma > tab > semicolon)
  }

  return bestDelimiter ? { delimiter: bestDelimiter, consistency: bestConsistency } : null;
}
```

If no delimiter produces a consistency score above 0.80 (80% of rows have the same column count), reject the file:

```typescript
if (!result || result.consistency < 0.80) {
  return { isValid: false, delimiter: null, encoding, rejectionReason: 'No consistent delimiter detected (columns vary across rows)' };
}
```

### Step 5 — Header Validation

Parse the first line (header row) using the detected delimiter. Validate that:
- Header has at least 1 column
- No column name is empty or whitespace-only after trimming
- No duplicate column names (case-insensitive comparison)

```typescript
const headers = lines[0].split(delimiter).map(h => h.trim());
const emptyHeaders = headers.filter(h => h.length === 0);
if (emptyHeaders.length > 0) {
  return { isValid: false, delimiter, encoding, rejectionReason: 'Header contains empty column names' };
}

const lowerHeaders = headers.map(h => h.toLowerCase());
const duplicates = lowerHeaders.filter((h, i) => lowerHeaders.indexOf(h) !== i);
if (duplicates.length > 0) {
  return { isValid: false, delimiter, encoding, rejectionReason: `Header contains duplicate column names: ${[...new Set(duplicates)].join(', ')}` };
}
```

### Return Valid Result

```typescript
return { isValid: true, delimiter, encoding, rejectionReason: null };
```

## Integration into Upload Flow

Modify `src/services/uploadService.ts` `processUpload()` method. After Multer saves the file but BEFORE the database INSERT:

```typescript
for (const file of files) {
  const detection = await detectFileType(file.path);
  if (!detection.isValid) {
    // Delete the saved file
    await fs.promises.unlink(file.path).catch(() => {});
    throw new AppError(415, detection.rejectionReason || 'File content does not match CSV format');
  }

  // Store detection metadata in schema_info
  const schemaInfo = { detection: { delimiter: detection.delimiter, encoding: detection.encoding } };

  const [dataset] = await trx('datasets').insert({
    name: datasetName,
    folder_id: folderId,
    file_path: file.path,
    original_filename: file.originalname,
    mime_type: file.mimetype || 'text/csv',
    file_size_bytes: file.size,
    status: 'pending',
    schema_info: JSON.stringify(schemaInfo)
  }).returning('*');
}
```

The CSV parsing service (BE-006) can later read `schema_info.detection.delimiter` to use the correct delimiter instead of defaulting to comma.

## Acceptance Criteria

- A valid comma-delimited CSV returns `{ isValid: true, delimiter: ',', encoding: 'utf-8' }`
- A valid tab-delimited TSV returns `{ isValid: true, delimiter: '\t', encoding: 'utf-8' }`
- A valid semicolon-delimited CSV returns `{ isValid: true, delimiter: ';', encoding: 'utf-8' }`
- A binary PNG file renamed to `.csv` is rejected with 415 and "Binary file detected"
- A binary Excel file (.xlsx) renamed to `.csv` is rejected with 415
- A file with inconsistent column counts (rows with 2, 3, 4 columns) is rejected with 415
- A file with empty header column names is rejected with 415 and "Header contains empty column names"
- A file with duplicate header column names is rejected with 415 listing the duplicates
- The `schema_info` JSONB on a successfully uploaded dataset contains `{ detection: { delimiter, encoding } }`
- When two delimiters tie in consistency, the earlier one wins (comma preferred over tab)
- Latin-1 encoded files are detected correctly (encoding field shows 'latin1' or 'ISO-8859-1')
- Files smaller than 8KB are fully read (no error from short files)
- Non-CSV uploads (.csv/.tsv/.txt) continue to work — detection runs for all three types
- Failed detection deletes the stored file before throwing (no orphaned files)
