# BE-015: Implement Column-Level Statistics and Data Profiling API

**Palantir Feature:** Data Ingestion — Foundry automatic data profiling (column-level statistics computed during CSV parsing)

## Reuse from Ontology Engine (Daily Tasks)

**Monday Task 27** already implements a statistics endpoint (`GET /api/v1/ontology/:ontologyId/objectTypes/:apiName/statistics`) that computes per-property statistics for object types using OpenSearch aggregations. It covers:
- Numeric stats: min, max, avg via OpenSearch `stats` aggregation
- Cardinality (distinct count) via `cardinality` aggregation
- Value distribution via `terms` aggregation (top values)
- Null counts via `missing` aggregation

**What to reuse vs. build new:**
- **REUSE** the response shape patterns from Monday Task 27 — the concept of per-field statistics with type-specific metrics translates directly
- **BUILD NEW** the streaming P-Square algorithm for median/percentiles (Monday Task 27 uses OpenSearch aggregations, not streaming algorithms), histogram bucket computation, and text-specific stats (minLength/maxLength/avgLength)
- **IMPROVE** Monday Task 27's statistics by adding the Welford's algorithm from BE-006 for more accurate streaming numeric stats without needing OpenSearch. These improvements can be backported to the ontology-engine for cases where OpenSearch is not available or for pre-index profiling

## Objective

Extend the CSV parsing service (from BE-006) to compute detailed per-column statistics during the initial parse job, and expose two GET endpoints to retrieve the computed statistics. All statistics are computed in a single streaming pass alongside the existing type inference — no additional file reads are required. Statistics are stored in the existing `dataset_columns.sample_values` JSONB column.

## Extended ColumnAccumulator Statistics

Modify the `ColumnAccumulator` class in `src/services/csvParsingService.ts` to compute additional statistics based on the inferred column type:

### Numeric Columns (integer, numeric)
- `min`, `max` — already computed via Welford's (BE-006)
- `mean`, `stddev` — already computed via Welford's (BE-006)
- `median` — approximate using the P-Square algorithm (described below)
- `percentiles` — 25th, 50th, 75th via three independent P-Square estimators
- `histogram` — 10 equal-width buckets computed after the streaming pass completes, using `min` and `max` to determine bucket boundaries: `bucketWidth = (max - min) / 10`. Each bucket: `{ low: number, high: number, count: number }`. Values exactly on a boundary go into the lower bucket (except the last bucket which is inclusive of max).

### Text Columns
- `minLength`, `maxLength` — track min/max of `value.length` for non-null values
- `avgLength` — `totalLength / nonNullCount` rounded to 2 decimal places
- `topValues` — 10 most frequent values. Maintain a `Map<string, number>` frequency counter capped at 1000 distinct entries. After parsing, sort by count descending and take the first 10: `[{ value: string, count: number, percentage: number }]`
- `uniqueRatio` — `distinctValues.size / nonNullCount` rounded to 4 decimal places

### Date/Timestamp Columns
- `minDate`, `maxDate` — earliest and latest date values as ISO strings
- `rangeInDays` — `Math.round((maxDate - minDate) / (1000*60*60*24))`
- `monthlyDistribution` — `Map<string, number>` keyed by `YYYY-MM`, counting values per month. Return as array: `[{ month: 'YYYY-MM', count: number }]` sorted chronologically.

### Boolean Columns
- `trueCount` — count of values matching true/yes/1/t/y (case-insensitive)
- `falseCount` — count of values matching false/no/0/f/n (case-insensitive)
- `nullCount` — already tracked (BE-006)
- `truePercentage` — `Math.round((trueCount / (trueCount + falseCount)) * 10000) / 100` (2 decimal places, excludes nulls from denominator)

## P-Square Algorithm for Streaming Median

The P-Square algorithm estimates quantiles in a single pass with O(1) memory. Implementation:

```typescript
class PSquareEstimator {
  private n: number[] = [1, 2, 3, 4, 5]; // marker positions
  private q: number[] = [];               // marker heights (quantile estimates)
  private dn: number[];                   // desired marker positions
  private count = 0;
  private p: number;                      // target quantile (e.g., 0.5 for median)

  constructor(quantile: number) {
    this.p = quantile;
    this.dn = [0, quantile / 2, quantile, (1 + quantile) / 2, 1];
  }

  addValue(x: number): void {
    this.count++;
    if (this.count <= 5) {
      this.q.push(x);
      if (this.count === 5) {
        this.q.sort((a, b) => a - b);
      }
      return;
    }
    // Standard P-Square update logic
    // ... (full algorithm adjusts markers using piecewise parabolic interpolation)
  }

  getEstimate(): number {
    if (this.count < 5) {
      const sorted = [...this.q].sort((a, b) => a - b);
      const idx = Math.floor(this.p * (sorted.length - 1));
      return sorted[idx];
    }
    return this.q[2]; // Middle marker is the quantile estimate
  }
}
```

Create three estimators per numeric column: one for p=0.25, one for p=0.50 (median), one for p=0.75. The median estimate is acceptable if within 5% of the actual median for datasets with 1000+ rows.

**Alternative:** If P-Square proves too complex, use the simpler "random sample + sort" approach: maintain a reservoir sample of 10,000 values (Algorithm R), then sort the sample and pick percentile indices. This is less memory-efficient but simpler and equally accurate for large datasets.

## JSONB Storage Schema

The `sample_values` JSONB column in `dataset_columns` stores all statistics. The structure extends the BE-006 format:

```json
{
  "samples": ["value1", "value2", "value3", "value4", "value5"],
  "nullCount": 42,
  "distinctCount": 850,
  "stats": {
    "type": "numeric",
    "min": 1.5,
    "max": 999.99,
    "mean": 152.34,
    "stddev": 87.21,
    "median": 134.50,
    "percentiles": { "p25": 78.0, "p50": 134.50, "p75": 210.0 },
    "histogram": [
      { "low": 1.5, "high": 101.35, "count": 2400 },
      { "low": 101.35, "high": 201.19, "count": 3100 }
    ]
  }
}
```

For text columns, `stats.type` is `"text"` with fields `minLength`, `maxLength`, `avgLength`, `topValues`, `uniqueRatio`. For date columns, `stats.type` is `"date"` with `minDate`, `maxDate`, `rangeInDays`, `monthlyDistribution`. For boolean columns, `stats.type` is `"boolean"` with `trueCount`, `falseCount`, `truePercentage`.

## Statistics Endpoints

### Single Column Statistics

`GET /api/v1/datasets/:datasetId/columns/:columnName/stats`

1. Query: `SELECT sample_values FROM dataset_columns WHERE dataset_id = $1 AND column_name = $2`. Return 404 if not found.
2. Parse the JSONB and return the `stats` object.
3. Return 409 if dataset status is not `ready`.

Response (example for numeric column):
```json
{
  "columnName": "price",
  "columnType": "numeric",
  "nullable": true,
  "nullCount": 42,
  "distinctCount": 850,
  "stats": { "min": 1.5, "max": 999.99, "mean": 152.34, "stddev": 87.21, "median": 134.50, "percentiles": { "p25": 78.0, "p50": 134.50, "p75": 210.0 }, "histogram": [...] }
}
```

### Full Dataset Profile

`GET /api/v1/datasets/:datasetId/profile`

1. Query: `SELECT column_name, column_type, nullable, sample_values FROM dataset_columns WHERE dataset_id = $1 ORDER BY ordinal_position`.
2. Return 409 if dataset status is not `ready`. Return 404 if dataset not found.

Response:
```json
{
  "datasetId": "...",
  "rowCount": 10000,
  "columnCount": 6,
  "columns": [
    { "columnName": "order_id", "columnType": "text", "nullable": false, "stats": { "type": "text", ... } },
    { "columnName": "amount", "columnType": "numeric", "nullable": true, "stats": { "type": "numeric", ... } }
  ]
}
```

## Acceptance Criteria

- Numeric columns: min, max, mean, stddev computed correctly (verified against known test data)
- Numeric columns: median estimate within 5% of actual median for datasets with 1000+ rows
- Numeric columns: 25th, 50th, 75th percentiles computed
- Numeric columns: histogram has exactly 10 buckets with correct count distribution
- Text columns: minLength, maxLength, avgLength computed correctly
- Text columns: topValues returns the 10 most frequent values with counts and percentages
- Text columns: uniqueRatio is correct (distinct/total, rounded to 4 decimal places)
- Date columns: minDate and maxDate are correct ISO strings
- Date columns: rangeInDays is correct integer
- Date columns: monthlyDistribution is sorted chronologically
- Boolean columns: trueCount, falseCount, truePercentage computed correctly
- GET /api/v1/datasets/:id/columns/:col/stats returns stats for a single column
- GET /api/v1/datasets/:id/profile returns stats for all columns ordered by ordinal_position
- Both endpoints return 404 for non-existent dataset or column
- Both endpoints return 409 if dataset status is not 'ready'
- Statistics stored in dataset_columns.sample_values JSONB without overwriting existing samples/nullCount/distinctCount
- All statistics computed during initial parse job — no additional file reads
