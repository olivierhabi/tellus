## Description

Two pinned copies of **`brace-expansion`** (versions **`1.1.12`** and **`2.1.0`**, both via `duckdb`'s install chain) are affected by CVE-2026-13149: exponential-time complexity on crafted brace patterns causes a denial of service in `expand()`. Fixed in `1.1.16` / `2.1.2` / `5.0.7`. The package resolves via `minimatch` under `glob`, reached through `duckdb`'s `node-gyp`/`make-fetch-happen` build chain and `@mapbox/node-pre-gyp`.

## Evidence

**Advisory evidence:** `CVE-2026-13149` applies to `brace-expansion` at installed version `1.1.12`. The advisory is fixed in `1.1.16`.

**Transitive dependency:** introduced by the direct dependency `duckdb@1.4.4`.

**Dependency chain:** `duckdb@1.4.4 > node-gyp@9.4.1 > glob@7.2.3 > minimatch@3.1.5 > brace-expansion@1.1.12`

**Usage analysis:** imported by application code; affected API usage unconfirmed. No direct `brace-expansion` import in application code. Two pinned copies (`1.1.12` via `glob@7.2.3 > minimatch@3.1.5`, and `2.1.0` via `cacache@16.1.3 > glob@8.1.0 > minimatch@5.1.9`) both roll up to the direct dep `duckdb@1.4.4`. `duckdb` is required in src/services/furnaceSqlService.ts:55 and src/services/duckdb/pool.ts:49. Affected-symbol (`expand`) check inside minimatch was not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

A crafted brace pattern triggers exponential-time `expand()`, causing CPU-exhaustion DoS. Reached through the duckdb native build/fetch toolchain (`node-gyp`/`minimatch`), i.e. at build/install time rather than request-handling time. Availability impact.

## Technical Analysis

**Root cause:** exponential time in `expand()` on adversarial patterns (node-tar/minimatch family). **Two lockfile copies, same CVE:** `brace-expansion@1.1.12` (duckdb > node-gyp > glob@7 > minimatch@3) and `brace-expansion@2.1.0` (duckdb > node-gyp > make-fetch-happen > cacache > glob@8 > minimatch@5). **Trivy:** Severity=HIGH, CVSS 7.5 (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H), CWE-407.

## Remediation

Resolve both copies: `pnpm.overrides: { "brace-expansion@<1.1.16": "^1.1.16", "brace-expansion@>=2.0.0 <2.1.2": "^2.1.2" }` in `package.json`, then `pnpm install` and verify with `trivy fs pnpm-lock.yaml`. Alternatively bump `duckdb` to a release whose build closure picks fixed versions.
