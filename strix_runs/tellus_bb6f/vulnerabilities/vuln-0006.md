## Description

The transitive package **`fast-uri@3.1.2`** (pinned via `pnpm-lock.yaml` through `ajv`) is affected by CVE-2026-18446: fast-uri requires a literal `//` to recognize a URI authority, so a reference that uses a backslash-based introducer (`\\`, `\/`, `/\`) is parsed with **no authority and folds into the path**, whereas Node's WHATWG parser treats `\` as interchangeable with `/` and still extracts the authority caller-provided data. Validated origin and fetched origin diverge. Fixed in `3.1.5` / `4.1.2` / `2.4.4`. References include upstream fix commit `fastify/fast-uri@f3c6c90`.

## Impact

Host-confusion: an attacker URL that fast-uri validates against one origin (or as relative) is fetched by Node's network stack as belonging to a different, attacker-chosen host. This can defeat SSRF/origin host allowlists enforced through any ajv/fast-uri-based validation, with Integrity impact.

## Technical Analysis

**Root cause:** fast-uri < 3.1.5 / 4.1.2 / 2.4.4 requires literal `//` for an authority; a `\`-introduced authority is folded into the path, but the WHATWG parser keeps the authority. Validation and resolution disagree on the effective host.

**Dependency chain (`pnpm-lock.yaml`):** `ajv@8.18.0 > fast-uri@3.1.2`. `ajv@8.18.0` direct in `package.json`; used at `src/services/workshop/validator.ts:48`.
