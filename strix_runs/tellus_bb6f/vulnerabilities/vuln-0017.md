## Description

The transitive package **`tar@7.5.13`** (via `duckdb`'s `@mapbox/node-pre-gyp`) is affected by CVE-2026-59874: a malformed tar archive header triggers denial of service. Fixed in `7.5.18`. One of four distinct tar DoS CVEs on this pinned copy.

## Evidence

**Advisory evidence:** `CVE-2026-59874` applies to `tar` at installed version `7.5.13`. The advisory is fixed in `7.5.18`.

**Transitive dependency:** introduced by the direct dependency `duckdb@1.4.4`.

**Dependency chain:** `duckdb@1.4.4 > @mapbox/node-pre-gyp@2.0.3 > tar@7.5.13`

**Usage analysis:** imported by application code; affected API usage unconfirmed. No direct `tar` import; reached only through duckdb > @mapbox/node-pre-gyp (src/services/furnaceSqlService.ts:55, src/services/duckdb/pool.ts:49 require duckdb). Affected-symbol check was not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

Malformed tar header causes process-level DoS during archive parse/extract in the `duckdb` native-binary fetch path. Availability only.

## Technical Analysis

**Root cause:** malformed tar header handling DoS in node-tar < 7.5.18.
**Chain:** `duckdb@1.4.4 > @mapbox/node-pre-gyp@2.0.3 > tar@7.5.13` (direct dep `duckdb@1.4.4`; binary-fetch layer uses tar to unpack the prebuilt binding).
**Trivy:** Severity=HIGH, CVSS ghsa:7.5 (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H).

## Remediation

Resolve `tar@>=7.5.21` via `pnpm.overrides: { "tar@<7.5.21": "^7.5.21" }` (also clears CVE-2026-59873, -59871, -59875) or bump `duckdb`, regenerate lockfile, verify with `trivy fs pnpm-lock.yaml`.

## Assumptions

Advisory from trivy-vendored GHSA; web_search unavailable. Reachability `imported`; tar is exercised inside duckdb's binary fetch/extract. Trivy DB fresh (2026-08-18).
