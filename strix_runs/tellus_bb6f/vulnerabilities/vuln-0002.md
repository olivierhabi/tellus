## Description

The transitive package **`ip-address@10.1.0`** (pinned via `pnpm-lock.yaml`) is affected by CVE-2026-42338: `Address6.group()`, `Address6.link()`, and one branch of `AddressError.parseMessage` embed attacker-controlled content into HTML strings without HTML-escaping it, producing XSS wherever those outputs are rendered in a browser. Fixed in `10.1.1`. References include the upstream repository and Red Hat CVE advisory.

## Evidence

**Advisory evidence:** `CVE-2026-42338` applies to `ip-address` at installed version `10.1.0`. The advisory is fixed in `10.1.1`.

**Transitive dependency:** introduced by the direct dependency `@kubernetes/client-node@1.4.0`.

**Dependency chain:** `@kubernetes/client-node@1.4.0 > socks-proxy-agent@8.0.5 > socks@2.8.7 > ip-address@10.1.0`

**Usage analysis:** imported by application code; affected API usage unconfirmed. Direct import search for `ip-address` returned no matches in `src/` or `scripts/` (`rg -n "require\(['\"]ip-address|from ['\"]ip-address"` across `--type ts`). The package is reached transitively via `@kubernetes/client-node` (dynamic `await import("@kubernetes/client-node")` in src/services/pipelines/udfRunner.ts:56 and src/services/orchestration/runners/k8s-runtime.ts:61). The affected-symbol check (`Address6.group`, `Address6.link`, `AddressError.parseMessage`) inside the k8s client chain was not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

If any HTML-rendered output (error page, admin network diagnostic view, cluster tooling UI) includes `Address6.group()/link()` results or `AddressError.parseMessage` for an attacker-controlled address string, script executes in the victim's browser, enabling session hijacking and defacement. User interaction is required (a victim must view the rendered output).
