## Description

The transitive package **`tar@7.5.13`** (via `duckdb`'s `@mapbox/node-pre-gyp`) is affected by CVE-2026-53655: node-tar applies a PAX extended header's `size=` record (and other PAX overrides) to the next header entry of ANY type, including intermediary metadata headers such as GNU long-name (`L`) or long-link (`K`) entries. Per POSIX pax, a PAX header describes the next FILE entry, not the intermediary extension headers — so a specifically-crafted archive can smuggle file content past archive-scanning or produce inconsistent extraction. Fixed in `7.5.16`. This is an integrity (file-smuggling) issue, not just DoS.

## Impact

An attacker-supplied tar archive can have a file's contents silently attributed to the wrong entry / extracted under a smuggled name, letting crafted content slip past archive-inspection or integrity checks. Local extraction with a victim needing to consume the archive (UI:R), confidentiality low + integrity high.

## Technical Analysis

**Root cause:** node-tar < 7.5.16 applies PAX `size=`/overrides to the next header of any type (including GNU `L`/`K` intermediary headers) instead of only the next file entry, producing parser-differential "file smuggling". **Chain:** `duckdb@1.4.4 > @mapbox/node-pre-gyp@2.0.3 > tar@7.5.13`. **Trivy:** Severity=MEDIUM, CVSS redhat:6.1 (CVSS:3.1/AV:L/AC:L/PR:N/UI:R/S:U/C:L/I:H/A:N), CWE-436.
