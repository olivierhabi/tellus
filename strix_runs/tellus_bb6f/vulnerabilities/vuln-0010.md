## Description

The transitive package **`fast-xml-parser@5.4.1`** (pinned via `pnpm-lock.yaml` through `@aws-sdk/client-s3`) is affected by CVE-2026-33036: numeric character references (`&#NNN;`, `&#xHH;`) and standard XML entities completely evade the entity-expansion limits (`maxTotalExpansions`, `maxExpandedLength`) added to fix the earlier CVE-2026-26278, re-enabling entity-expansion (billion-laughs) denial of service. Fixed in `5.5.6` / `4.5.5`. The package is also already pinned under a project `pnpm.overrides` rule (`fast-xml-parser@<5.4.1: 5.4.1`), showing the team actively manages this package.

## Evidence

**Advisory evidence:** `CVE-2026-33036` applies to `fast-xml-parser` at installed version `5.4.1`. The advisory is fixed in `5.5.6`.

**Transitive dependency:** introduced by the direct dependency `@aws-sdk/client-s3@3.1010.0`.

**Dependency chain:** `@aws-sdk/client-s3@3.1010.0 > @aws-sdk/core@3.973.20 > @aws-sdk/xml-builder@3.972.11 > fast-xml-parser@5.4.1`

**Usage analysis:** imported by application code; affected API usage unconfirmed. No application code imports `fast-xml-parser` directly (`rg -n "require\(['\"]fast-xml-parser|from ['\"]fast-xml-parser"` over `--type ts` on src/ returned no hits). Reached via `@aws-sdk/client-s3` (direct dep, used by S3 storage code throughout `src/services`). The app's `package.json` already has `pnpm.overrides` forcing `fast-xml-parser@<5.4.1 → 5.4.1`, confirming the team actively pins this package. Affected-symbol (parser entity-handling) check inside the AWS SDK chain was not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

A crafted XML document (entity expansion) parsed through the AWS SDK's XML builder can cause unbounded memory/CPU consumption despite the supposed expansion limits, hanging the event loop. Availability impact only; reachable when the S3 client parses XML responses.

## Technical Analysis

**Root cause:** fast-xml-parser 4.0.0-beta.3 through 5.5.5 — the expansion-limit guards added for CVE-2026-26278 are bypassed by numeric character references and standard entities, restoring entity-expansion DoS.

## Remediation

The package is transitive AND already behind a `pnpm.overrides` pin, so update the override ceiling:
1. Edit `package.json` `pnpm.overrides` to raise the floor/ceiling: `"fast-xml-parser@<5.5.6": "5.5.6"` (or widen to also bump 4.x: `"fast-xml-parser@>=4.0.0 <5.5.6": "5.5.6"` and keep a `4.5.5` pin if any consumer is locked to 4.x).
2. `pnpm install` to regenerate `pnpm-lock.yaml`.
3. Confirm with `trivy fs pnpm-lock.yaml` that all `fast-xml-parser` copies are at fixed versions (≥5.5.6 / ≥4.5.5). Alternatively bump `@aws-sdk/client-s3` to a release whose closure resolves a fixed fast-xml-parser.
