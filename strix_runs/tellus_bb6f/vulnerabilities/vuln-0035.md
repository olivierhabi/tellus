## Description

The transitive package **`@opentelemetry/propagator-jaeger@2.7.1`** (pinned via `pnpm-lock.yaml`) is affected by CVE-2026-59892: `uber-trace-id` and `uberctx-*` HTTP header values are decoded with `decodeURIComponent()` without handling decode errors, so an **unauthenticated remote attacker** can send a malformed percent-encoded value that throws an uncaught `URIError` and terminates the Node.js process. This is a remotely triggerable DoS with no preconditions — the most directly attacker-relevant of the dependency findings. Fixed in `2.9.0`.

## Evidence

**Advisory evidence:** `CVE-2026-59892` applies to `@opentelemetry/propagator-jaeger` at installed version `2.7.1`. The advisory is fixed in `2.9.0`.

**Usage analysis:** imported by application code; affected API usage unconfirmed. No direct import of `@opentelemetry/propagator-jaeger` in application code; it is pulled into the process by the OpenTelemetry SDK (`src/otelBootstrap.ts` boots the telemetry SDK for the Express API). Whether the jaeger propagator is the *configured* propagator for incoming headers was not confirmed; affected-symbol (header extraction) check not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

An unauthenticated remote client sends a malformed `uber-trace-id` / `uberctx-*` header; the propagator throws an uncaught `URIError` that terminates the Node.js process — a reliable remote DoS of the API server.

## Technical Analysis

**Root cause:** uncaught `URIError` from `decodeURIComponent` on malformed incoming trace headers. **Package:** `@opentelemetry/propagator-jaeger@2.7.1`, exercises the incoming-request path (unauthenticated). **Trivy:** Severity=HIGH, CVSS ghsa:7.5 (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:H), CWE-248.

## Remediation

Resolve `@opentelemetry/propagator-jaeger@>=2.9.0` by bumping `@opentelemetry/auto-instrumentations-node` / `@opentelemetry/sdk-node`, or `pnpm.overrides: { "@opentelemetry/propagator-jaeger@<2.9.0": "^2.9.0" }`. Regenerate lockfile, verify with `trivy fs pnpm-lock.yaml`.
