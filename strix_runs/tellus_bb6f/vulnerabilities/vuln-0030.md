## Description

Two pinned copies of **`brace-expansion`** (`1.1.12` and `2.1.0`) are affected by CVE-2026-14257: memory exhaustion in the `expand()` function on crafted patterns. Fixed in `1.1.17` / `2.1.3` / `3.0.3` / `5.0.8`. Reached via `minimatch` under `glob`, through `duckdb`'s build chain.

## Evidence

**Advisory evidence:** `CVE-2026-14257` applies to `brace-expansion` at installed version `1.1.12`. The advisory is fixed in `1.1.17`.

**Transitive dependency:** introduced by the direct dependency `duckdb@1.4.4`.

**Dependency chain:** `duckdb@1.4.4 > node-gyp@9.4.1 > glob@7.2.3 > minimatch@3.1.5 > brace-expansion@1.1.12`

**Usage analysis:** imported by application code; affected API usage unconfirmed. No direct import; two pinned copies (1.1.12 + 2.1.0) both roll up to direct dep `duckdb@1.4.4` (required at src/services/furnaceSqlService.ts:55, src/services/duckdb/pool.ts:49). Affected-symbol check not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

Memory exhaustion in `expand()` on adversarial brace patterns, in the duckdb native build/fetch toolchain path. Availability impact.

## Technical Analysis

**Root cause:** memory exhaustion in `expand()` < fixed lines. **Copies:** 1.1.12 (glob@7/minimatch@3) and 2.1.0 (cacache/glob@8/minimatch@5), both under duckdb's node-gyp/make-fetch-happen chain. **Trivy:** Severity=HIGH, CVSS 7.5.

`pnpm.overrides` for both majors: `"brace-expansion@<1.1.18": "^1.1.18"` and `"brace-expansion@>=2.0.0 <2.1.4": "^2.1.4"` (covers all four brace-expansion CVEs), then `pnpm install` and verify.
