# Unauthenticated Prometheus metrics endpoints leak operational and object-type data

**ID:** vuln-0021
**Severity:** MEDIUM
**Found:** 2026-08-18 06:42:44 UTC
**Target:** http://host.docker.internal:3000
**Endpoint:** /api/metrics
**Method:** GET
**CWE:** CWE-200
**CVSS:** 5.3
**Fix Effort:** Low

## Description

Three Prometheus scrape endpoints — `GET /api/metrics`, `GET /api/v1/pipelines/metrics`, and `GET /api/v1/funnel/metrics` — are reachable without authentication and expose operational internals: egress-guard block reasons, connection-pool gauges, per-route RED latency series, queue depths, lag and failure counters, and high-cardinality labels that name production object types (e.g. `QaRwBkLoanApplications`). The code assumes network isolation that does not exist in this deployment.

## Evidence

All three endpoints return 200 unauthenticated (30 KB, 6.6 KB, 7.5 KB of exposition). Representative series:

```text
tellus_sql_query_duration_seconds{object_type="QaRwBkLoanApplications",...}
funnel_dispatch_pending_age_seconds{...}
pipeline_health_check_failures_total{...}
tellus_index_name_missing_tenant_total{...}
# connectivity pool gauges, egress-guard block-reason counters,
# route-level http request duration series for /api/v1/connectivity/connections, ...
```

Metric-family names enumerate internal subsystems: `quiver`, `workshop`, `funnel`, `connectivity`, `compass`, `indexing`. Root cause: allowlist at `src/middleware/globalAuth.ts:150-152` (justification comment `:36-38` assumes network isolation); unguarded handlers at `src/server.ts:731`, `src/routes/pipelinesMetrics.ts:15`, `src/routes/funnel.ts:385`.

## Impact

An unauthenticated attacker gains a live operational view of the platform: which subsystems exist and how heavily they are used, egress-guard blocking policy and trigger counts, connection-pool sizing/integration topology, per-endpoint latency profiles (useful for attack tuning and resource-exhaustion targeting), queue depths and failure rates, and labels that name production business object types (e.g. banking loan applications) together with their query volumes. This is restricted internal telemetry that profiles both the stack and hosted business data categories; no control-plane action was performed.

## Technical Analysis

The global auth middleware explicitly allowlists all three paths, on the documented assumption that network isolation — not JWT — protects scrape targets:

```typescript title=src/middleware/globalAuth.ts startLineNumber=149 endLineNumber=152
  // Prometheus scrape targets.
  if (p === "/api/metrics") return true;
  if (p === "/api/v1/pipelines/metrics") return true;
  if (p === "/api/v1/funnel/metrics") return true;
```

The header comment at `src/middleware/globalAuth.ts:36-38` states: *"Scrape targets are internal-only (network isolation, not JWT)."* In this deployment the app listens on port 3000 with no such isolation, so any client that can reach the port scrapes them.

The handlers carry no auth of their own:

```typescript title=src/server.ts startLineNumber=731 endLineNumber=737
app.get("/api/metrics", async (_req: Request, res: Response) => {
  try {
    const prom = (await import("prom-client")) as unknown as {
      register: { metrics(): Promise<string>; contentType: string };
    };
    res.setHeader("Content-Type", prom.register.contentType);
    res.send(await prom.register.metrics());
```

```typescript title=src/routes/pipelinesMetrics.ts startLineNumber=15 endLineNumber=19
router.get("/metrics", (_req: Request, res: Response) => {
  res
    .status(200)
    .setHeader("content-type", "text/plain; version=0.0.4; charset=utf-8")
    .send(renderPrometheus());
```

mounted at `src/server.ts:1158` (`app.use("/api/v1/pipelines", pipelinesMetricsRouter)`) and `src/server.ts:1319` (`app.use("/api/v1/funnel", funnelRouter)`; the funnel router's `GET /metrics` handler at `src/routes/funnel.ts:385` is documented in-code as "deliberately unauthenticated for Prometheus scraping").

The exposed series go beyond coarse health: per-route RED latency metrics enumerate API paths and relative traffic, egress-guard counters reveal blocked-destination policies, connectivity pool gauges reveal integration topology, and labels such as `object_type="QaRwBkLoanApplications"` name production business object types and their query volumes.

## Proof of Concept

1. Send unauthenticated GET requests to `/api/metrics`, `/api/v1/pipelines/metrics`, and `/api/v1/funnel/metrics`.
2. Observe 200 Prometheus text-format responses (30 KB, 6.6 KB, 7.5 KB respectively) containing internal metric names, egress-guard counters, route latency series, queue/failure metrics, and object-type labels naming production business entities.

```bash
for p in /api/metrics /api/v1/pipelines/metrics /api/v1/funnel/metrics; do
  echo "== $p"; curl -s http://host.docker.internal:3000$p | grep -v '^#' | head -20
done
```

## Code Analysis

**Location 1:** `src/middleware/globalAuth.ts` (lines 149-152)
  Remove metrics paths from the unauthenticated allowlist
  ```
    // Prometheus scrape targets.
    if (p === "/api/metrics") return true;
    if (p === "/api/v1/pipelines/metrics") return true;
    if (p === "/api/v1/funnel/metrics") return true;
  ```

  **Suggested Fix:**
```diff
-   // Prometheus scrape targets.
-   if (p === "/api/metrics") return true;
-   if (p === "/api/v1/pipelines/metrics") return true;
-   if (p === "/api/v1/funnel/metrics") return true;
+   // Prometheus scrape targets: require the dedicated scrape-token
+   // middleware on each handler instead of an unauthenticated allowlist
+   // entry; network isolation is an additional control, not the only one.
+   if (p === "/api/metrics") return false;
+   if (p === "/api/v1/pipelines/metrics") return false;
+   if (p === "/api/v1/funnel/metrics") return false;
```

## Remediation

1. Authenticate the scrape endpoints: accept a static bearer token (e.g. a `PROMETHEUS_SCRAPE_TOKEN` env value checked in a small middleware) or route them through globalAuth with a dedicated scrape principal.
2. Remove the three paths from the globalAuth unauthenticated allowlist.
3. Reduce label cardinality and identifiability: replace `object_type` name labels with opaque identifiers (or drop them), and stop exporting per-route latency series with full path labels that enumerate the API surface.
4. Document that network isolation is an additional control, never the sole one, for metrics exposure.

## Assumptions

Assumes the deployment does not enforce network-level isolation on these paths (true in the tested environment; the application itself provides no fallback control).
