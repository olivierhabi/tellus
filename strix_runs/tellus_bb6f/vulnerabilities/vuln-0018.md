## Description

The transitive package **`tar@7.5.13`** (via `duckdb`'s `@mapbox/node-pre-gyp`) is affected by CVE-2026-59871: incorrect PAX path handling causes denial of service. Fixed in `7.5.18`.

## Evidence

**Advisory evidence:** `CVE-2026-59871` applies to `tar` at installed version `7.5.13`. The advisory is fixed in `7.5.18`.

**Transitive dependency:** introduced by the direct dependency `duckdb@1.4.4`.

**Dependency chain:** `duckdb@1.4.4 > @mapbox/node-pre-gyp@2.0.3 > tar@7.5.13`

**Usage analysis:** imported by application code; affected API usage unconfirmed. No direct `tar` import; reached only through duckdb > @mapbox/node-pre-gyp (src/services/furnaceSqlService.ts:55, src/services/duckdb/pool.ts:49 require duckdb). Affected-symbol check not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

Incorrect PAX path handling during tar extraction causes process DoS in the duckdb binary-fetch path. Availability only.

## Technical Analysis

**Root cause:** PAX path handling DoS in node-tar < 7.5.18. **Chain:** `duckdb@1.4.4 > @mapbox/node-pre-gyp@2.0.3 > tar@7.5.13`. **Trivy:** Severity=HIGH, CVSS ghsa:7.5.

## Remediation

Resolve `tar@>=7.5.21` via `pnpm.overrides: { "tar@<7.5.21": "^7.5.21" }` or bump `duckdb`; regenerate lockfile; verify with `trivy fs pnpm-lock.yaml`.
