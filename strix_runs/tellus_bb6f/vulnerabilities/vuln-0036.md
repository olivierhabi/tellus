**Fix Effort:** Low

## Description

The transitive package **`@opentelemetry/core`** (two pinned copies: `2.7.0` and `2.7.1`, via `pnpm-lock.yaml`) is affected by CVE-2026-54285: oversized span/log attributes cause a denial of service. Fixed in `2.8.0`.

## Evidence

**Advisory evidence:** `CVE-2026-54285` applies to `@opentelemetry/core` at installed version `2.7.1`. The advisory is fixed in `2.8.0`.

**Transitive dependency:** introduced by the direct dependency `@opentelemetry/sdk-node@0.218.0`.

**Dependency chain:** `@opentelemetry/sdk-node@0.218.0 > @opentelemetry/core@2.7.1`

**Usage analysis:** imported by application code; affected API usage unconfirmed. No direct import of `@opentelemetry/core` in application code; via `@opentelemetry/sdk-node` (booted in src/otelBootstrap.ts). Affected-symbol check not performed. Two lockfile copies (2.7.0 and 2.7.1) covered in one report per the one-CVE-per-package rule. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

Oversized attributes cause low-severity DoS in the OpenTelemetry core used by the API's telemetry bootstrap.

## Technical Analysis

**Root cause:** oversized attributes DoS in `@opentelemetry/core` < 2.8.0. **Copies:** 2.7.0 and 2.7.1 under the sdk-node chain (src/otelBootstrap.ts boots the SDK). **Trivy:** Severity=MEDIUM, CVSS 5.3.

## Remediation

Resolve `@opentelemetry/core@>=2.8.0` via `@opentelemetry/sdk-node` bump or `pnpm.overrides`; regenerate lockfile; verify with `trivy fs pnpm-lock.yaml`.

Advisory from trivy-vendored GHSA; web_search unavailable. Reachability `imported`. Trivy DB fresh (2026-08-18).
