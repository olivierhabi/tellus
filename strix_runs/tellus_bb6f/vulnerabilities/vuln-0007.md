## Description

The transitive package **`js-yaml@4.2.0`** (pinned via `pnpm-lock.yaml` through `@kubernetes/client-node`) is affected by CVE-2026-59869: parsing a YAML document whose chain of mappings uses merge keys where each mapping merges the previous one costs **quadratic CPU** in the document size, enabling a small crafted document to cause a denial of service. Fixed in `3.15.0` / `4.3.0`. Advisory GHSA/NVD record references the upstream parser.

## Evidence

**Advisory evidence:** `CVE-2026-59869` applies to `js-yaml` at installed version `4.2.0`. The advisory is fixed in `4.3.0`.

**Transitive dependency:** introduced by the direct dependency `@kubernetes/client-node@1.4.0`.

**Dependency chain:** `@kubernetes/client-node@1.4.0 > js-yaml@4.2.0`

**Usage analysis:** imported by application code; affected API usage unconfirmed. No application code imports `js-yaml` directly (`rg -n "require\(['\"]js-yaml|from ['\"]js-yaml"` over `--type ts` on src/ and scripts/ returned no hits). Reached transitively via `@kubernetes/client-node` (dynamic `await import` at src/services/pipelines/udfRunner.ts:56, src/services/orchestration/runners/k8s-runtime.ts:61). Affected-symbol (`load` of attacker-controlled YAML) check inside the k8s client was not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

A crafted YAML document processed through the `@kubernetes/client-node` config/manifest parsing path can consume CPU quadratic in input length, hanging the Node.js event loop and denying service. Availability impact only; requires the attacker to reach a YAML-parsing surface.

## Technical Analysis

**Root cause:** js-yaml ≤ 4.2.0 (4.x) / 3.x merge-key resolution has an algorithmic-complexity flaw producing O(n²) CPU on adversarial documents.

**Dependency chain (`pnpm-lock.yaml`):**
```
@kubernetes/client-node@1.4.0(encoding@0.1.13) > js-yaml@4.2.0
```
The direct dep `@kubernetes/client-node` is confirmed in `package.json` and lazy-loaded in the k8s runtime paths.

## Remediation

1. Bump the direct dependency `@kubernetes/client-node` in `package.json` to a version whose closure resolves `js-yaml@>=4.3.0`, then `pnpm install`.
2. If needed, force resolution: `pnpm.overrides: { "js-yaml@<4.3.0": "^4.3.0" }`.
3. Commit lockfile, verify with `trivy fs pnpm-lock.yaml`.
