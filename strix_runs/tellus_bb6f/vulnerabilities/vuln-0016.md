# Unauthenticated full OpenAPI specification exposes superadmin API surface

**ID:** vuln-0016
**Severity:** MEDIUM
**Found:** 2026-08-18 06:41:10 UTC
**Target:** http://host.docker.internal:3000
**Endpoint:** /api/docs/spec.json
**Method:** GET
**CWE:** CWE-200
**CVSS:** 5.3
**Fix Effort:** Low

## Description

`GET /api/docs/spec.json` serves a 616 KB auto-generated OpenAPI document covering all 612 API paths with no authentication, including the complete superadmin surface: user lifecycle operations (`/api/v1/auth/admin/users` create/delete/enable/invite), role and member CRUD, OAuth application registration, settings read/write, and function-publish grant and audit-log administration. It is a complete adversary route map of privileged functionality.

## Evidence

Unauthenticated `GET /api/docs/spec.json` returned 200 with 616,426 bytes and 612 paths. Excerpt of privileged operations catalogued:

```text
/api/v1/auth/admin/users                -> get, post        (list/create users)
/api/v1/auth/admin/users/{id}           -> get, patch, delete
/api/v1/auth/admin/users/{id}/enabled   -> post             (enable/disable account)
/api/v1/auth/admin/users/invite         -> post
/api/v1/auth/admin/roles ...            -> CRUD
/api/v1/functions/admin/function-publish-grants     -> get, post, delete
/api/v1/functions/admin/function-publish-audit-log -> get
```

Root cause lines: `src/middleware/globalAuth.ts:48-52` documents the public intent and `:164` allowlists `/api/docs*`; `src/docs/openapi.ts:2980` and `:2985` mount `spec.json` and the UI without auth; `src/server.ts:1384` calls `setupSwagger(app)` unguarded.

## Impact

An unauthenticated attacker obtains a complete, always-current map of the privileged API surface — user administration, role management, OAuth application management, settings, and function-publish governance — including exact path shapes, HTTP methods, and operation intent. This substantially accelerates targeted attacks against admin endpoints and removes any uncertainty about which privileged operations exist. The spec mostly lacks parameter/body schemas (auto-generated stubs), so the disclosure is limited to the route/operation map; no privileged action was performed and no data beyond the catalog itself was obtained.

## Technical Analysis

`setupSwagger()` mounts the spec and UI with no auth middleware:

```typescript title=src/docs/openapi.ts startLineNumber=2977 endLineNumber=2986
export function setupSwagger(app: Express): void {
  // Serve the raw OpenAPI spec — derived from the live route table so it is
  // always complete (every real endpoint) and phantom-free (only real ones).
  app.get('/api/docs/spec.json', (_req, res) => {
    res.json(buildServedSpec(app));
  });
```

and `setupSwagger(app)` is invoked at `src/server.ts:1384` with no guard. The middleware additionally allowlists the whole path family in the global JWT gate:

```typescript title=src/middleware/globalAuth.ts startLineNumber=162 endLineNumber=165
  // Swagger UI + OpenAPI JSON spec. Note the `url` check catches
  // /api/docs?foo=bar; `p` check catches bare /api/docs and subpaths.
  if (p === "/api/docs" || p.startsWith("/api/docs/")) return true;
  if (url.startsWith("/api/docs?")) return true;
```

The header comment at `src/middleware/globalAuth.ts:48-52` documents this as "Publicly readable by design; contains no secrets", but the generated document reveals privileged intent: operation IDs and summaries for every admin/superadmin operation (user create/delete/enable, MFA reset, invites, roles/members CRUD, OAuth application registration, settings write, function-publish grants and audit log review). Because the spec is built from the live route table (`buildServedSpec(app)`), it is always complete and current — a perfect reconnaissance artifact. Request/response schemas are mostly auto-generated stubs, which limits the disclosure to paths/operation structure rather than full parameter detail; that is why the impact is scored Low rather than Medium.

## Proof of Concept

1. Send an unauthenticated GET to `/api/docs/spec.json`.
2. Observe a 200 response with a ~616 KB OpenAPI JSON document.
3. Inspect `paths` and confirm superadmin operations are catalogued: `/api/v1/auth/admin/users` (POST/GET), `/api/v1/auth/admin/users/{id}` (DELETE/PATCH), enable/invite variants, roles and members endpoints, OAuth application registration, settings endpoints, and `/api/v1/functions/admin/function-publish-grants` plus audit-log endpoints.

```bash
curl -s http://host.docker.internal:3000/api/docs/spec.json -o spec.json
python3 - <<'PY'
import json
```

## Code Analysis

**Location 1:** `src/middleware/globalAuth.ts` (lines 162-165)
  Remove /api/docs from the unauthenticated allowlist
  ```
    // Swagger UI + OpenAPI JSON spec. Note the `url` check catches
    // /api/docs?foo=bar; `p` check catches bare /api/docs and subpaths.
    if (p === "/api/docs" || p.startsWith("/api/docs/")) return true;
    if (url.startsWith("/api/docs?")) return true;
  ```

  **Suggested Fix:**
```diff
-   // Swagger UI + OpenAPI JSON spec. Note the `url` check catches
-   // /api/docs?foo=bar; `p` check catches bare /api/docs and subpaths.
-   if (p === "/api/docs" || p.startsWith("/api/docs/")) return true;
-   if (url.startsWith("/api/docs?")) return true;
+   // Swagger UI + OpenAPI JSON spec: catalogues the entire privileged API
+   // surface (admin user/role/settings operations). Requires authentication.
+   if (p === "/api/docs" || p.startsWith("/api/docs/")) return false;
+   if (url.startsWith("/api/docs?")) return false;
```

**Location 2:** `src/docs/openapi.ts` (lines 2980-2982)
  Defense-in-depth: require an authenticated principal on spec.json
  ```
    app.get('/api/docs/spec.json', (_req, res) => {
      res.json(buildServedSpec(app));
    });
  ```

  **Suggested Fix:**
```diff
-   app.get('/api/docs/spec.json', (_req, res) => {
-     res.json(buildServedSpec(app));
-   });
+   app.get('/api/docs/spec.json', requireAuthenticated, (_req, res) => {
+     res.json(buildServedSpec(app));
+   });
```

## Remediation

1. Remove `/api/docs` and `/api/docs/*` from the globalAuth allowlist so the Swagger UI and spec require authentication like every other API path.
2. Serve `/api/docs/spec.json` and `/api/docs` only to authenticated users (any valid principal), enforced inside `setupSwagger` as defense in depth regardless of the allowlist.
3. If a public spec is genuinely desired for integrators, generate a redacted variant that excludes all `/api/v1/auth/admin/**`, `/api/v1/functions/admin/**`, and any other `/**/admin/**` paths before exposing it unauthenticated.

## Assumptions

Assumes the deployment exposes port 3000 to untrusted networks. Scoring reflects catalog-level disclosure only; severity would rise if request/response schemas for privileged operations were also enumerated.
