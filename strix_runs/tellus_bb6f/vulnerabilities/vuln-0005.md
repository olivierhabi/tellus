## Description

The transitive package **`fast-uri@3.1.2`** (pinned via `pnpm-lock.yaml` through `ajv`) is affected by CVE-2026-16221: versions 2.3.1 through 4.1.0 do not treat a literal backslash (U+005C) as an authority delimiter, whereas Node's native WHATWG URL parser (used by `fetch`, `undici`, `http`) normalizes `\` to `/` for special schemes. A URL that ajv/fast-uri validates as one origin can resolve to a different host at fetch time, bypassing URI-format/security policy. Fixed in `3.1.4` / `4.1.1` / `2.4.3`.

## Impact

An attacker-supplied URL containing a backslash (e.g. `https://allowed.com\\.evil.com/`) is parsed by fast-uri as belonging to the allowed origin, while Node's WHATWG parser used at fetch time treats the backslash as a path separator and sends the request to `evil.com`. This bypasses origin/host security policy with Integrity impact only.

## Technical Analysis

**Root cause:** fast-uri ≤ 4.1.0 (3.x to 3.1.3) does not treat `\` as an authority delimiter; WHATWG URL treats it as equivalent to `/` for special schemes. Validation-vs-resolution disagreement.

**Dependency chain (`pnpm-lock.yaml`):** `ajv@8.18.0 > fast-uri@3.1.2`. `ajv@8.18.0` is direct (package.json), instantiated at `src/services/workshop/validator.ts:48`.

## Remediation

Single bump covers all three fast-uri CVEs (13676, 16221, 18446): resolve `fast-uri` to `>=3.1.5`.
1. Bump direct `ajv` in `package.json` to a version whose closure picks `fast-uri@>=3.1.5`, then `pnpm install`; or
2. `pnpm.overrides: { "fast-uri@<3.1.5": "^3.1.5" }` in `package.json`, `pnpm install`, commit lockfile.
3. Verify with `trivy fs pnpm-lock.yaml` that no fast-uri copy is below the fixed line.
