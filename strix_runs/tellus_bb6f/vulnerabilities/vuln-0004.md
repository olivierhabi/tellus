## Description

The transitive package **`fast-uri@3.1.2`** (pinned via `pnpm-lock.yaml` through `ajv`) is affected by CVE-2026-13676: `fast-uri` versions 2.3.1 through 3.1.2 and 4.0.0 fail to canonicalize Unicode (IDN) hostnames for HTTP-family URLs — the IDN conversion path calls a helper that does not exist on the global `URL` constructor — so `normalize()` / `equal()` return values that differ from a WHATWG-compatible URL parser. Applications using `fast-uri` (directly or via `ajv`'s URI format validation) to enforce hostname policy can be bypassed. Fixed in `3.1.3` / `4.0.1` / `2.4.2`.

## Evidence

**Advisory evidence:** `CVE-2026-13676` applies to `fast-uri` at installed version `3.1.2`. The advisory is fixed in `3.1.3`.

**Transitive dependency:** introduced by the direct dependency `ajv@8.18.0`.

**Dependency chain:** `ajv@8.18.0 > fast-uri@3.1.2`

**Usage analysis:** imported by application code; affected API usage unconfirmed. `ajv` is a direct dependency used by application code: `src/services/workshop/validator.ts:48` (`const ajv = new Ajv2020()`). No application code imports `fast-uri` directly (`rg -n "require\(['\"]fast-uri|from ['\"]fast-uri"` over `--type ts` on src/ returned no hits). fast-uri is used internally by ajv for URI reference resolution; whether the app validates any URL with a hostname policy through this path was not confirmed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

Hostname allow/deny decisions made on the fast-uri-normalized value can disagree with what the actual HTTP client (Node WHATWG URL) resolves, letting an attacker-registered look-alike Unicode (IDN) host pass a host-equality or origin check. This is a security-policy bypass with Integrity impact; no direct confidentiality or availability effect on its own.

## Technical Analysis

**Root cause:** `fast-uri` ≤ 3.1.2 (and 4.0.0) calls a nonexistent helper for IDN/Unicode hostname conversion, silently leaving the host in Unicode form while `normalize()`/`equal()` still behave as though canonicalization happened. Two URLs that Node's WHATWG parser would consider identical can compare unequal in fast-uri (and vice versa).

## Remediation

`fast-uri@3.1.2` → `3.1.3` is a patch-level bump, but it is transitive so fix at the direct level:
1. Bump the direct `ajv` dependency in `package.json` to a version whose closure pulls `fast-uri@>=3.1.3` (or `>=4.0.1`), then `pnpm install`.
2. Alternatively force resolution with `pnpm.overrides: { "fast-uri@<3.1.3": "^3.1.3" }`.
3. Commit the regenerated `pnpm-lock.yaml` and verify with `trivy fs pnpm-lock.yaml`.
