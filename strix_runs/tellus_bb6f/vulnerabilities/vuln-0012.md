# Unauthenticated system-status endpoints leak infrastructure and business-schema inventory

**ID:** vuln-0012
**Severity:** MEDIUM
**Found:** 2026-08-18 06:39:45 UTC
**Target:** http://host.docker.internal:3000
**Endpoint:** /api/v1/system/health
**Method:** GET
**CWE:** CWE-200
**CVSS:** 5.3
**Fix Effort:** Low

## Description

The endpoints `GET /api/v1/system/health` and `GET /health/detailed` respond with no authentication and disclose a full infrastructure and business-schema inventory: the PostgreSQL server version, per-table row counts, the live OpenSearch cluster name and node count, all 80 index names with per-index document counts and sizes, a 121-entry object-type inventory (apiName, propertyCount, objectCount, lastIndexed, indexStatus) that exposes client business domains, host memory footprint, database reachability, and uptime.

## Impact

An unauthenticated attacker learns the exact infrastructure stack (PostgreSQL 16.14, OpenSearch single-node `docker-cluster`), every internal index name and per-index data volumes, per-table row counts, and — most sensitive — 121 object-type apiNames that disclose which client business domains and data categories are hosted (customs/tax, banking customers/loans/collateral, payments, citizen records) together with their record volumes. `/health/detailed` additionally exposes process memory footprint, database reachability and uptime. This is restricted operational and business intelligence: it profiles high-value targets and data volumes for attack prioritization and gives precise versions/stack details for exploit staging. No modification or availability impact was demonstrated.

## Technical Analysis

Two routes serve rich operational diagnostics without any authentication middleware:

1. `GET /api/v1/system/health` is handled by `health.ts` and returns the full `buildHealthResponse()` payload: PostgreSQL version, per-table `rowCount` for 8 core tables, OpenSearch cluster metadata (`clusterName`, `nodeCount`) including every index `name`, `documentCount` and `sizeBytes`, plus the complete object-type inventory with `apiName`, `propertyCount`, `objectCount`, `lastIndexed` and `indexStatus` per type.

```typescript title=src/routes/health.ts startLineNumber=413 endLineNumber=426
  try {

```

2. `GET /health/detailed` is handled by `healthDetailedRouter` and returns process memory (`used`/`total` MB), database connectivity, uptime and version.


Both routers are mounted with no auth middleware:

```typescript title=src/server.ts startLineNumber=1285 endLineNumber=1285

```


Additionally `src/middleware/globalAuth.ts` (around line 141-146) explicitly allowlists `/api/v1/system/health` alongside the liveness/readiness probes, so even the global JWT gate lets these paths through before any route-level check exists (and none exists). The object-type `apiName` strings are the sensitive element: they name real client business domains (e.g. `CustomsDeclaration`, `TaxReturn`, `Taxpayer`, `QaRwBkLoanApplications`, `QaRwBkCustomers`, `QaRwRswitch*`, `QaRwIremboCitizens`), revealing which organizations and what data categories the platform hosts, plus their record volumes — valuable target-profiling intelligence for an unauthenticated network attacker. The memory footprint (`used 16292 MB / total 16384 MB`) and exact PostgreSQL version aid exploit staging and capacity attacks.

## Remediation

1. Split the health surface into two routers: a minimal liveness/readiness router returning only `{status, timestamp}` (kept unauthenticated for Kubernetes probes) and a detailed/system router for diagnostics.
2. Gate the detailed/system endpoints behind authentication: remove `/api/v1/system/health` from the globalAuth allowlist (keep only `/liveness` and `/readiness`) and add an authentication middleware to the system-health and health-detailed handlers, or mount those routers after `globalAuth` runs.
3. Reduce the payload of the system-health response: return aggregate counts only, and drop the object-type `apiName` and index `name` strings (per-type/per-index names must never appear in an unauthenticated response) or require an authorized viewer/operator role for the detailed breakdown.
4. Remove process memory figures from any unauthenticated response.

## Assumptions

Assumes the deployment exposes port 3000 to untrusted networks (true in the tested environment; the endpoints carry no ingress-level guard of their own). Impact is disclosure only.
