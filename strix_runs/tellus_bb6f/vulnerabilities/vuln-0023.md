## Description

The transitive package **`qs@6.14.2`** (pinned via `pnpm-lock.yaml` through `express`) is affected by CVE-2026-8723: `qs.stringify` throws a synchronous `TypeError` when called with `arrayFormat: 'comma'` and `encodeValuesOnly: true` on an array containing `null`/`undefined` — the comma + encodeValuesOnly branch maps through a raw encode of the null value. Not guarded by `skipNulls`/`strictNullHandling`. Causes an uncaught exception / process-level DoS when this code path is hit. Fixed in `6.15.2`.

## Evidence

**Advisory evidence:** `CVE-2026-8723` applies to `qs` at installed version `6.14.2`. The advisory is fixed in `6.15.2`.

**Transitive dependency:** introduced by the direct dependency `express@4.22.1`.

**Dependency chain:** `express@4.22.1 > qs@6.14.2`

**Usage analysis:** imported by application code; affected API usage unconfirmed. `qs` is not imported directly in src; it is express's default query-string parser (`express@4.22.1` direct dep). Affected-symbol (`qs.stringify` with the specific `arrayFormat:'comma' + encodeValuesOnly:true` config) check was not performed — the app may not use that exact option combination. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

Uncaught `TypeError` from `qs.stringify(null, {arrayFormat:'comma', encodeValuesOnly:true})` can crash the request handler (low availability impact) when the app stringifies arrays that may contain null/undefined.

## Technical Analysis

**Root cause:** null/undefined array element reaches `encode(null)` in the comma+encodeValuesOnly branch of `lib/stringify.js:145`. **Chain:** `express@4.22.1 > qs@6.14.2`. **Trivy:** Severity=MEDIUM, CVSS ghsa:5.3 (CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:U/C:N/I:N/A:L), CWE-476.

## Remediation

Bump `express` to a release whose `qs` dependency floor is `>=6.15.2`, or `pnpm.overrides: { "qs@<6.15.2": "^6.15.2" }`. Regenerate lockfile, verify with `trivy fs pnpm-lock.yaml`.
