## Description

The transitive package **`body-parser@1.20.4`** (pinned via `pnpm-lock.yaml` through `express`) is affected by CVE-2026-12590: when configured with an invalid `limit` option (unparseable string / NaN), `bytes.parse` returns null and the request-body size check is silently skipped, so applications relying on `limit` as their primary guard accept arbitrarily large payloads, leading to memory-exhaustion DoS. Fixed in `1.20.6` / `2.3.0`.

## Evidence

**Advisory evidence:** `CVE-2026-12590` applies to `body-parser` at installed version `1.20.4`. The advisory is fixed in `1.20.6`.

**Transitive dependency:** introduced by the direct dependency `express@4.22.1`.

**Dependency chain:** `express@4.22.1 > body-parser@1.20.4`

**Usage analysis:** imported by application code; affected API usage unconfirmed. `body-parser` is not imported directly in src, but it is the JSON/urlencoded parser used internally by `express@4.22.1` — express itself is the direct dependency imported pervasively in src/server.ts, route files. Whether the app relies on an invalid `limit` value was not confirmed. Affected-symbol check was not performed. This is a prioritization signal from static analysis, not a proof of exploitability or of safety.

## Impact

Oversized request bodies are accepted when the `limit` option is misconfigured to an invalid value, allowing memory-exhaustion DoS. Requires the (high-complexity) precondition of a misconfigured limit; availability impact.

## Technical Analysis

**Root cause:** invalid `limit` (NaN/garbage) makes `bytes.parse` return null, skipping the body-size guard. **Chain:** `express@4.22.1 > body-parser@1.20.4` (express is the direct dep; this app is an Express server). **Trivy:** Severity=LOW, CVSS nvd:5.9 (CVSS:3.1/AV:N/AC:H/PR:N/UI:N/S:U/C:N/I:N/A:H), CWE-770.

## Remediation

Fix at the direct level: bump `express` in `package.json` to a release whose closure resolves `body-parser@>=1.20.6` (express 4.19+ / 5.x line), or `pnpm.overrides: { "body-parser@<1.20.6": "^1.20.6" }`. Regenerate lockfile, verify with `trivy fs pnpm-lock.yaml`.
